# @openchamber/agent-service

Private Bun Agent Service and dedicated OMP SDK worker processes. The Node Host uses `createAgentServiceSupervisor` in `packages/web/server/lib/host/agent-service-supervisor.js`; Electron keeps that Host in process. Hosted mobile and Capacitor connect to the Host and start no local worker. Guest clients do not receive access to these private routes.

Application execution is not activated by this package's presence. Task 22 composes the service into the Host; task 17 removes the inherited engine after replacement consumers are ready.

## Lifecycle

Build with `bun run build`. The built entrypoint is `dist/index.js`, with its worker at `dist/worker/index.js`. The service starts only under the Host supervisor; an IPC-less start exits with code 1 without listening.

The Host generates a 256-bit token and answers the service's private spawn-IPC request with it; the service accepts only a 64-hex value and gives up after 10 seconds. The token never appears in the environment, arguments, URLs or logs. Every request requires `X-Internal-Secret` and a loopback peer. The listener binds only `127.0.0.1`; stdout publishes one `{ "type": "agent-service.listening", "port": ... }` line for endpoint discovery, not readiness. After that handshake an IPC `disconnect` stops the service beside SIGTERM/SIGINT, so a hard-killed Host does not leave the detached service and its unrelated workers running.

`GET /api/agent/v1/ready` returns `{ "ready": true, "engine": "omp", "version": "1.0.0" }` only after a dedicated worker initializes the real SDK public factory, disposes its session and exits successfully. The probe owns an ephemeral profile and workspace, removed after it exits. On Windows only, the readiness probe allows up to one second after IPC stop for a cooperative exit before the normal process-tree termination sequence. A signalled or nonzero exit still fails readiness. Other worker stops are unchanged. Startup is bounded to 15 seconds; orderly stop gets 5 seconds before forced termination.

## Private worker operations

- `POST /internal/workers` admits a root session.
- `GET /internal/workers` returns authoritative worker state and generation.
- `POST /internal/workers/:rootSessionId/restart` retires the old generation before launching its replacement.
- `DELETE /internal/workers/:rootSessionId` waits for its process to exit.
- `POST /internal/worktree-leases` releases every session, stateless and usage worker at or inside a directory before the Host removes it. The Host supplies `{ leaseId, directory }`; the service never mints an id. It answers `201 { leaseId, released }` only after every stop is proved by worker-entry removal, child exit and process-tree exit (on Windows only entry removal and child exit: `waitForWorkerProcessTree` is unconditional there). A session run refuses with `409 RUN_ACTIVE`; a starting worker, pending operation, action, running shell job, restart reservation or session storage inside the directory refuses with `409 COMMAND_IN_FLIGHT`; the same refusal names the holder for a duplicate id or an overlapping (same, ancestor, descendant) directory. A refusal creates no lease.
- `DELETE /internal/worktree-leases/:leaseId` is idempotent and answers `204`, including for an unknown id. If that id's acquire is still canonicalizing its directory, deletion cancels the in-flight acquire; the pending id exists only for the lifetime of that request, with no tombstone.
- While a lease fence is installed, admission and the last check before `spawn` refuse a worker whose `cwd` is inside it with `409 COMMAND_IN_FLIGHT` and `details { leaseId }`. The Host id is reserved before asynchronous canonicalization; the overlap check, fence install and worker snapshot remain one synchronous block inside the single lease-mutation chain. Leases live in memory: there is no TTL, persisted marker, reconcile route or replay. The Host supervisor's restart hold and the IPC-disconnect stop cover their lifetime.
- Host-private `POST /internal/sessions/:rootSessionId/worktree-archive-delete` accepts the reserved operation ID and exact project, workspace, agent-directory and session family IDs, never caller-provided paths. It requires the same private secret, validates native references and owner, and serializes against the stopped root. An operation-scoped durable intent/receipt permits exact replay after a lost response; the Host retires the matching completed receipt after its own commit. An incomplete or changed native owner is refused rather than treated as an absent-successful delete. This is distinct from deleted-space recursive cleanup and is not a public session API.

Bootstrap data contains opaque root, project, and workspace IDs, absolute private `cwd` and `agentDirectory`, optional `sessionsDirectory`, and an optional Host-resolved environment overlay. Independent roots get separate processes even in the same workspace. Worker replacement and shutdown are serialized per root; prompt admission rejects a second active run while abort can interrupt the first.

Only `kind: 'session'` roots count toward `WORKER_CAPACITY_POLICY.maxActiveRootWorkers` (5); stateless catalog and usage workers are workspace overhead. A new root past the cap receives HTTP 503 `SERVICE_UNAVAILABLE` with `details.reason: "worker_capacity"` and existing workers untouched. A session worker idle for 600000 ms with no active run, pending operation, unresolved approval/question, restart reservation or running background Shell job is stopped through the graceful shutdown path and reopens cold from its native transcript on the next request; the 30000 ms reaper timer is unreferenced. Workers are spawned with an explicit process/locale/proxy/OMP allowlist plus the Host-authorized directory overlay; the overlay cannot set `OHPICHAMBER_INTERNAL_SECRET`, `OPENCHAMBER_MANAGED_PROCESS_TOKEN`, `PI_CODING_AGENT_DIR` (names are reserved case-insensitively). Ambient Host credentials are not inherited: provider credentials come from that overlay or OMP `AuthStorage`, so an environment-only provider works only when its values are configured in the authorized overlay. Environment values and private paths are absent from public worker observations. Authoritative worker observations (`WorkerInfo`) omit operating-system process IDs (`pidExposed: false`), exposing only lifecycle status, worker generation, and readiness to keep internal process layout private.

Both service and worker launches pass Bun's `--no-env-file`. Project dotenv files cannot add values to the Host-resolved environment.

When a standalone OMP binary runs as Bun, workers inherit `BUN_BE_BUN=1` from the service, including the readiness worker that has no workspace overlay. A workspace cannot override the selected interpreter mode.

Only `src/worker/` imports the OMP SDK; the Node Host never imports or loads the SDK. Each session owns its supplied `SessionManager`; disposal closes that manager, then the worker closes its owned `AuthStorage`. `SessionRegistry.close()` first settles openings and then closes its owned `WorkerRegistry` before closing persistent references, so graceful service shutdown cannot leave native workers alive after the registry is unavailable. Workers pass `initialModelRefreshStrategy: 'offline'` to `createAgentSession` so initial cold-cache default-model fallback does not block readiness on an external catalog fetch while leaving later explicit `ModelRegistry` discovery unchanged, and enable native approval/question hooks and concrete Promise-based interactive UI before admitting prompts. LSP and extension discovery remain disabled (`enableLsp: false`, `disableExtensionDiscovery: true`); `WorkerMcp` is passed as `mcpManager` (`enableMCP: mcp !== undefined`) when mcp is supplied.

## Sessions and recovery

`POST /internal/sessions` creates or reopens a Host-authorized root. The service persists only private bootstrap references and the SDK session filename, not resolved environment values, Host metadata or a transcript copy. A cold reference is unavailable with no active run until the Host supplies its current environment and reopens the worker. A healthy live root is returned without admission or replacement. When a reopen replaces an unavailable or cold root's worker, policy preloading precedes the replacement worker launch: a failed policy read before replacement preserves the existing live worker, while a failure after replacement worker startup terminates the started replacement and marks the session unavailable rather than restoring a false-live entry.

The private `/api/agent/v1/sessions` namespace provides runtime list/detail, snapshot, history, run admission, abort, delete and SSE events. Host authorization, metadata composition, and delivery ownership wrap these service routes; they are not an external client entrypoint. Host-chosen run IDs and resolved attachment paths use `/internal/sessions/:sessionId/runs`.

OMP alone writes messages. The worker stores canonical identity and per-cycle lifecycle references in native custom entries, binding message identities after SDK persistence settles. Live and reopened history retain IDs, terminal tool outcomes and each cycle's status/times. One outer run may contain several native model cycles; `turn_end` does not complete that run. Tool failure stays distinct from provider failure. A failed provider run retains partial output and does not affect another root. Projection or persistence failure stops the affected worker rather than allowing its execution to publish fabricated success.
Agent profile `allowedTools` limits model-invoked tools: `null` inherits the SDK default active tool set captured before profile selection, `[]` exposes none, and an array is the exact restriction. Canonical profile metadata keeps this distinction; hand-authored native frontmatter that declares only `tools: []` is parsed by the SDK, which appends `yield`. Provider credential authorization is a separate capability check and is not a tool name in that list; an otherwise allowed profile must still be able to use its selected provider. The Host applies provider authorization independently.

Streaming steer and follow-up admission bind captured context, developer instructions, synthetic messages, and non-image attachment references to the exact admitted native user message. The worker composes the SDK's queued-message preparation hook and commits these companions with that user delivery, preserving native preparation and cancellation, message identity, and attachment metadata without parking context in the direct-prompt-only `nextTurn` buffer or modifying the in-flight transcript during preparation. Web/PWA and Electron use this worker through the Host; hosted mobile and Capacitor reach the same worker through their active Host, with no runtime-specific admission path.

Captured context retains input order, with each entry's developer instructions preceding its associated custom context message in both direct prompts and queued deliveries. Direct admission appends every native context role through the same transcript owners rather than mixing immediate messages with conditional `nextTurn` buffering while a previous turn unwinds.

The worker extracts validated session and session-message identities from captured `PromptContext` metadata and binds them to the exact native user entry in its existing canonical reference. Canonical user text parts expose them as `sessionMentions` in live part events, snapshots, and branch-aware cold history; private paths in display fields are redacted. Older references without mentions remain valid. The native transcript remains the only transcript owner.

`sessionMentions` is optional for existing v1 native references. Host and UI
must deploy the updated strict canonical decoder together: older decoders are
not assumed to accept the new field. Pending references are associated with
the exact native message object persisted by the SDK, not role/timestamp or
latest-turn inference; SDK objects stay private to the worker.

The service journal retains the newest 1,000 ordered events and a tail of 100 turns. Snapshot and cursor are captured together. SSE validates cursor syntax and replay coverage before headers: malformed cursors return 400 `INVALID_CURSOR`; stale epochs or missing coverage return 410 `RESYNC_REQUIRED`. Live epoch changes and delivery overflow invalidate and close the stream. Reopening a worker creates a new epoch; historical messages never imply live activity.

History uses an opaque cursor bound to the selected branch version and leaf. It is not an SSE cursor. Session deletion uses the native SDK storage owner before removing its private service reference. Archive and operational metadata remain with Host SQLite.

## Projection, compaction, and usage

`WorkerProjection` translates native SDK session events into canonical projection inputs for `SessionJournal`.

- **Compaction**: On native `auto_compaction_end`, when the action completes without abort, retry, or skip, the projection emits a canonical `session.compacted` event containing `compactionId`, `tokensBefore`, and `completedAt`. Compaction is projected as an opaque canonical lifecycle transition without fabricating synthetic turns or exposing internal summary text.
- **Token usage**: Message metadata extracts `providerId`, `modelId`, and parsed `TokenUsage` (`input`, `output`, `cacheRead`, `cacheWrite`) from native assistant messages. Canonical events (`message.created`, `message.updated`) carry usage objects, and `SessionJournal` indexes usage per message in history and snapshots.
- **Run and turn lifecycle**: A run begins with `run.started` and tracks active execution state. Tool execution results and partial turn progress update incrementally. A run settles to `completed`, `failed`, or `cancelled` on terminal outcomes.
- **Live cancellation**: `requestCancel(runId)` latches abort intent before the worker awaits the native abort. While the latch matches, `turn_end`, `agent_end` and a late completed settlement record the turn and run `cancelled`, so an interrupted turn without its aborted assistant `message_end` cannot publish `completed`; `beginRun` clears the latch. History reports the open active-run turn as `running` until a recorded terminal settles it.

## Approvals and questions

The public SDK factory receives `hasUI: true`, `interactivePrompts: true`, and an inline extension observing typed native tool-call/approval events. `WorkerInteraction` initializes the native `pi-tui` theme synchronously (`ensureThemeSync`) so builtin `ask` formatting can access `ui.theme`, while `initializeExtensions` wires the real session runner to the worker UI and `setToolUIContext` gives builtin tools the same context. `ApprovalRequest` projects the actual tool name, a redacted/truncated one-line input summary, and `policyTarget` only when a native session allowance exists (`bash` + `*`), with stripped details rather than exposing raw native execution inputs, private absolute paths, or credentials. The exact native execution input and policy target are retained only in service-private records for policy matching and worker dispatch. Multi-question choices, selections and freeform answers retain native question IDs, enforce single-choice mutual exclusion between `selectedOptions` and `customInput`, and validate before consuming a handle. Native promises and session objects never leave the worker.

The private session namespace exposes `GET approvals`, `POST approvals/:approvalId/respond`, `GET questions`, and `POST questions/:questionId/respond`. Replies require the current version, epoch and worker generation, checking expired/stale owner identity (`410`) before CAS (`409` with `{ expectedVersion, actualVersion, currentRecord }`). The service atomically reserves CAS, publishes requested/resolved events through the existing journal cursor, and includes current pending requests in snapshots. Terminal always-deny resolutions project committed `{ policyId, revision }` metadata; always-allow reports `{ scope: "session", persistence: "ephemeral" }` and writes no Host policy. Cancellation and five-minute expiry are terminal; abort, shutdown, worker failure and replacement invalidate old requests without allowing them to revive on a late acknowledgement. Reconnect within an epoch preserves pending requests; a new epoch replaces the pending set.

Always-allow resolves OMP's native `allow_always` handle in the worker's per-session ACP cache and writes no Host policy; each later cached bash call still receives its own exact Host execution grant before it runs. Always-deny commits an exact workspace policy in the Node Host SQLite owner through private child IPC. Node authorizes the captured Host bootstrap scope before writing. A real committed policy ID/revision is required before a denied worker handle resolves. Failed persistence leaves the request pending with `APPROVAL_POLICY_WRITE_FAILED`; no missing Host handler can fabricate a commit. Policies load before reopening a session and apply to future exact native targets, with workspace denial taking precedence. A failed policy read during reopen preserves an intact live worker when replacement startup has not begun. Web and Electron use that Host; hosted mobile and Capacitor reach the same Host without starting local workers.

## Native policy and grammar derivation

`src/worker/native-policy-descriptor.ts` provides execution-free first-party grammar inspection via `describeNativeOperation`, parsing tool inputs into a `NativeOperationDescriptor`:
- `edit`: inspects `editMode` (`apply_patch`, `hashline`, `patch`, `replace`, `sloppy`) and file operations (`kind`, `path`, `to`).
- `read` and `write`: resolve file targets against `cwd`, including archive candidates, SQLite targets, JSON query paths, video, and PDF paths.
- `grep` and `glob`: extract search path entries and base directory paths.
- `bash` and `shell`: inspect commands and execution targets.
- `lsp`: inspects actions and methods, resolves workspace-contained file targets and file:// URIs, distinguishes read-only operations (`hover`, `definition`, `type_definition`, `implementation`, `references`, `symbols`, `diagnostics`, `status`, `capabilities`, `code_actions` without apply) from mutations (`rename`, `rename_file`, `code_actions` with `apply: true`, `format`), and derives exact destination paths and file operations.

`WorkerPolicy` intercepts operations in the worker and sends a `policy.request` over child IPC to the supervisor. The supervisor delegates to the Host's `WorkerOperationAuthorizer`, which verifies the request against `HostWorkspacePolicy` (`fileTools`, `shellCommands`, `providerEntry`) and persistent approval policies. If policy requires interactive confirmation, the worker raises `NativeApprovalRequired`, prompting an allowlisted public approval request.

## Private Host Action RPC bridge

Builtin Host tools (`openchamber`, `web`, `memory`, `notify`) are registered in the worker via `createHostToolExtension`:
- `openchamber`: project and model discovery, session management (`list`, `create`, `send`, `fork`, `status`, `messages`, `link`), schedule tasks, and `file.open`.
- `web`: browser navigation, page inspection, screenshot capture, clicking, typing, and scrolling. Browser credentials remain with the Host.
- `memory`: session memory read, list, save, and delete.
- `notify`: notification delivery.

`WorkerHostActions` dispatches these requests across private child IPC (`action.request`, `action.result`, `action.cancel`). The Host executes the action through `invokeHostAction` within the captured workspace root. AbortSignal cancellation dispatches `action.cancel`, aborting pending Host execution.

## Shell projection

`WorkerShell` owns native `AsyncJobManager` jobs backed by `executeBash`. Guest-started jobs suppress native agent delivery, so observing command output does not append it to the transcript. Streaming chunks, not cumulative previews, advance UTF-8 byte cursors. Each job retains at most 65,536 bytes; reads report skipped bytes and preserve complete code points. The newest 200 terminal observations remain available independently of native job eviction.

Output checks session, epoch and worker generation for running and ended jobs. Stop waits for the native job promise and returns success only for an observed stopped termination. Native timeout, nonzero exit and missing exit status remain distinct. Settled jobs release their private native shell-session keys; close cancels and waits for owned jobs. `ShellCoordinator` routes `/api/agent/v1/sessions/:sessionId/shell/jobs` (start/snapshot), `/api/agent/v1/workspaces/:workspaceId/shell/jobs`, `/api/agent/v1/projects/:projectId/shell/jobs`, `/api/agent/v1/shell/jobs`, and `/api/agent/v1/sessions/:sessionId/shell/jobs/:jobId/(output|stop)` across admitted root workers; public Host scope authorization and gateway composition wrap these routes.

## Catalogs, MCP OAuth, skills, stateless completion, and credential handoff

`WorkspaceRoutes` serves `/api/agent/v1/workspaces/:workspaceId/(models|providers|agents)` reads and revisioned configuration, model, credential (`PUT .../credential`, `DELETE .../credential/:credentialRef`) and agent profile mutations, plus `/api/agent/v1/workspaces/:workspaceId/completions` and `.../completions/:completionId/cancel` through a workspace-scoped stateless worker. Native agent profiles and completions are scoped per workspace, maintaining independent model selection, system prompt configuration, and transcript boundaries across roots without cross-workspace leakage. Completions distinguish Host authorization and service HTTP Problem Details errors (such as 403 `UNAUTHORIZED` on provider or tool preset authorization, or 503 `SERVICE_UNAVAILABLE` when the workspace worker is unavailable) from terminal `CompletionResult` outcomes (`status: 'failed'` or `'cancelled'` with structured codes such as `MODEL_UNAVAILABLE`, `PROVIDER_UNAVAILABLE`, `PROVIDER_FAILURE`, `CONTEXT_LIMIT`, `UNSUPPORTED_CAPABILITY`, or `STRUCTURED_OUTPUT_INVALID`). Host authorization or service failures produce HTTP Problem responses directly, without being swallowed into a successful HTTP 200 failed completion payload. `publicModel` projects native catalog models with `getModelPricingStatus`: negative sentinel rates (such as bundled `openrouter/auto`) and `unknown`, `included`, `variable` or unannotated all-zero rates map to `pricing: null` without dropping the model or clamping rates, explicit `free` status keeps `0`, and positive `fixed` rates are preserved. `NativeModels` reloads native settings from disk (`Settings.reloadFromDisk`) and reapplies model policies before reads and selections, preventing deleted bundled providers or profiles from persisting in memory. Reconfiguring provider protocols strips generated inherited chat-model API overrides while preserving explicit non-chat and transport-level overrides. Disabling models uses an explicit match-none glob (`__openchamber_no_enabled_models__/*`) rather than an empty array `[]` (which native filters treat as unrestricted), ensuring an empty enabled-model set is enforced, and model recreation preserves restrictions. `NativeModelRegistry` and `NativeModels` keep canonical provider `credentialRef` selection bound to the exact selected `AuthStorage` row across native `getApiKey`/`getApiKeyWithCredentialForProvider` resolution and the provider catalog, selecting the bound `api_key` row across multiple stored keys, pinning `oauth` session affinity, and failing closed when the bound row is disabled or deleted without falling back to sibling credentials. `NativeAgents` serializes profile frontmatter with a trailing newline before the closing `---` delimiter so `parseAgent` round-trips created and updated profiles. Private `/internal/workspaces/:workspaceId` registers the workspace's `agentDirectoryId` and `/internal/workspaces/:workspaceId/skill-sources` publishes Host-committed workspace or selected-agent skill source revisions.
Bundled agent profiles expose only tools present in the admitted native worker. Explicit workspace profile tool selections remain unchanged and reject unavailable tools before execution. Provider credential authorization remains separate from profile tool allowlists.

`CatalogCoordinator` serializes workspace MCP configuration, root-worker admission and scoped fan-out across `/api/agent/v1/sessions/:sessionId/mcp/(catalog|config|apply|servers/:serverId/reconnect)` and `/api/agent/v1/sessions/:sessionId/skills/(catalog|apply|expand)`. Each admitted worker generation initializes its own local skill `catalogRevision` at `"1"` independently of the persisted provider/model configuration revision `"0"`. `WorkerSkills.expand` builds skill prompts with `buildSkillPromptMessage({ ...skill, baseDir: `skill://${skill.name}` })` while `sanitizeRoots` redacts private workspace, agent-directory, and skill-containment roots in descriptions and expanded prompt messages to `[skill-root]`. Subagent session IDs resolve to their owning root worker. Enabled native skill discovery roots (`.github/skills`, `.opencode/skills`, and user root) are preflighted before loading, and `catalog.updated` events for skills are emitted only when `skills.apply` yields an `'applied'` outcome, suppressing publication on failed apply attempts. Remote (`http`/`sse`) MCP servers expose `GET /api/agent/v1/sessions/:sessionId/mcp/servers/:serverId/oauth` and `POST /api/agent/v1/sessions/:sessionId/mcp/servers/:serverId/oauth` for the addressed root worker (`MCPOAuthRequest` actions `start`, `complete`, `cancel` and `disconnect` with `persistedRevision` and `workerGeneration`, returning `MCPOAuthResult` in `pending`, `authenticated` or `unauthenticated` state). OAuth flows authorize the server and public OAuth endpoints through the Host callback before discovery and login, classify pre-settlement failures before cleanup aborts the flow, persist/reload credentials in the worker's owned `AuthStorage`, and disconnect any active server transport when credentials are removed.

Session authorization snapshots and stateless catalog reads share first-use MCP storage semantics: a Host-owned configuration path with no file (`ENOENT`) means MCP has not been configured. Existing malformed, unreadable, mismatched, or divergent files remain explicit `MCP_CONFIG_READ_FAILED` failures; operations requiring a committed configuration retain the strict loader.

Private credential handoff is exposed via `/internal/workspaces/:workspaceId/credentials/handoff` and credential lookup via `/internal/workspaces/:workspaceId/credentials/resolve`. The handoff endpoint receives verified `SelectedCredentialSelectionSchema` items, writes them to the worker's owned `AuthStorage`, and reloads storage to return confirmed outcomes with `credentialRef`. Lookup resolves stored credentials for authorized Node callers (quota, TTS, and model routing) without exposing secrets to external clients.

Both private operations use the workspace-owned stateless worker; they do not require an admitted session.

## Package inputs

The SDK closure uses archives and patches under `vendor/omp/b5a6b2f7` (OMP 18.18.0), not matching-version registry substitutes or an external source checkout. The 12 first-party packages are packed from the pinned source; all six native leaves are official registry packages with verified SLSA provenance for the pinned commit. The vendor manifest binds archive identities and the resolved parent-scoped dependency versions. Linux x64 native behavior is verified; the other five targets remain unrun without host availability, and native source-build equivalence is not claimed.

`bun run type-check` resolves the installed first-party SDK closure from the package directory via `Bun.resolveSync` (resolving the active patched installation in the workspace's scoped `.bun` cache with the explicit `patchedDependencies` delta in `src/sdk.ts`, `src/async/job-manager.ts` and `src/tools/bash.ts`), emits declarations with the pinned upstream publish convention into `node_modules/.cache/omp-types`, and checks this package's source strictly against them. No handwritten SDK facade or runtime alias is used, and the vendored tarball files remain byte-identical. This avoids checking unrelated upstream CLI implementation as application code. Bun build and runtime resolve the installed vendored TypeScript source with that patch applied; M0 evidence applies only to unchanged SDK owners, while the patched initial model-refresh fallback and native Bash observation paths require re-proof in the mandatory M2 canonical HTTP scenarios.
