# @openchamber/agent-service

Private Bun Agent Service and dedicated OMP SDK worker processes. The Node Host uses `createAgentServiceSupervisor` in `packages/web/server/lib/host/agent-service-supervisor.js`; Electron keeps that Host in process. Hosted mobile and Capacitor connect to the Host and start no local worker. Guest clients do not receive access to these private routes.

Application execution is not activated by this package's presence. Task22 composes the service into the Host; task17 removes the inherited engine after replacement consumers are ready.

## Lifecycle

Build with `bun run build`. The built entrypoint is `dist/index.js`, with its worker at `dist/worker/index.js`. Development can use `bun --no-env-file src/index.ts --port 0`.

The Host injects `OHPICHAMBER_INTERNAL_SECRET` as 32 random bytes encoded in hex. It never appears in arguments, URLs or logs. Every request requires `X-Internal-Secret` and a loopback peer. The listener binds only `127.0.0.1`; stdout publishes one `{ "type": "agent-service.listening", "port": ... }` line for endpoint discovery, not readiness.

`GET /api/agent/v1/ready` returns `{ "ready": true, "engine": "omp", "version": "1.0.0" }` only after a dedicated worker initializes the real SDK public factory, disposes its session and exits successfully. The probe owns an ephemeral profile and workspace, removed after it exits. Startup is bounded to 15 seconds; orderly stop gets 5 seconds before forced termination.

## Private worker operations

- `POST /internal/workers` admits a root session.
- `GET /internal/workers` returns authoritative worker state and generation.
- `POST /internal/workers/:rootSessionId/restart` retires the old generation before launching its replacement.
- `DELETE /internal/workers/:rootSessionId` waits for its process to exit.

Bootstrap data contains opaque root/project/workspace IDs, absolute private `cwd` and `agentDirectory`, optional `sessionsDirectory`, and an optional Host-resolved environment overlay. Independent roots get separate processes even in the same workspace. Worker replacement and shutdown are serialized per root; prompt admission rejects a second active run while abort can interrupt the first. The internal secret is stripped before spawning a worker; environment values and private paths are absent from public worker observations. Authoritative worker observations (`WorkerInfo`) intentionally omit operating-system process IDs (`pidExposed: false`), exposing only lifecycle status, worker generation, and readiness to keep internal process layout private.

Both service and worker launches pass Bun's `--no-env-file`. Project dotenv files cannot add values to the Host-resolved environment.

Only `src/worker/` imports the OMP SDK. Its session owns the supplied `SessionManager`; disposal closes that manager, then the worker closes its owned `AuthStorage`. Workers pass `initialModelRefreshStrategy: 'offline'` to `createAgentSession` so initial cold-cache default-model fallback does not block readiness on an external catalog fetch while leaving later explicit `ModelRegistry` discovery unchanged, and enable native approval/question hooks and concrete Promise-based interactive UI before admitting prompts. LSP and extension discovery remain disabled (`enableLsp: false`, `disableExtensionDiscovery: true`); `WorkerMcp` is passed as `mcpManager` (`enableMCP: mcp !== undefined`) when `mcpConfigPath` is supplied, and `WorkerCatalogs` manages workspace/selected-agent skill discovery, refresh and `buildSkillPromptMessage` expansion.

## Sessions and recovery

`POST /internal/sessions` creates or reopens a Host-authorized root. The service persists only private bootstrap references and the SDK session filename, not resolved environment values, Host metadata or a transcript copy. A cold reference is unavailable with no active run until the Host supplies its current environment and reopens the worker. When reopening a live root, policy preloading precedes replacement worker launch: a failed policy read before replacement preserves the existing live worker, while a failure after replacement worker startup terminates the started replacement and marks the session unavailable rather than restoring a false-live entry.

The private `/api/agent/v1/sessions` namespace provides runtime list/detail, snapshot, history, run admission, abort, delete and SSE events. Task22 supplies public Host authorization, metadata composition and delivery ownership; these service routes are not an external client entrypoint. Host-chosen run IDs and resolved attachment paths use `/internal/sessions/:sessionId/runs`.

OMP alone writes messages. The worker stores canonical identity and per-cycle lifecycle references in native custom entries, binding message identities after SDK persistence settles. Live and reopened history retain IDs, terminal tool outcomes and each cycle's status/times. One outer run may contain several native model cycles; `turn_end` does not complete that run. Tool failure stays distinct from provider failure. A failed provider run retains partial output and does not affect another root. Projection or persistence failure stops the affected worker rather than allowing its execution to publish fabricated success.

The service journal retains the newest 1,000 ordered events and a tail of 100 turns. Snapshot and cursor are captured together. SSE validates cursor syntax and replay coverage before headers: malformed cursors return 400 `INVALID_CURSOR`; stale epochs or missing coverage return 410 `RESYNC_REQUIRED`. Live epoch changes and delivery overflow invalidate and close the stream. Reopening a worker creates a new epoch; historical messages never imply live activity.

History uses an opaque cursor bound to the selected branch version and leaf. It is not an SSE cursor. Session deletion uses the native SDK storage owner before removing its private service reference. Archive and operational metadata remain with Host SQLite.

## Approvals and questions

The public SDK factory receives `hasUI: true`, `interactivePrompts: true`, and an inline extension observing typed native tool-call/approval events. `WorkerInteraction` initializes the native `pi-tui` theme synchronously (`ensureThemeSync`) so builtin `ask` formatting can access `ui.theme`, while `initializeExtensions` wires the real session runner to the worker UI and `setToolUIContext` gives builtin tools the same context. `ApprovalRequest` projects an allowlisted, sanitized public summary (`policyTarget` with opaque pattern `'native-input'`, generic `commandSummary`, and stripped details) rather than exposing raw native execution inputs, private absolute paths, or credentials. The exact native execution input and policy target are retained only in service-private records for policy matching and worker dispatch. Multi-question choices, selections and freeform answers retain native question IDs, enforce single-choice mutual exclusion between `selectedOptions` and `customInput`, and validate before consuming a handle. Native promises and session objects never leave the worker.

The private session namespace exposes `GET approvals`, `POST approvals/:approvalId/respond`, `GET questions`, and `POST questions/:questionId/respond`. Replies require the current version, epoch and worker generation, checking expired/stale owner identity (`410`) before CAS (`409` with `{ expectedVersion, actualVersion, currentRecord }`). The service atomically reserves CAS, publishes requested/resolved events through the existing journal cursor, and includes current pending requests in snapshots. Terminal resolution for cached always-allow and always-deny policies projects explicit minimal `{ policyId, revision }` metadata without spreading internal decision or target fields into the strict public schema. Cancellation and five-minute expiry are terminal; abort, shutdown, worker failure and replacement invalidate old requests without allowing them to revive on a late acknowledgement. Reconnect within an epoch preserves pending requests; a new epoch replaces the pending set.

Always-allow commits a session policy, and always-deny commits a workspace policy, in the Node Host SQLite owner through private child IPC. Node authorizes the captured Host bootstrap scope before writing. A real committed policy ID/revision is required before the worker handle resolves. Failed persistence leaves the request pending with `APPROVAL_POLICY_WRITE_FAILED`; no missing Host handler can fabricate a commit. Policies load before reopening a session and apply to future exact native targets, with workspace denial taking precedence. A failed policy read during reopen preserves an intact live worker when replacement startup has not begun. Web and Electron use that Host; hosted mobile and Capacitor reach the same Host without starting local workers. Task22 still owns external authentication and production route activation.

## Shell projection

`WorkerShell` owns native `AsyncJobManager` jobs backed by `executeBash`. Guest-started jobs suppress native agent delivery, so observing command output does not append it to the transcript. Streaming chunks, not cumulative previews, advance UTF-8 byte cursors. Each job retains at most 65,536 bytes; reads report skipped bytes and preserve complete code points. The newest 200 terminal observations remain available independently of native job eviction.

Output checks session, epoch and worker generation for running and ended jobs. Stop waits for the native job promise and returns success only for an observed stopped termination. Native timeout, nonzero exit and missing exit status remain distinct. Settled jobs release their private native shell-session keys; close cancels and waits for owned jobs. `ShellCoordinator` routes `/api/agent/v1/sessions/:sessionId/shell/jobs` (start/snapshot), `/api/agent/v1/workspaces/:workspaceId/shell/jobs`, `/api/agent/v1/projects/:projectId/shell/jobs`, `/api/agent/v1/shell/jobs`, and `/api/agent/v1/sessions/:sessionId/shell/jobs/:jobId/(output|stop)` across admitted root workers; task22's public Host scope authorization and gateway composition remain separate integration work.

## Catalogs, MCP OAuth, skills and stateless completion

`WorkspaceRoutes` serves `/api/agent/v1/workspaces/:workspaceId/(models|providers|agents)` reads and revisioned configuration, model, credential (`PUT .../credential`, `DELETE .../credential/:credentialRef`) and agent profile mutations, plus `/api/agent/v1/workspaces/:workspaceId/completions` and `.../completions/:completionId/cancel` through a workspace-scoped stateless worker. Native agent profiles and completions are scoped per workspace, maintaining independent model selection, system prompt configuration, and transcript boundaries across roots without cross-workspace leakage. Completions distinguish Host authorization and service HTTP Problem Details errors (such as 403 `UNAUTHORIZED` on provider or tool preset authorization, or 503 `SERVICE_UNAVAILABLE` when the workspace worker is unavailable) from terminal `CompletionResult` outcomes (`status: 'failed'` or `'cancelled'` with structured codes such as `MODEL_UNAVAILABLE`, `PROVIDER_UNAVAILABLE`, `PROVIDER_FAILURE`, `CONTEXT_LIMIT`, `UNSUPPORTED_CAPABILITY`, or `STRUCTURED_OUTPUT_INVALID`). Host authorization or service failures produce HTTP Problem responses directly, without being swallowed into a successful HTTP 200 failed completion payload. `publicModel` projects native catalog models with `getModelPricingStatus`: negative sentinel rates (such as bundled `openrouter/auto`) and `unknown`, `included`, `variable` or unannotated all-zero rates map to `pricing: null` without dropping the model or clamping rates, explicit `free` status keeps `0`, and positive `fixed` rates are preserved. `NativeModels` reloads native settings from disk (`Settings.reloadFromDisk`) and reapplies model policies before reads and selections, preventing deleted bundled providers or profiles from persisting in memory. Reconfiguring provider protocols strips generated inherited chat-model API overrides while preserving explicit non-chat and transport-level overrides. Disabling models uses an explicit match-none glob (`__openchamber_no_enabled_models__/*`) rather than an empty array `[]` (which native filters treat as unrestricted), ensuring an empty enabled-model set is enforced, and model recreation preserves restrictions. `NativeModelRegistry` and `NativeModels` keep canonical provider `credentialRef` selection bound to the exact selected `AuthStorage` row across native `getApiKey`/`getApiKeyWithCredentialForProvider` resolution and the provider catalog, selecting the bound `api_key` row across multiple stored keys, pinning `oauth` session affinity, and failing closed when the bound row is disabled or deleted without falling back to sibling credentials. `NativeAgents` serializes profile frontmatter with a trailing newline before the closing `---` delimiter so `parseAgent` round-trips created and updated profiles. Private `/internal/workspaces/:workspaceId` registers the workspace's `agentDirectoryId` and `/internal/workspaces/:workspaceId/skill-sources` publishes Host-committed workspace or selected-agent skill source revisions.

`CatalogCoordinator` serializes workspace MCP configuration, root-worker admission and scoped fan-out across `/api/agent/v1/sessions/:sessionId/mcp/(catalog|config|apply|servers/:serverId/reconnect)` and `/api/agent/v1/sessions/:sessionId/skills/(catalog|apply|expand)`. Each admitted worker generation initializes its own local skill `catalogRevision` at `"1"` independently of the persisted provider/model configuration revision `"0"`. `WorkerSkills.expand` builds skill prompts with `buildSkillPromptMessage({ ...skill, baseDir: `skill://${skill.name}` })` while `sanitizeRoots` redacts private workspace, agent-directory, and skill-containment roots in descriptions and expanded prompt messages to `[skill-root]`. Subagent session IDs resolve to their owning root worker. Enabled native skill discovery roots (`.github/skills`, `.opencode/skills`, and user root) are preflighted before loading, and `catalog.updated` events for skills are emitted only when `skills.apply` yields an `'applied'` outcome, suppressing publication on failed apply attempts. Remote (`http`/`sse`) MCP servers expose `GET /api/agent/v1/sessions/:sessionId/mcp/servers/:serverId/oauth` and `POST /api/agent/v1/sessions/:sessionId/mcp/servers/:serverId/oauth` for the addressed root worker (`MCPOAuthRequest` actions `start`, `complete`, `cancel` and `disconnect` with `persistedRevision` and `workerGeneration`, returning `MCPOAuthResult` in `pending`, `authenticated` or `unauthenticated` state). OAuth flows authorize the server and public OAuth endpoints through the Host callback before discovery and login, classify pre-settlement failures before cleanup aborts the flow, persist/reload credentials in the worker's owned `AuthStorage`, and disconnect any active server transport when credentials are removed.


## Package inputs

The SDK closure uses source-derived archives and patches under `vendor/omp/c9de2b02`, not matching-version registry substitutes or an external source checkout. The vendor manifest binds archive identities and parent-scoped dependency versions. Linux x64 native inputs are retained; non-Linux native behavior and native source-build equivalence remain unverified.

`bun run type-check` resolves the installed first-party SDK closure from the package directory via `Bun.resolveSync` (resolving the active patched installation in the workspace's scoped `.bun` cache with the explicit `patchedDependencies` delta in `src/sdk.ts`, `src/async/job-manager.ts` and `src/tools/bash.ts`), emits declarations with the pinned upstream publish convention into `node_modules/.cache/omp-types`, and checks this package's source strictly against them. No handwritten SDK facade or runtime alias is used, and the 13 vendored tarball files remain byte-identical. This avoids checking unrelated upstream CLI implementation as application code. Bun build and runtime resolve the installed vendored TypeScript source with that patch applied; M0 evidence applies only to unchanged SDK owners, while the patched initial model-refresh fallback and native Bash observation paths require re-proof in the mandatory M2 canonical HTTP scenarios.
