# 권한과 안전망

에이전트의 모든 작업(명령 실행, 파일 편집, MCP 도구 호출, 페이지 가져오기)은 Host 인가자와 Agent Service의 워커 정책을 통해 평가됩니다. OpenChamber의 권한 모드는 작업에 승인이 필요할 때의 처리 방식을 결정합니다.

## 인가와 승인

Host Gateway는 프로젝트 디렉터리를 기준으로 파일 시스템 접근을 검증합니다. 프로젝트 루트 외부의 경로를 대상으로 하는 작업은 즉시 거부됩니다. 프로젝트 루트 내부에서는 일상적인 파일 읽기와 편집이 프로젝트 파일 도구를 통해 추가 확인 없이 진행됩니다.

권한이 부여되지 않은 셸 명령 실행과 같이 사용자의 동의가 필요한 작업이 발생하면, 에이전트는 일시 중지하고 승인 요청을 생성합니다. 승인 요청에 응답할 때 한 번만 허용하거나, 현재 세션 동안 항상 허용하거나, 워크스페이스 전체에서 거부할 수 있습니다. 지속되는 승인 정책에는 세션 단위 허용 또는 워크스페이스 단위 거부가 저장됩니다.

에이전트가 확인하고 호출할 수 있는 도구를 구성하려면 **설정 → 에이전트**의 **허용된 도구**(allowed tools) 필드를 사용하세요. 새 세션의 기본 권한 모드를 선택하려면 **설정 → 세션**을 사용하세요.

## 세 가지 모드

| 모드 | 승인 요청에 답하는 쪽 |
| --- | --- |
| **매번 묻기** | 사용자입니다. 모든 요청이 사용자의 답을 기다립니다. |
| **안전망** | Jev가 일상적인 작업은 통과시키고 위험한 작업은 사용자에게 남깁니다. |
| **모두 승인** | OpenChamber가 동의가 필요한 요청을 자동으로 승인합니다. |

**모두 승인** 모드에서는 동의가 필요한 요청이 자동으로 승인되어 대기 없이 작업이 계속 진행됩니다. 워크스페이스 디렉터리 격리 및 워크스페이스 거부 정책을 포함한 Host의 보안 경계 검사는 모든 작업에서 항상 실행됩니다.

## 모드 바꾸기

- **한 세션만:** 입력창의 방패 버튼을 누릅니다. 누를 때마다 다음 모드로 바뀝니다.
- **새 세션:** **설정 → 세션 → 권한**에서 기본 모드를 고릅니다. 기존 세션은 자기 모드를 유지합니다.

하위 에이전트는 자신을 시작한 세션을 따릅니다.

## 안전망

이 모드에서 OpenChamber는 요청마다 [Jev](/ko/classification-providers/)에게 묻습니다. 일상적인 작업인가, 아니면 사용자가 결정해야 하는가. 읽기, 빌드, 테스트 실행, 프로젝트 파일 편집, 평범한 커밋은 통과합니다. git 기록 다시 쓰기, 데이터 삭제, 시스템 변경, 배포, 어딘가에 게시, 외부로 파일 보내기는 불분명한 작업과 마찬가지로 사용자를 기다립니다.

보류된 요청은 도구 이름, 명령 요약, 세부 정보를 포함한 승인 카드로 채팅에 표시되며, 허용하거나 거부할 수 있습니다. Jev가 4초 안에 답하지 않아도 작업은 사용자를 기다립니다. 분류가 실패하거나 시간이 초과되었을 때 안전망이 작업을 허용하는 일은 없습니다.

안전망에는 [분류 제공자](/ko/classification-providers/)가 필요합니다. 없으면 방패 버튼이 이 모드를 건너뛰고, 설정에서도 비활성화됩니다.

## 자리를 비워도 계속 동작

모드는 OpenChamber 서버에 있으므로, 탭을 닫거나 휴대폰을 잠가도 계속 요청에 답하고 재시작 후에도 유지됩니다.
