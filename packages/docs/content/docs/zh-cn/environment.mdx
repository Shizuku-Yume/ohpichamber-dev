# 环境变量

OhPiChamber 会在启动时读取这些变量。对于开机启动服务，`ohpichamber startup enable` 默认会保存当前环境的 snapshot，所以如果要让服务使用新的变量，请重新运行它。

## 供智能体会话、Git 与终端使用的变量

要给智能体会话、Git、终端和[项目操作](/zh-cn/project-actions/)提供你自己的变量，比如 API 令牌或数据库地址，请在 **设置 → 通用 → 环境变量** 中添加，而不是在启动 OhPiChamber 之前导出。这些值只保存在运行 OhPiChamber 的机器上，位于数据目录中的 `environment.json`，只有你的用户能读取。设置不会再显示已保存的值：你可以替换或删除它，但无法读回。

- 智能体会话在启动时读取这些变量。
- Git、终端和项目操作会在下一次运行时拿到这些变量。

项目可以在 **设置 → 项目** 中添加自己的变量，或者添加一条输出这些变量的命令，例如 `direnv export json`。参阅[项目](/zh-cn/projects/#项目环境)。

下面的所有变量都由 OhPiChamber 本身在启动时读取。

## OhPiChamber 服务器

### `OPENCHAMBER_HOST`

OhPiChamber web 服务器监听的地址。使用 `0.0.0.0` 可允许其他机器访问。

### `OPENCHAMBER_LAN_URL`

网络中其他设备访问 OhPiChamber 所用的地址，例如 `http://192.168.1.20:3000`。配对链接和二维码会使用它，而不是 OhPiChamber 自己检测到的地址。当检测结果不对时设置它，例如在 Docker 中，OhPiChamber 只能看到容器的内部地址。

### `OPENCHAMBER_UI_PASSWORD`

浏览器 UI 的密码。当你绑定到 localhost 之外、使用隧道或反向代理时，请设置它。

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

未勾选“信任此设备”时，浏览器登录的有效时长（小时）。默认值为 `12`。

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

在你选择信任的设备上，登录的有效时长（天）。默认值为 `7`。

### `OPENCHAMBER_API_ONLY`

设置为 `true` 或 `1` 时，以 headless 模式启动 OhPiChamber。桌面和移动客户端仍可使用 API 路由，但不会提供浏览器 UI。

### `OPENCHAMBER_FRAME_ANCESTORS`

允许在自己页面的框架中显示 OhPiChamber 的源，用空格分隔，例如 `https://dash.example.com`。`*` 允许任何站点。默认只有 OhPiChamber 本身及其桌面和移动应用可以嵌入它，其他站点无法在它的按钮上叠加内容。

### `OPENCHAMBER_TRUSTED_PROXIES`

运行在其他机器或其他容器中的反向代理地址，用逗号分隔，例如 `192.168.1.10` 或 `172.18.0.0/16`。OhPiChamber 按客户端限制登录失败次数，只有当请求来自本机或这里列出的地址时，才会从 `X-Forwarded-For` 读取客户端地址。未列出的代理会被当作一个客户端，因此一个人的失败尝试可能会让它后面的所有人暂时无法登录。

### `OPENCHAMBER_DATA_DIR`

覆盖 OhPiChamber 数据目录。默认是 `~/.config/ohpichamber`。

OhPiChamber 存储的所有内容都位于此目录下：设置、认证、项目配置、主题、计划和语音模型。在 1.23 之前使用自定义目录的实例会在首次启动时将 `projects`、`themes` 和 `speech-models` 文件夹从 `~/.config/ohpichamber` 复制到此目录；原文件夹保持不变，不会合并任何内容。

### `OPENCHAMBER_CHATS_DIR`

更改 OhPiChamber 为无项目聊天创建的托管聊天目录的位置。默认是 `~/.config/ohpichamber/chats`。现有聊天不会被移动。

### `OPENCHAMBER_COMPRESS_API`

控制 API 响应压缩。`true` 或 `1` 强制开启，`false` 或 `0` 强制关闭。

### `OPENCHAMBER_SKIP_API_COMPRESSION`

设置为 `true` 或 `1` 时关闭 API 响应压缩。它优先于 `OPENCHAMBER_COMPRESS_API`。

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

设置为 `true` 或 `1` 时启用详细 HTTP request logs。

## 代理

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

OhPiChamber 自身发出的请求（例如用量限额和技能目录）会通过代理发送。小写变量名同样有效。`NO_PROXY` 中的主机直接连接，`localhost`、`127.0.0.1` 和 `::1` 始终直接连接，因此登录回调和本地连接不受影响。

## Terminal 和 Git

### `OPENCHAMBER_TERMINAL_SHELL`

OhPiChamber terminal sessions 使用的 shell executable。

### `OPENCHAMBER_GIT_BINARY`

OhPiChamber Git 功能使用的 Git executable。

### `GIT_BINARY`

Git executable 的备用 override。OhPiChamber 专用配置建议使用 `OPENCHAMBER_GIT_BINARY`。

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Git-backed file reads cache 的 TTL，单位为毫秒。调试时可设置为 `0` 禁用 cache。

## 语音和隧道

### `OPENAI_API_KEY`

OhPiChamber 语音功能直接调用 OpenAI 时使用的 API key。它不会发送到自定义的 OpenAI 兼容服务器：请在设置中为该服务器单独配置密钥。

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

设置为 `true` 或 `1` 时，允许语音功能使用远程 OpenAI-compatible base URLs。

### `NGROK_AUTHTOKEN`

OhPiChamber tunnel commands 使用的 ngrok auth token。也可以用 `ngrok config add-authtoken <token>` 配置。

## Runtime helpers

### `BUN_BINARY`

OhPiChamber 启动 daemon processes 时使用的 Bun executable。

### `BUN_INSTALL`

Bun 安装根目录。OhPiChamber 使用它查找 `bin/bun` 来启动 daemon 和执行更新。
