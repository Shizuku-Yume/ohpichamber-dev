# Berechtigungen und Sicherheitsnetz

Jede Aktion des Agenten (einen Befehl ausführen, eine Datei bearbeiten, ein MCP-Tool aufrufen, eine Seite abrufen) wird von der Host-Autorisierung und der Worker-Richtlinie des Agent Service ausgewertet. Die Berechtigungsmodi von OpenChamber entscheiden, was passiert, wenn eine Aktion eine Bestätigung erfordert.

## Autorisierung und Genehmigungen

Das Host-Gateway prüft Dateisystemzugriffe anhand des Projektverzeichnisses. Aktionen, die auf Pfade außerhalb des Projektstamms zielen, werden direkt verweigert. Innerhalb des Projektstamms laufen routinemäßige Dateilesevorgänge und -bearbeitungen über Projekt-Dateitools ohne zusätzliche Rückfragen ab.

Erfordert eine Aktion die Zustimmung des Benutzers, etwa das Ausführen eines nicht genehmigten Shell-Befehls, pausiert der Agent und erstellt eine Genehmigungsanfrage. Beim Beantworten einer Genehmigungsanfrage kannst du sie einmalig erlauben, für die restliche Sitzung erlauben oder arbeitsbereichsweit verweigern. Dauerhafte Genehmigungsrichtlinien speichern sitzungsbezogene Freigaben oder arbeitsbereichsbezogene Verweigerungen.

Um zu konfigurieren, welche Tools ein Agent sehen und aufrufen kann, nutze das Feld **Erlaubte Tools** (allowed tools) unter **Einstellungen → Agenten**. Den Standard-Berechtigungsmodus für neue Sitzungen wählst du unter **Einstellungen → Sitzungen**.

## Die drei Modi

| Modus | Wer Genehmigungsanfragen beantwortet |
| --- | --- |
| **Jedes Mal fragen** | Du. Jede Anfrage wartet auf deine Antwort. |
| **Sicherheitsnetz** | Jev lässt Routineaktionen durch und hält riskante für dich zurück. |
| **Alles akzeptieren** | OpenChamber genehmigt zustimmungsbedürftige Anfragen automatisch. |

Im Modus **Alles akzeptieren** werden zustimmungsbedürftige Anfragen automatisch genehmigt, sodass die Arbeit ohne Unterbrechung weiterläuft. Sicherheitsgrenzen des Hosts, einschließlich der Beschränkung auf das Projektverzeichnis und arbeitsbereichsweiter Verweigerungsrichtlinien, werden weiterhin bei jeder Aktion uneingeschränkt geprüft.

## Modi wechseln

- **Für eine Sitzung:** Klicke auf den Schild-Button im Eingabefeld. Jeder Klick schaltet zum nächsten Modus.
- **Für neue Sitzungen:** Wähle den Standard unter **Einstellungen → Sitzungen → Berechtigungen**. Bestehende Sitzungen behalten ihren Modus.

Subagenten folgen der Sitzung, die sie gestartet hat.

## Das Sicherheitsnetz

In diesem Modus fragt OpenChamber [Jev](/de/classification-providers/) zu jeder Anfrage: Ist das Routine, oder solltest du entscheiden? Lesen, Bauen, Tests ausführen, Projektdateien bearbeiten und normale Commits gehen durch. Git-Verlauf umschreiben, Daten löschen, das System ändern, deployen, irgendwo etwas veröffentlichen oder Dateien nach außen schicken warten auf dich, genauso wie alles, was unklar ist.

Eine zurückgehaltene Anfrage zeigt die Genehmigungskarte im Chat mit Tool-Namen, Befehlszusammenfassung und Details, auf der du sie erlauben oder ablehnen kannst. Antwortet Jev nicht innerhalb von vier Sekunden, wartet die Aktion ebenfalls auf dich. Das Sicherheitsnetz erlaubt nie eine Aktion, wenn die Klassifizierung fehlschlägt oder das Zeitlimit überschreitet.

Das Sicherheitsnetz braucht einen [Klassifizierungsanbieter](/de/classification-providers/). Ohne ihn überspringt der Schild-Button diesen Modus, und in den Einstellungen ist er deaktiviert.

## Läuft weiter, während du weg bist

Der Modus lebt im OpenChamber-Server. Er beantwortet Anfragen also weiter, nachdem du den Tab geschlossen oder das Handy gesperrt hast, und übersteht Neustarts.


## Verwandt

- [Klassifizierungsanbieter (Jev)](/de/classification-providers/): das Modell hinter dem Sicherheitsnetz einrichten
- [Benachrichtigungen](/de/notifications/): erfahren, wenn eine Anfrage auf dich wartet
