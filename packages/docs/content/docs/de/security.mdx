# Sicherheit

OhPiChamber gewährt Zugriff auf Ihren Rechner und Ihren Code. Sperren Sie es also ab, bevor jemand außer Ihnen darauf zugreifen kann. Diese Seite behandelt das UI-Passwort, Passkeys und was Sie wissen sollten, bevor Sie OhPiChamber in ein Netzwerk exponieren.

## UI-Passwort setzen

Starten Sie OhPiChamber mit einem Passwort, und die Browser-UI fragt danach:

```bash
ohpichamber --ui-password be-creative-here
```

Sie können es auch über die Umgebungsvariable `OPENCHAMBER_UI_PASSWORD` setzen, statt es in die Befehlszeile zu schreiben. Nach der Anmeldung merkt sich OhPiChamber das Gerät für eine Weile, damit Sie nicht jedes Mal gefragt werden.

Setzen Sie immer ein Passwort, wenn die Instanz für andere erreichbar ist — besonders über einen [Tunnel](/de/tunnels/) oder das öffentliche Internet.

## Passkeys

Sobald ein Passwort gesetzt ist, können Sie Passkeys (Face ID, Touch ID, ein Sicherheitsschlüssel) für eine schnellere Anmeldung hinzufügen. Fügen Sie sie unter **Einstellungen → OhPiChamber → Passkeys** hinzu.

Passkeys sind an das aktuelle Passwort gebunden. Wenn Sie das Passwort ändern oder entfernen, werden gespeicherte Passkeys gelöscht und Sie fügen sie erneut hinzu.

## Geräte-Tokens

Geräte, die über [Ein Gerät verbinden](/de/connect-devices/) gekoppelt werden, authentifizieren sich mit eigenen gerätespezifischen Tokens, nicht mit dem UI-Passwort. Pairing-Links sind nur einmal nutzbar und laufen ab, wenn sie nicht verwendet werden; jedes gekoppelte Gerät wird unter **Einstellungen → Remote-Instanzen → Mit diesem Server verbinden** aufgeführt, wo Sie es jederzeit widerrufen können. Verbindungen von außerhalb laufen über das [Private Relay](/de/private-relay/), das Ende-zu-Ende verschlüsselt ist und Ihren Traffic nicht lesen kann.

## Bevor Sie es freigeben

- Standardmäßig lauscht OhPiChamber nur auf Ihrem eigenen Rechner (`127.0.0.1`). Es braucht eine bewusste Änderung, um breiter zu lauschen, und Sie sollten vorher ein Passwort setzen.
- Für Ihre eigenen Geräte bevorzugen Sie [Pairing](/de/connect-devices/) mit dem [Private Relay](/de/private-relay/) — dabei wird überhaupt nichts öffentlich freigegeben.
- Wenn Sie eine öffentliche URL brauchen, verwenden Sie lieber einen [Tunnel](/de/tunnels/) oder ein privates Netzwerk (z. B. VPN), statt einen Port ins Internet zu öffnen.
- Wenn Sie OhPiChamber hinter Ihrem eigenen HTTPS-Server betreiben, sehen Sie sich [Reverse Proxy](/de/reverse-proxy/) an.

## Enterprise-Modus

Wenn Ihr Team Gesprächsinhalte nur an die Modellanbieter senden darf, die im Host konfiguriert sind, schalten Sie den Enterprise-Modus ein. Dafür gibt es zwei Wege, und einer davon reicht.

### Eine Richtliniendatei auf dem Rechner

Das ist der Weg für Laptops, die Sie verwalten. Legen Sie eine Datei namens `policy.json` in einen Ordner, in den nur ein Administrator schreiben darf:

| System | Pfad |
|---|---|
| macOS | `/Library/Application Support/OhPiChamber/policy.json` |
| Windows | `C:\ProgramData\OhPiChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

Der Pfad hängt nicht davon ab, wie OhPiChamber installiert ist. Die Desktop-App, der über npm gestartete Webserver und die CLI lesen alle dieselbe Datei. Verteilen können Sie sie über Ihre Geräteverwaltung (Jamf, Intune und Ähnliche). Für einen Server in Docker binden Sie die Datei unter dem Linux-Pfad ein.

```json
{
  "enterpriseMode": true,
  "organization": "Acme",
  "relayUrl": "wss://relay.acme.com/ws",
  "allowNetworkAccess": false,
  "allowedExtensions": ["https://github.com/acme/"],
  "jev": {
    "url": "https://llm.acme.com/v1/systemone",
    "model": "acme-classifier",
    "apiKey": "..."
  }
}
```

Nötig ist nur `enterpriseMode`. `organization` erscheint in den Einstellungen als „Verwaltet von Acme“, damit alle wissen, wer das entschieden hat. Mit `relayUrl` und `jev` legen Sie Ihr eigenes Relay und Ihren eigenen Jev-Endpunkt fest, `allowNetworkAccess` lässt andere Geräte OhPiChamber über das Netzwerk erreichen, und `allowedExtensions` listet die Erweiterungs-Repositories auf, denen Sie vertrauen. Alle sind unten beschrieben.

- Nichts, was ein Nutzer einstellt, weder in den Einstellungen noch in der Umgebung, schaltet aus, was die Datei einschaltet.
- Wenn die Datei den Enterprise-Modus einschaltet, entscheidet nur die Datei. Die Umgebungsvariablen unten für Relay, Jev und Netzwerkzugriff werden ignoriert, weil ein Nutzer sie selbst setzen kann.
- Wenn die Datei existiert, sich aber nicht lesen lässt oder kein gültiges JSON ist, bleibt der Enterprise-Modus an und nichts wird festgelegt. Die Einstellungen zeigen dann, dass die Richtlinie nicht gelesen werden konnte. Eine kaputte Datei hebt den Schutz nie stillschweigend auf.
- Änderungen greifen ohne Neustart.
- OhPiChamber läuft unter dem Konto des Nutzers, also kann der Nutzer die Datei lesen. Denken Sie daran, bevor Sie einen API-Schlüssel hineinschreiben.

### Eine Umgebungsvariable

Auf einem Server oder in einem Container, wo Sie die Umgebung selbst in der Hand haben, genügt das:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

Auf einem Laptop ist das die schwächere Sperre: Die Desktop-App liest die Variable aus dem Profil der Login-Shell (zum Beispiel `~/.zshrc`), und das kann der Nutzer bearbeiten. Nehmen Sie dort die Richtliniendatei.

Mit der Variable kommen auch Relay, Jev, Netzwerkzugriff und erlaubte Erweiterungen aus eigenen Variablen: `OPENCHAMBER_RELAY_URL`, `OPENCHAMBER_JEV_URL`, `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`, `OPENCHAMBER_ALLOWED_EXTENSIONS` (Repository-URLs, durch Kommas getrennt) und `OPENCHAMBER_ALLOW_LOCAL_EXTENSIONS=1`. In Docker brauchen Sie die für den Netzwerkzugriff, weil der Server über den Container hinaus lauschen muss.

### Integrierte Skill-Kataloge ausblenden

OhPiChamber bringt einige öffentliche Skill-Kataloge mit (Anthropic, OpenAI, Cursor, Matt Pocock). Wenn deine Organisation einen eigenen pflegt, füge ihn als eigenen Katalog hinzu und blende die integrierten in der Richtliniendatei aus. Das funktioniert mit oder ohne Enterprise-Modus.

```json
{
  "hideBuiltinSkillCatalogs": true
}
```

Die Einstellungen bieten dann nur Kataloge an, die Personen selbst hinzufügen, und OhPiChamber lädt keinen integrierten, auch nicht auf direkte Anfrage. Eine Umgebungsvariable gibt es dafür nicht, da Nutzer diese selbst setzen können.

### Beispiele

Die Richtliniendatei auf einem Mac ablegen. Führen Sie im Terminal als Administrator aus:

```bash
sudo mkdir -p "/Library/Application Support/OhPiChamber"
sudo tee "/Library/Application Support/OhPiChamber/policy.json" > /dev/null <<'JSON'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
JSON
```

Unter Linux geht es genauso, nur mit `/etc/openchamber` als Ordner.

Unter Windows starten Sie PowerShell als Administrator. Die letzte Zeile sorgt dafür, dass nur Administratoren und das System in den Ordner schreiben können:

```powershell
New-Item -ItemType Directory -Force "C:\ProgramData\OhPiChamber" | Out-Null
@'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
'@ | Set-Content -Encoding UTF8 "C:\ProgramData\OhPiChamber\policy.json"
icacls "C:\ProgramData\OhPiChamber" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Users:(OI)(CI)RX"
```

Ein Server in Docker, ergänzt im `environment` von `docker-compose.yml`. Der Container lauscht über sich hinaus und braucht deshalb erlaubten Netzwerkzugriff:

```yaml
environment:
  OPENCHAMBER_UI_PASSWORD: ${OPENCHAMBER_UI_PASSWORD}
  OPENCHAMBER_ENTERPRISE_MODE: "1"
  OPENCHAMBER_ALLOW_NETWORK_ACCESS: "1"
  # Optional:
  OPENCHAMBER_RELAY_URL: wss://relay.acme.com/ws
  OPENCHAMBER_JEV_URL: https://llm.acme.com/v1/systemone
  OPENCHAMBER_JEV_MODEL: acme-classifier
  OPENCHAMBER_JEV_API_KEY: ${ACME_JEV_KEY}
  OPENCHAMBER_ALLOWED_EXTENSIONS: https://github.com/acme/
```

Zur Kontrolle öffnen Sie Einstellungen → Anbieter: Oben erscheint ein Hinweis zum Enterprise-Modus mit dem Namen Ihrer Organisation.

### Was sich ändert

- Die Verwaltung von Modellanbietern und Anmeldedaten liegt beim Host. Im Enterprise-Modus werden Operationen zur Anbietereinrichtung – das Verbinden eines Anbieters, das Hinzufügen oder Konfigurieren benutzerdefinierter Anbieter oder Modelle, das Schreiben von Anmeldedaten, die Modellerkennung oder das Starten von OAuth – vom Host verweigert; bestehende Konten zu entfernen oder zu wechseln funktioniert weiterhin. In der Sitzung oder im Workspace konfigurierte MCP-Server funktionieren weiterhin, da sie diesen Server und keinen Modellanbieter erreichen. Der explizite Preflight zur Übergabe von Anmeldedaten wird vom Host bei eingeschaltetem Enterprise-Modus ebenfalls verweigert; es werden keine Anmeldedaten gelesen oder importiert.
- Das Ausfüllen von Modellinformationen erreicht OpenRouter im Enterprise-Modus nie. Die Anfrage enthält ohnehin nur Modell-IDs; bei aktivem Modus wird sie verweigert, sodass das automatische Ausfüllen aus dem mitgelieferten Katalog antwortet und unbekannte Modelle ihre leeren Felder behalten.
- Die Anmeldung bei einem MCP-Server bleibt aus. Der Start einer MCP-Anmeldung und der Browser-Callback, der sie abschließt, werden vom Host verweigert (`403 enterprise_mode`). Server ohne Anmeldung, auch lokale mit Umgebungswerten, sind nicht betroffen.
- Der Host verweigert native Websuchen an der Netzwerkgrenze und blockiert das Hinzufügen oder Ersetzen von Suchschlüsseln. Sucheinstellungen können Sie weiterhin ändern und gespeicherte Schlüssel löschen; Schlüssel sind nur schreibbar und werden nie zurückgegeben.
- [Klassifizierungsanbieter (Jev)](/classification-providers/) bleiben aus, auch ein eigener Endpunkt, den jemand in den Einstellungen einträgt. Sicherheitsnetz und Auto werden nicht angeboten, und Sitzungen kommen nur von Hand in Arbeit. Um Jev über Ihre eigene Infrastruktur zu nutzen, legen Sie einen Endpunkt mit `jev` in der Richtliniendatei oder mit `OPENCHAMBER_JEV_URL` fest (dazu `OPENCHAMBER_JEV_MODEL` und, falls er einen braucht, `OPENCHAMBER_JEV_API_KEY`). Er wird zur Voreinstellung, lässt sich weiterhin ausschalten, und etwas anderes kann nicht gewählt werden.
- Vorlesen über OpenAI ist aus. Ein eigener Server für Sprachausgabe oder Transkription muss auf demselben Rechner laufen. Lokale Stimmen und lokale Diktiermodelle funktionieren weiter.
- Push-Benachrichtigungen an Telefone und Browser enthalten nur einen allgemeinen Titel wie „Agent response is ready“, ohne Nachrichtentext oder Sitzungsnamen. Desktop-Benachrichtigungen bleiben auf Ihrem Rechner und behalten den vollständigen Text.
- [Externe Tunnel](/de/tunnels/) (Cloudflare, ngrok, Tailscale) sind aus. Cloudflare und ngrok entschlüsseln den Traffic an ihrem Edge und sehen jede Anfrage im Klartext; Tailscale Serve und Funnel öffnen diesen Rechner für andere Geräte.
- `.drawio`-Diagramme öffnen sich als XML-Text. Der Diagrammeditor ist eine Seite von diagrams.net, und ein dort geöffnetes Diagramm wird ihr übergeben.
- Der Integrationskatalog in der Seitenleiste ist ausgeblendet. Er installiert externe Dienste aus einer Liste, die mit OhPiChamber ausgeliefert wird. MCP-Server, Plugins und Skills in den Einstellungen hinzuzufügen funktioniert wie bisher.
- Schriften für Oberfläche und Code, die von einem öffentlichen CDN geladen werden, fallen auf die Systemschriften zurück. Deine Auswahl bleibt für die Zeit ohne den Modus erhalten.
- Das [Private Relay](/de/private-relay/) funktioniert nur über ein selbst gehostetes Relay, das Sie mit `relayUrl` in der Richtliniendatei oder `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws` konfigurieren. OhPiChamber hat kein eingebautes gemeinsames Relay (und entfernter iOS-Push erfordert `OPENCHAMBER_PUSH_RELAY_URL` oder eine direkte APNs-Konfiguration), sodass Ihr eigenes Relay die Verbindungsmetadaten und den Weg zu diesem Rechner in Ihrem Netzwerk hält. Ohne konfigurierte Relay-URL lassen sich keine Geräte über das Relay koppeln.
- Seiten, die der Agent per Link und PIN mit anderen Personen teilt, laufen nur über Ihr eigenes Relay, das mit `relayUrl` oder `OPENCHAMBER_RELAY_URL` eingestellte. Das Relay speichert nur die verschlüsselte Seite und Antwort, aber der Link führt dorthin. Ohne eigenes Relay gibt es das Teilen nicht: Der Agent bekommt es nicht angeboten, und der Server lehnt es ab. Seiten, die andere mit Ihnen geteilt haben, öffnet OhPiChamber ebenso nur über Ihr eigenes Relay; ohne es bleibt ein eingefügter Link einfacher Text.
- OhPiChamber lauscht nur auf dem Rechner, auf dem es läuft. Die Desktop-Einstellung, mit der andere Geräte im lokalen Netzwerk die App öffnen können, ist aus, und der Server startet nicht auf einer Netzwerkadresse, weder über die CLI (`--host`, `--lan`) noch über die Umgebung. Taucht die Richtliniendatei auf, während die App läuft, werden Verbindungen von anderen Rechnern bis zum nächsten Start getrennt. Netzwerkzugriff erlauben Sie mit `"allowNetworkAccess": true` in der Richtliniendatei oder mit `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`, wo die Umgebung den Enterprise-Modus einschaltet. Denken Sie daran, dass die Verbindung unverschlüsseltes HTTP ist, in einem gemeinsamen Netzwerk kann sie also jeder mitlesen; stellen Sie einen Server, den andere erreichen, hinter [Ihr eigenes HTTPS](/de/reverse-proxy/).
- [Erweiterungen](/de/extensions/), die Daten vom Rechner nach außen senden können (weil sie eine externe API ansprechen, von externen Adressen laden, einen Hintergrunddienst ausführen, sich an diesen Dienst schicken lassen, was der Agent in Sitzungen sagt, Sitzungen aus dem Host lesen oder Sitzungen starten, Berechtigungsanfragen des Agenten beantworten, Anweisungen hinzufügen), lassen sich nur aus einem Git-Repository installieren, das in `allowedExtensions` steht. Eine erlaubte Erweiterung, die Benachrichtigungen zustellt, bekommt nur den allgemeinen Titel, ohne Nachrichtentext, Sitzungsnamen oder Projekt, genau wie das Telefon. Eine erlaubte Erweiterung, die als Tracker dient, bekommt Ihre Suchanfragen und die Bezeichner der Elemente, die Sie öffnen, und die Sitzungskommentare, die sie postet, tragen eine feste Beschriftung und einen Link zur Sitzung, nie das, was darin gesagt wurde. Eine erlaubte Erweiterung, die die Nutzung meldet, bekommt die Zugangsdaten, die der Host für die in ihrem Manifest aufgezählten Anbieter hält und denen du in ihrem Dialog zugestimmt hast, und nichts aus deinen Sitzungen. Erweiterungen, die nichts davon tun, installieren Sie wie gewohnt. Eine installierte Erweiterung aus einer anderen Quelle bleibt aus, und die Einstellungen sagen, warum. Die Liste enthält Repository-URLs, weil eine Erweiterung ihren Namen selbst wählt; ein Eintrag, der auf `/` endet, wie `https://github.com/acme/`, erlaubt jedes Repository darunter. Auf den Rechnern von Leuten, die Erweiterungen entwickeln, erlaubt `"allowLocalExtensions": true` außerdem die Installation aus einem lokalen Ordner. Ein ZIP bleibt in jedem Fall gesperrt.
- Umgebungsvariablen aus **Einstellungen → Allgemein** erreichen OMP nicht, weil eine davon einen Anbieterschlüssel enthalten könnte. Git, das Terminal und Projektaktionen bekommen sie weiterhin.

Aufgaben des kleinen Modells (Sitzungstitel, Zusammenfassungen, Commit-Nachrichten, die Durchsicht der Änderungen) brauchen keinen besonderen Modus. Sie laufen immer auf dem kleinen Modell, das Sie in den Einstellungen gewählt haben, auf einem kleinen Modell des Anbieters, mit dem Sie gerade arbeiten, oder auf dem im Host konfigurierten Standardmodell. Sie weichen nie auf einen anderen Anbieter aus, der zufällig ebenfalls verbunden ist.
