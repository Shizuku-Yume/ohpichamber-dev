# Umgebungsvariablen

OhPiChamber liest diese Umgebungsvariablen beim Start. Für Startdienste speichert `ohpichamber startup enable` die aktuelle Umgebung standardmäßig als Schnappschuss, also führe den Befehl nach Änderungen an den Variablen, die der Dienst verwenden soll, erneut aus.

## Variablen für Agent-Sitzungen, Git und das Terminal

Um Agent-Sitzungen, Git, dem Terminal und [Projektaktionen](/de/project-actions/) eigene Variablen mitzugeben, etwa ein API-Token oder die Adresse einer Datenbank, trage sie unter **Einstellungen → Allgemein → Umgebungsvariablen** ein, statt sie vor dem Start von OhPiChamber zu exportieren. Die Werte bleiben auf dem Rechner, auf dem OhPiChamber läuft, in `environment.json` im Datenverzeichnis, und nur dein Benutzer kann sie lesen. Die Einstellungen zeigen einen Wert nie wieder an: Du kannst ihn ersetzen oder entfernen, aber nicht zurücklesen.

- Agent-Sitzungen erhalten sie beim Start.
- Git, das Terminal und Projektaktionen bekommen sie beim nächsten Lauf.

Ein Projekt kann unter **Einstellungen → Projekte** eigene Variablen hinzufügen oder einen Befehl, der sie ausgibt, etwa `direnv export json`. Siehe [Projekte](/de/projects/#projektumgebung).

Alles Weitere unten liest OhPiChamber selbst beim Start.

## OhPiChamber-Server

### `OPENCHAMBER_HOST`

Bind-Adresse für den OhPiChamber-Webserver. Verwende `0.0.0.0`, um Zugriff von anderen Maschinen zu erlauben.

### `OPENCHAMBER_LAN_URL`

Die Adresse, unter der andere Geräte in deinem Netzwerk OhPiChamber erreichen, zum Beispiel `http://192.168.1.20:3000`. Kopplungslinks und QR-Codes bieten sie statt der selbst erkannten Adresse an. Setze sie, wenn diese Erkennung falsch liegt, etwa in Docker, wo OhPiChamber nur die interne Adresse des Containers sieht.

### `OPENCHAMBER_UI_PASSWORD`

Passwort für die Browser-Oberfläche. Verwende es, wenn du außerhalb von localhost bindest, Tunnels nutzt oder hinter einem Reverse Proxy läufst.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

Wie lange eine Anmeldung im Browser gilt, in Stunden, wenn „Diesem Gerät vertrauen“ aus ist. Standard ist `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

Wie lange eine Anmeldung gilt, in Tagen, auf einem Gerät, dem du vertraust. Standard ist `7`.

### `OPENCODE_JWT_SECRET`

Überschreibt das Geheimnis zum Signieren von Host-UI-Sitzungstokens. Diese Einstellung steuert die Sitzungssignierung des Hosts und betrifft nicht die Agent-Runtime. Halte diesen Wert geheim. Wenn gesetzt, ist die globale Abmeldung nicht verfügbar, da OhPiChamber das Signiergeheimnis nicht rotieren kann.

### `OPENCHAMBER_API_ONLY`

Startet OhPiChamber im Headless-Modus, wenn auf `true` oder `1` gesetzt. API-Routen bleiben für Desktop- und Mobile-Clients verfügbar, aber die Browser-Oberfläche wird nicht ausgeliefert.

### `OPENCHAMBER_FRAME_ANCESTORS`

Origins, die OhPiChamber in einem Frame auf ihrer eigenen Seite zeigen dürfen, durch Leerzeichen getrennt, zum Beispiel `https://dash.example.com`. `*` erlaubt jede Seite. Standardmäßig dürfen nur OhPiChamber selbst und seine Desktop- und Mobile-Apps es einbetten, damit keine fremde Seite seine Schaltflächen überlagern kann.

### `OPENCHAMBER_TRUSTED_PROXIES`

Adressen von Reverse Proxys, die auf einem anderen Rechner oder in einem anderen Container laufen, durch Kommas getrennt, etwa `192.168.1.10` oder `172.18.0.0/16`. OhPiChamber begrenzt fehlgeschlagene Anmeldeversuche pro Client und liest die Adresse des Clients nur dann aus `X-Forwarded-For`, wenn die Anfrage von diesem Rechner oder von einer hier eingetragenen Adresse kommt. Ein nicht eingetragener Proxy zählt als ein Client: Die Fehlversuche einer Person können dann alle dahinter eine Weile von der Anmeldung aussperren.

### `OPENCHAMBER_DATA_DIR`

Überschreibt das OhPiChamber-Datenverzeichnis. Standard ist `~/.config/ohpichamber`.

### `OPENCHAMBER_CHATS_DIR`

Verschiebt die verwalteten Chat-Verzeichnisse, die OhPiChamber für Chats ohne Projekt anlegt. Standard ist `~/.config/ohpichamber/chats`. Bestehende Chats werden nicht verschoben.

### `OPENCHAMBER_COMPRESS_API`

Steuert die Komprimierung von API-Antworten. Verwende `true` oder `1`, um sie zu erzwingen, und `false` oder `0`, um sie zu deaktivieren.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Deaktiviert die Komprimierung von API-Antworten, wenn auf `true` oder `1` gesetzt. Das hat Vorrang vor `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Aktiviert ausführliche HTTP-Request-Logs, wenn auf `true` oder `1` gesetzt.

## Proxy

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Leitet die eigenen ausgehenden Anfragen von OhPiChamber, etwa Nutzungslimits und Skill-Kataloge, über einen Proxy. Kleingeschriebene Namen funktionieren ebenfalls. Hosts in `NO_PROXY` verbinden sich direkt, `localhost`, `127.0.0.1` und `::1` immer, sodass Anmelde-Callbacks und lokale Verbindungen weiter funktionieren.

## Terminal und Git

### `OPENCHAMBER_TERMINAL_SHELL`

Shell-Executable, die OhPiChamber für Terminal-Sessions verwendet.

### `OPENCHAMBER_GIT_BINARY`

Git-Executable, die OhPiChamber-Git-Funktionen verwenden.

### `GIT_BINARY`

Alternative Git-Executable-Überschreibung. Bevorzuge `OPENCHAMBER_GIT_BINARY` für OhPiChamber-spezifische Konfiguration.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Lebensdauer in Millisekunden für zwischengespeicherte Git-gestützte Dateilesevorgänge. Setze `0`, um diesen Cache beim Debuggen zu deaktivieren.

## Voice und Tunnels

### `OPENAI_API_KEY`

API-Schlüssel, den OhPiChamber-Voice-Funktionen verwenden, wenn sie OpenAI selbst aufrufen. An einen eigenen OpenAI-kompatiblen Server wird er nie gesendet: Gib diesem Server in den Einstellungen einen eigenen Schlüssel.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Erlaubt entfernte OpenAI-kompatible Basis-URLs für Voice-Funktionen, wenn auf `true` oder `1` gesetzt.

### `NGROK_AUTHTOKEN`

ngrok-Auth-Token, den OhPiChamber-Tunnel-Befehle verwenden. Du kannst ngrok auch mit `ngrok config add-authtoken <token>` konfigurieren.

## Laufzeit-Helfer

### `BUN_BINARY`

Bun-Executable, die OhPiChamber beim Starten von Daemon-Prozessen verwenden soll.

### `BUN_INSTALL`

Installationswurzel von Bun. OhPiChamber verwendet sie, um `bin/bun` für Daemon-Start und Updates zu finden.
