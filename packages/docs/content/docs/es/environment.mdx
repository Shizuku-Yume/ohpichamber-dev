# Variables de entorno

OhPiChamber lee estas variables al arrancar. Para servicios de inicio, `ohpichamber startup enable` guarda por defecto una copia del entorno actual, así que vuelve a ejecutarlo después de cambiar variables que quieras usar en el servicio.

## Variables para sesiones de agentes, Git y la terminal

Para darles a las sesiones de agentes, a Git, a la terminal y a las [acciones de proyecto](/es/project-actions/) variables propias, como un token de API o la dirección de una base de datos, añádelas en **Configuración → General → Variables de entorno** en lugar de exportarlas antes de arrancar OhPiChamber. Los valores se quedan en la máquina donde se ejecuta OhPiChamber, en `environment.json` dentro del directorio de datos, y solo tu usuario puede leerlos. Configuración nunca vuelve a mostrar un valor: puedes sustituirlo o quitarlo, pero no leerlo.

- Las sesiones de agentes las reciben al arrancar.
- Git, la terminal y las acciones de proyecto las reciben la próxima vez que se ejecutan.

Un proyecto puede añadir sus propias variables, o un comando que las imprima como `direnv export json`, en **Configuración → Proyectos**. Consulta [Proyectos](/es/projects/#entorno-del-proyecto).

Todo lo que sigue lo lee el propio OhPiChamber al arrancar.

## Servidor OhPiChamber

### `OPENCHAMBER_HOST`

Dirección donde escucha el servidor web de OhPiChamber. Usa `0.0.0.0` para permitir acceso desde otras máquinas.

### `OPENCHAMBER_LAN_URL`

La dirección con la que otros dispositivos de tu red llegan a OhPiChamber, por ejemplo `http://192.168.1.20:3000`. Los enlaces y códigos QR de emparejamiento la ofrecen en lugar de la que OhPiChamber detecta por sí mismo. Defínela cuando esa detección falle, por ejemplo en Docker, donde OhPiChamber solo ve la dirección interna del contenedor.

### `OPENCHAMBER_UI_PASSWORD`

Contraseña para la interfaz del navegador. Úsala cuando no te limites a localhost, o cuando uses túneles o un proxy inverso.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

Cuánto dura un inicio de sesión en el navegador, en horas, cuando «confiar en este dispositivo» está desactivado. El valor por defecto es `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

Cuánto dura un inicio de sesión, en días, en un dispositivo marcado como de confianza. El valor por defecto es `7`.

### `OPENCHAMBER_API_ONLY`

Inicia OhPiChamber en modo headless cuando vale `true` o `1`. Las rutas API siguen disponibles para clientes de escritorio y móviles, pero no se sirve la UI del navegador.

### `OPENCHAMBER_FRAME_ANCESTORS`

Orígenes que pueden mostrar OhPiChamber dentro de un frame en su propia página, separados por espacios, por ejemplo `https://dash.example.com`. `*` permite cualquier sitio. Por defecto solo OhPiChamber y sus apps de escritorio y móvil pueden incrustarlo, para que ningún otro sitio pueda superponer sus botones.

### `OPENCHAMBER_TRUSTED_PROXIES`

Direcciones de proxies inversos que se ejecutan en otra máquina o en otro contenedor, separadas por comas, como `192.168.1.10` o `172.18.0.0/16`. OhPiChamber limita los intentos de inicio de sesión fallidos por cliente y solo lee la dirección del cliente de `X-Forwarded-For` cuando la petición llega desde esta máquina o desde una dirección de esta lista. Un proxy que no está en la lista cuenta como un único cliente, así que los intentos fallidos de una persona pueden impedir durante un rato que todos los que están detrás inicien sesión.

### `OPENCHAMBER_DATA_DIR`

Cambia el directorio de datos de OhPiChamber. Por defecto es `~/.config/ohpichamber`.

### `OPENCHAMBER_CHATS_DIR`

Cambia la ubicación de los directorios de chat gestionados que OhPiChamber crea para chats sin proyecto. Por defecto es `~/.config/ohpichamber/chats`. Los chats existentes no se mueven.

### `OPENCHAMBER_COMPRESS_API`

Controla la compresión de respuestas de la API. `true` o `1` la activa; `false` o `0` la desactiva.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Desactiva la compresión de respuestas de la API si vale `true` o `1`. Tiene prioridad sobre `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Activa logs HTTP detallados si vale `true` o `1`.

## Proxy

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Envía a través de un proxy las solicitudes salientes propias de OhPiChamber, como los límites de uso y los catálogos de skills. También funcionan los nombres en minúsculas. Los hosts de `NO_PROXY` se conectan directamente, y `localhost`, `127.0.0.1` y `::1` siempre lo hacen, así que las devoluciones de inicio de sesión y las conexiones locales siguen funcionando.

## Terminal y Git

### `OPENCHAMBER_TERMINAL_SHELL`

Ejecutable de shell para las sesiones de terminal en OhPiChamber.

### `OPENCHAMBER_GIT_BINARY`

Ejecutable de Git usado por las funciones Git de OhPiChamber.

### `GIT_BINARY`

Override alternativo para el ejecutable de Git. Para ajustes específicos de OhPiChamber, prefiere `OPENCHAMBER_GIT_BINARY`.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

TTL, en milisegundos, para lecturas de archivos con cache respaldadas por Git. Usa `0` para desactivar la cache al depurar.

## Voz y túneles

### `OPENAI_API_KEY`

API key que usan las funciones de voz de OhPiChamber cuando llaman a OpenAI directamente. Nunca se envía a un servidor propio compatible con OpenAI: dale a ese servidor su propia clave en Ajustes.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Permite base URLs remotas compatibles con OpenAI para funciones de voz cuando vale `true` o `1`.

### `NGROK_AUTHTOKEN`

Token de autenticación de ngrok usado por los comandos de túnel de OhPiChamber. También puedes configurarlo con `ngrok config add-authtoken <token>`.

## Ayudas de runtime

### `BUN_BINARY`

Ejecutable de Bun que OhPiChamber debe usar al iniciar procesos daemon.

### `BUN_INSTALL`

Raíz de instalación de Bun. OhPiChamber la usa para encontrar `bin/bun` al iniciar daemons y actualizar.
