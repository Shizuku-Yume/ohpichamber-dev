# セキュリティ

OhPiChamber はあなたのマシンとコードへのアクセスを提供するため、あなた以外が到達できるようにする前に必ず保護してください。このページでは UI パスワード、パスキー、ネットワークに OhPiChamber を公開する前に知っておくべきことを説明します。

## UI パスワードを設定する

パスワード付きで OhPiChamber を起動すると、ブラウザ UI がそれを要求します。

```bash
ohpichamber --ui-password be-creative-here
```

コマンドラインに書く代わりに、`OPENCHAMBER_UI_PASSWORD` 環境変数で設定することもできます。サインイン後、OhPiChamber はしばらくそのデバイスを記憶するため、毎回求められることはありません。

インスタンスが自分以外から到達可能な場合は、必ずパスワードを設定してください。特に [トンネル](/ja/tunnels/) や public internet 経由の場合は重要です。

## パスキー

パスワードを設定すると、より速くサインインするためにパスキー（Face ID、Touch ID、セキュリティキー）を追加できます。**Settings → OhPiChamber → Passkeys** で追加します。

パスキーは現在のパスワードに紐づきます。パスワードを変更または削除すると、保存済みパスキーは消去され、再追加が必要になります。

## デバイストークン

[デバイスを接続する](/ja/connect-devices/) でペアリングしたデバイスは、UI パスワードではなく、デバイスごとの専用トークンで認証します。ペアリングリンクは 1 回限りで、未使用なら期限切れになります。ペアリング済みのデバイスはすべて **Settings → Remote Instances → このサーバーに接続** に一覧表示され、いつでも無効化できます。外出先からの接続は [Private Relay](/ja/private-relay/) を経由します。リレーはエンドツーエンドで暗号化されており、通信内容を読むことはできません。

## 公開する前に

- デフォルトでは、OhPiChamber はあなたのマシン上（`127.0.0.1`）でのみ待ち受けます。より広く待ち受けるには明示的な変更が必要で、その前にパスワードを設定するべきです。
- 自分のデバイスなら、[Private Relay](/ja/private-relay/) を使った [ペアリング](/ja/connect-devices/) を推奨します。何も公開されません。
- 公開 URL が必要な場合は、インターネットにポートを開けるより、[トンネル](/ja/tunnels/) または VPN のようなプライベートネットワークを推奨します。
- OhPiChamber を自分の HTTPS サーバーの背後に置く場合は、[リバースプロキシ](/ja/reverse-proxy/) を参照してください。

## エンタープライズモード

チームが会話の内容を Host で設定したモデルプロバイダーにしか送れない場合は、エンタープライズモードをオンにします。方法は 2 つあり、どちらか一方で十分です。

### マシン上のポリシーファイル

管理しているノート PC ではこちらを使います。管理者だけが書き込めるフォルダーに `policy.json` という名前のファイルを置きます。

| システム | パス |
|---|---|
| macOS | `/Library/Application Support/OpenChamber/policy.json` |
| Windows | `C:\ProgramData\OpenChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

パスは OhPiChamber のインストール方法に関係ありません。デスクトップアプリ、npm から起動した Web サーバー、CLI はすべて同じファイルを読みます。配布にはデバイス管理ツール（Jamf、Intune など）を使えます。Docker で動かすサーバーでは、Linux のパスにファイルをマウントしてください。

```json
{
  "enterpriseMode": true,
  "organization": "Acme",
  "relayUrl": "wss://relay.acme.com/ws",
  "allowNetworkAccess": false,
  "allowedExtensions": ["https://github.com/acme/"],
  "jev": {
    "url": "https://llm.acme.com/v1/systemone",
    "model": "acme-classifier",
    "apiKey": "..."
  }
}
```

必須なのは `enterpriseMode` だけです。`organization` は設定に「Acme が管理しています。」と表示され、誰が決めたのかがわかります。`relayUrl` と `jev` は自前のリレーと自前の Jev エンドポイントを固定し、`allowNetworkAccess` はほかのデバイスがネットワーク経由で OhPiChamber にアクセスできるようにし、`allowedExtensions` は信頼する拡張機能のリポジトリを列挙します。いずれも後述します。

- ユーザーが設定や環境で何を指定しても、ファイルでオンにしたものはオフになりません。
- ファイルでエンタープライズモードをオンにした場合、決めるのはファイルだけです。後述のリレー、Jev、ネットワークアクセス用の環境変数は無視されます。これらはユーザーが自分で設定できるためです。
- ファイルがあるのに読み込めない、または JSON として正しくない場合、エンタープライズモードはオンのままで、何も固定されません。設定には、ポリシーを読み込めなかったことが表示されます。壊れたファイルが知らないうちに保護を外すことはありません。
- 変更は再起動なしで反映されます。
- OhPiChamber はユーザーの権限で動くため、ユーザーはこのファイルを読めます。API キーを書き込む前に、この点を考慮してください。

### 環境変数

環境を自分で管理できるサーバーやコンテナーなら、これで十分です。

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

ノート PC ではロックとして弱くなります。デスクトップアプリはこの変数をログインシェルのプロファイル（例：`~/.zshrc`）から読み込みますが、そのファイルはユーザーが編集できます。ノート PC ではポリシーファイルを使ってください。

この変数を使う場合、リレー、Jev、ネットワークアクセス、許可する拡張機能もそれぞれの変数（`OPENCHAMBER_RELAY_URL`、`OPENCHAMBER_JEV_URL`、`OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`、`OPENCHAMBER_ALLOWED_EXTENSIONS`、`OPENCHAMBER_ALLOW_LOCAL_EXTENSIONS=1`）で指定します。`OPENCHAMBER_ALLOWED_EXTENSIONS` にはリポジトリの URL をカンマ区切りで並べます。Docker ではサーバーがコンテナーの外に向けて待ち受ける必要があるため、ネットワークアクセスの変数が必要です。

### 組み込みのスキルカタログを隠す

OhPiChamber にはいくつかの公開スキルカタログ (Anthropic、OpenAI、Cursor、Matt Pocock) が付属しています。組織で独自のカタログを管理している場合は、カスタムカタログとして追加し、ポリシーファイルで組み込みのものを隠してください。エンタープライズモードの有無にかかわらず機能します。

```json
{
  "hideBuiltinSkillCatalogs": true
}
```

設定には利用者が自分で追加したカタログだけが表示され、直接要求されても OhPiChamber は組み込みのカタログを読み込みません。ユーザーが自分で設定できるため、これに対応する環境変数はありません。

### 例

Mac にポリシーファイルを置くには、ターミナルで管理者として次を実行します。

```bash
sudo mkdir -p "/Library/Application Support/OpenChamber"
sudo tee "/Library/Application Support/OpenChamber/policy.json" > /dev/null <<'JSON'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
JSON
```

Linux でも同じで、フォルダーは `/etc/openchamber` です。

Windows では、PowerShell を管理者として実行します。最後の行で、フォルダーに書き込めるのを管理者とシステムだけにします。

```powershell
New-Item -ItemType Directory -Force "C:\ProgramData\OpenChamber" | Out-Null
@'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
'@ | Set-Content -Encoding UTF8 "C:\ProgramData\OpenChamber\policy.json"
icacls "C:\ProgramData\OpenChamber" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Users:(OI)(CI)RX"
```

Docker で動かすサーバーでは、`docker-compose.yml` の `environment` に追加します。コンテナーは自身の外に向けて待ち受けるため、ネットワークアクセスの許可が必要です。

```yaml
environment:
  OPENCHAMBER_UI_PASSWORD: ${OPENCHAMBER_UI_PASSWORD}
  OPENCHAMBER_ENTERPRISE_MODE: "1"
  OPENCHAMBER_ALLOW_NETWORK_ACCESS: "1"
  # Optional:
  OPENCHAMBER_RELAY_URL: wss://relay.acme.com/ws
  OPENCHAMBER_JEV_URL: https://llm.acme.com/v1/systemone
  OPENCHAMBER_JEV_MODEL: acme-classifier
  OPENCHAMBER_JEV_API_KEY: ${ACME_JEV_KEY}
  OPENCHAMBER_ALLOWED_EXTENSIONS: https://github.com/acme/
```

うまくいったか確かめるには、設定 → プロバイダーを開きます。上部に、組織名の入ったエンタープライズモードの通知が表示されます。

### 変わること

- モデルプロバイダーと認証情報の管理は Host が行います。エンタープライズモードでは、プロバイダーの追加操作（プロバイダーの接続、カスタムプロバイダーやモデルの設定、認証情報の書き込み、モデル検出、OAuth の開始）は Host によって拒否されます。既存のアカウントの削除や切り替えは引き続き可能です。セッションまたはワークスペースに設定された MCP サーバーはモデルプロバイダーではなくそのサーバーに接続するため、引き続き動作します。エンタープライズモードがオンの間は、明示的な認証情報ハンドオフのプリフライトも Host により拒否され、認証情報の読み取りやインポートは行われません。
- モデル情報の自動入力は、エンタープライズモードでは OpenRouter に到達しません。リクエストはもともとモデル ID だけを送信し、モードがオンのときは拒否されるため、自動入力はアプリに同梱のカタログから応答し、そのカタログにないモデルは空のフィールドのままになります。
- MCP サーバーへのサインインは行われません。MCP サインインの開始と、それを完了させるブラウザのコールバックは Host によって拒否されます（`403 enterprise_mode`）。サインイン不要のサーバー（環境変数の値を受け取るローカルサーバーを含む）は影響を受けません。
- Host はネットワーク送信時にネイティブの Web 検索を拒否し、検索認証情報の追加や置き換えも拒否します。検索設定の変更や保存済み認証情報の削除は引き続きできます。キーは書き込み専用で、返されることはありません。
- [分類プロバイダー（Jev）](/classification-providers/)はオフのままで、誰かが設定で入力したカスタムエンドポイントも同様です。セーフティネットと Auto は表示されず、セッションは手動で移したときだけ作業中になります。自社のインフラ経由で Jev を使うには、ポリシーファイルの `jev`、または `OPENCHAMBER_JEV_URL`（加えて `OPENCHAMBER_JEV_MODEL`、必要なら `OPENCHAMBER_JEV_API_KEY`）でエンドポイントを固定します。それが既定になり、オフにはできますが、ほかのものは選べません。
- OpenAI による読み上げはオフになります。カスタムの音声合成サーバーや文字起こしサーバーは、同じマシン上で動かす必要があります。ローカルの音声とローカルの音声入力モデルはそのまま使えます。
- スマートフォンやブラウザへのプッシュ通知には「Agent response is ready」のような汎用のタイトルだけが入り、メッセージ本文やセッション名は含まれません。デスクトップ通知はあなたのマシンの中にとどまり、全文を表示します。
- 更新の確認は引き続き行われるため、セキュリティ修正は届きます。ただし利用状況は一切報告せず、匿名のインストール ID すら送りません。
- [外部トンネル](/ja/tunnels/)（Cloudflare、ngrok、Tailscale）はオフになります。Cloudflare と ngrok はエッジで通信を復号するため、すべてのリクエストを平文で見られます。Tailscale Serve と Funnel はこのマシンをほかのデバイスに開きます。
- `.drawio` のダイアグラムは XML テキストとして開きます。ダイアグラムエディターは diagrams.net のページで、そこで開くとファイルがそのページに渡されるためです。
- サイドバーの連携カタログは非表示になります。OhPiChamber に同梱されたリストから外部サービスをインストールするためです。設定から MCP サーバー、プラグイン、スキルを追加する操作はこれまでどおり使えます。
- 公開 CDN から読み込むインターフェース用・コード用フォントは、システムフォントに置き換わります。選択はモードがオフになったときのために保持されます。

- マシンの外にデータを送れる[拡張機能](/ja/extensions/)（外部の API と通信するもの、外部のアドレスから読み込むもの、バックグラウンドサービスを動かすもの、セッションでのエージェントの発言をそのサービスに送るもの、OpenCode からセッションを読み取るもの、セッションを開始するもの、エージェントの権限リクエストに応答するもの、指示を追加するもの、エージェント向けのスキルを同梱するもの、OpenCode プラグインを同梱するもの（OpenCode 自体の中で動くコード））は、`allowedExtensions` に載っている Git リポジトリからしかインストールできません。許可された拡張機能のうち通知を届けるものは、スマートフォンと同じく汎用的なタイトルだけを受け取り、メッセージ本文、セッション名、プロジェクトは含まれません。許可された拡張機能のうちトラッカーとして動作するものは、あなたの検索と開いたアイテムの識別子を受け取り、投稿するセッションコメントには固定のラベルとセッションへのリンクだけが含まれ、セッションで話された内容は含まれません。許可された拡張機能のうち使用量を報告するものは、マニフェストに列挙され、ダイアログであなたが承認したプロバイダーについて OpenCode が保持する認証情報を受け取り、セッションからは何も受け取りません。どれにも当てはまらない拡張機能は通常どおりインストールできます。ほかの場所からインストールされた拡張機能はオフのままになり、設定にその理由が表示されます。拡張機能は自分で名前を決められるため、リストにはリポジトリの URL を書きます。`https://github.com/acme/` のように `/` で終わるエントリーは、その下にあるすべてのリポジトリを許可します。拡張機能を開発する人のマシンでは、`"allowLocalExtensions": true` にするとローカルフォルダーからのインストールも許可されます。ZIP はどちらの場合もインストールできません。
- **設定 → 一般** と `opencode service set env` の環境変数は、プロバイダーのキーが含まれている可能性があるため OpenCode には渡りません。Git、ターミナル、プロジェクトアクションには引き続き渡ります。
- VS Code 拡張機能では、プロバイダーの接続がオフになり、更新の確認は利用状況を報告しません。Jev、リレー、トンネル、プッシュ通知、クラウドの音声機能はもともとありません。

小さなモデルのタスク（セッションのタイトル、要約、コミットメッセージ、変更のウォークスルー）に特別なモードは必要ありません。常に、設定で選んだ小さなモデル、作業中のプロバイダーの小さなモデル、または Host で設定されたデフォルトモデルのいずれかで動きます。たまたま接続している別のプロバイダーに切り替わることはありません。
