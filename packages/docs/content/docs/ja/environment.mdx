# 環境変数

OpenChamber は起動時にこれらの環境変数を読み取ります。スタートアップサービスでは、`openchamber startup enable` がデフォルトで現在の環境をスナップショットするため、サービスに使わせたい変数を変更した後は再実行してください。

## エージェントセッション、Git、ターミナル用の変数

エージェントセッション、Git、ターミナル、[プロジェクトアクション](/ja/project-actions/) に独自の変数（API トークンやデータベースアドレスなど）を渡すには、OpenChamber を起動する前に export するのではなく、**設定 → 一般 → 環境変数** に追加します。値は OpenChamber を実行しているマシンのデータディレクトリ内にある `environment.json` に保存され、あなたのユーザーのみが読み取れます。設定画面では一度保存した値を再表示しません。置き換えや削除はできますが、再読み取りはできません。

- エージェントセッションは起動時にこれらを受け取ります。
- Git、ターミナル、プロジェクトアクションは次回の実行時にこれらを受け取ります。

プロジェクトごとの変数や、`direnv export json` のように変数を出力するコマンドは、**設定 → プロジェクト** で追加できます。[プロジェクト](/ja/projects/#プロジェクトの環境)を参照してください。

以下はすべて、OpenChamber 自体が起動時に読み取るものです。

## OpenChamber サーバー

### `OPENCHAMBER_HOST`

OpenChamber Web サーバーのバインドアドレスです。他のマシンからアクセスできるようにするには `0.0.0.0` を使います。

### `OPENCHAMBER_LAN_URL`

ネットワーク上の他のデバイスが OpenChamber に接続するためのアドレスです（例: `http://192.168.1.20:3000`）。ペアリングリンクと QR コードは、OpenChamber が自分で検出したアドレスの代わりにこれを使います。検出が間違う場合に設定してください。たとえば Docker では、OpenChamber にはコンテナ内部のアドレスしか見えません。

### `OPENCHAMBER_UI_PASSWORD`

ブラウザ UI のパスワードです。localhost 以外にバインドする場合、トンネルを使う場合、またはリバースプロキシの背後で実行する場合に使います。

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

「このデバイスを信頼する」がオフのときのブラウザのサインイン有効期間（時間）です。既定値は `12` です。

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

信頼したデバイスでのサインイン有効期間（日）です。既定値は `7` です。

### `OPENCHAMBER_API_ONLY`

`true` または `1` に設定すると、OpenChamber をヘッドレスモードで起動します。デスクトップおよびモバイルクライアント向けの API ルートは利用できますが、ブラウザ UI は配信されません。

### `OPENCHAMBER_FRAME_ANCESTORS`

自分のページのフレーム内に OpenChamber を表示できるオリジンをスペース区切りで指定します（例: `https://dash.example.com`）。`*` はすべてのサイトを許可します。既定では OpenChamber 自身とそのデスクトップ・モバイルアプリだけが埋め込めるため、他のサイトがボタンの上に重ねることはできません。

### `OPENCHAMBER_DATA_DIR`

OpenChamber のデータディレクトリを上書きします。デフォルトは `~/.config/openchamber` です。

OpenChamber が保存するものはすべてこのディレクトリ配下にあります: 設定、認証、プロジェクト設定、テーマ、プラン、音声モデル。バージョン 1.23 より前にカスタムディレクトリを使っていたインスタンスでは、初回起動時に `projects`、`themes`、`speech-models` フォルダーが `~/.config/openchamber` からここへコピーされます。元のフォルダーはそのまま残り、マージはされません。

### `OPENCHAMBER_CHATS_DIR`

プロジェクトのないチャット用に OpenChamber が作成する管理チャットディレクトリの場所を変更します。デフォルトは `~/.config/openchamber/chats` です。既存のチャットは移動されません。

### `OPENCHAMBER_COMPRESS_API`

API レスポンス圧縮を制御します。`true` または `1` で強制的に有効化し、`false` または `0` で強制的に無効化します。

### `OPENCHAMBER_SKIP_API_COMPRESSION`

`true` または `1` に設定すると API レスポンス圧縮を無効化します。これは `OPENCHAMBER_COMPRESS_API` より優先されます。

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

`true` または `1` に設定すると詳細な HTTP リクエストログを有効にします。

### `OPENCHAMBER_UPDATE_API_URL`

更新確認 API エンドポイントを上書きします。ほとんどのユーザーは未設定のままでかまいません。

### `OPENCHAMBER_PACKAGE_MANAGER`

自動検出が間違っている場合に、更新操作で使うパッケージマネージャーを強制します。

## プロキシ

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

利用上限やスキルカタログなど、OpenChamber 自身が送るリクエストをプロキシ経由にします。小文字の変数名も使えます。`NO_PROXY` のホストは直接接続し、`localhost`、`127.0.0.1`、`::1` は常に直接接続するため、サインインのコールバックやローカル接続はそのまま動作します。

## ターミナルと Git

### `OPENCHAMBER_TERMINAL_SHELL`

OpenChamber のターミナルセッションで使うシェル実行ファイルです。

### `OPENCHAMBER_GIT_BINARY`

OpenChamber の Git 機能で使う Git 実行ファイルです。

### `GIT_BINARY`

代替の Git 実行ファイル上書きです。OpenChamber 固有の設定には `OPENCHAMBER_GIT_BINARY` を推奨します。

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Git に基づくファイル読み取りキャッシュの有効期間（ミリ秒）です。デバッグ中にこのキャッシュを無効化するには `0` を設定します。

## 音声とトンネル

### `OPENAI_API_KEY`

OpenChamber の音声機能が OpenAI 本体を呼び出すときに使う API キーです。カスタムの OpenAI 互換サーバーには送信されません。そのサーバーには設定で専用のキーを指定してください。

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

`true` または `1` に設定すると、音声機能でリモートの OpenAI 互換 base URL を許可します。

### `NGROK_AUTHTOKEN`

OpenChamber のトンネルコマンドで使う ngrok 認証トークンです。`ngrok config add-authtoken <token>` で ngrok 側に設定することもできます。

## ランタイムヘルパー

### `BUN_BINARY`

デーモンプロセスを起動するときに OpenChamber が使う Bun 実行ファイルです。

### `BUN_INSTALL`

Bun のインストールルートです。OpenChamber はデーモン起動と更新のために `bin/bun` を探す際に使います。
