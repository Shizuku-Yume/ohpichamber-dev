# Безпека

OhPiChamber дає доступ до вашої машини та вашого коду, тож заблокуйте його, перш ніж до нього зможе дістатися хтось, окрім вас. Ця сторінка охоплює пароль UI, ключі доступу (passkeys) і те, що треба знати перед тим, як відкривати OhPiChamber у мережі.

## Установлення пароля UI

Запустіть OhPiChamber із паролем, і браузерний UI запитуватиме його:

```bash
ohpichamber --ui-password be-creative-here
```

Ви також можете задати його через змінну середовища `OPENCHAMBER_UI_PASSWORD` замість того, щоб писати його в командному рядку. Після входу OhPiChamber на деякий час запам'ятовує пристрій, тож вас не питатимуть щоразу.

Завжди задавайте пароль, якщо інстанс доступний комусь іще — особливо через [тунель](/uk/tunnels/) чи публічний інтернет.

## Ключі доступу (passkeys)

Щойно задано пароль, ви можете додати ключі доступу (Face ID, Touch ID, апаратний ключ безпеки) для швидшого входу. Додайте їх у **Settings → OhPiChamber → Passkeys**.

Ключі доступу прив'язані до поточного пароля. Якщо ви зміните чи приберете пароль, збережені ключі доступу очищаються, і вам доведеться додати їх знову.

## Токени пристроїв

Пристрої, зв'язані через [Підключення пристрою](/uk/connect-devices/), автентифікуються власними токенами для кожного пристрою, а не паролем UI. Посилання для зв'язування одноразові й спливають, якщо не використані; кожен зв'язаний пристрій показано в **Settings → Remote Instances → Підключення до цього сервера**, де будь-який можна відкликати в будь-який момент. Підключення поза домом ідуть через [Private Relay](/uk/private-relay/), який наскрізно зашифрований і не може прочитати ваш трафік.

## Перш ніж відкривати доступ

- За замовчуванням OhPiChamber слухає лише вашу власну машину (`127.0.0.1`). Щоб слухати ширше, потрібна свідома зміна, і спершу вам слід задати пароль.
- Для власних пристроїв надавайте перевагу [зв'язуванню](/uk/connect-devices/) з [Private Relay](/uk/private-relay/) — назовні взагалі нічого не відкривається.
- Якщо потрібен публічний URL, надавайте перевагу [тунелю](/uk/tunnels/) чи приватній мережі (як-от VPN) перед відкриттям порту в інтернет.
- Якщо ви ставите OhPiChamber за власним HTTPS-сервером, див. [Зворотний проксі](/uk/reverse-proxy/).

## Корпоративний режим

Якщо ваша команда може надсилати вміст розмов лише тим провайдерам моделей, які налаштовані в Host, увімкніть корпоративний режим. Для цього є два способи, і будь-якого з них достатньо.

### Файл політики на машині

Цей спосіб для ноутбуків, якими ви керуєте. Покладіть файл `policy.json` у теку, куди може писати лише адміністратор:

| Система | Шлях |
|---|---|
| macOS | `/Library/Application Support/OhPiChamber/policy.json` |
| Windows | `C:\ProgramData\OhPiChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

Шлях не залежить від того, як встановлено OhPiChamber. Десктопний застосунок, вебсервер, запущений із npm, і CLI читають той самий файл. Розгорнути його можна через систему керування пристроями (Jamf, Intune тощо). Для сервера в Docker змонтуйте файл за шляхом для Linux.

```json
{
  "enterpriseMode": true,
  "organization": "Acme",
  "relayUrl": "wss://relay.acme.com/ws",
  "allowNetworkAccess": false,
  "allowedExtensions": ["https://github.com/acme/"],
  "jev": {
    "url": "https://llm.acme.com/v1/systemone",
    "model": "acme-classifier",
    "apiKey": "..."
  }
}
```

Обов'язкове лише `enterpriseMode`. `organization` показується в Налаштуваннях як "Керує Acme", щоб люди знали, хто ухвалив це рішення. `relayUrl` і `jev` закріплюють ваш власний relay і ваш власний endpoint Jev, `allowNetworkAccess` дає іншим пристроям доступ до OhPiChamber через мережу, а `allowedExtensions` перелічує репозиторії розширень, яким ви довіряєте. Про всі них нижче.

- Ніщо, що задає користувач, ні в Налаштуваннях, ні в середовищі, не вимикає того, що вмикає файл.
- Коли файл вмикає корпоративний режим, вирішує лише файл. Змінні середовища для relay, Jev і мережевого доступу, описані нижче, ігноруються, бо користувач може задати їх сам.
- Якщо файл є, але його не вдається прочитати або це не коректний JSON, корпоративний режим лишається увімкненим і нічого не закріплюється. Налаштування повідомляють, що політику не вдалося прочитати. Зламаний файл ніколи тихо не знімає захист.
- Зміни застосовуються без перезапуску.
- OhPiChamber працює від імені користувача, тож користувач може прочитати файл. Пам'ятайте про це, перш ніж класти туди API-ключ.

### Змінна середовища

На сервері чи в контейнері, де середовище контролюєте ви, достатньо цього:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

На ноутбуці це слабший замок: десктопний застосунок читає змінну з профілю login shell (наприклад, `~/.zshrc`), а його користувач може редагувати. Там використовуйте файл політики.

Зі змінною relay, Jev, мережевий доступ і дозволені розширення теж беруться з власних змінних: `OPENCHAMBER_RELAY_URL`, `OPENCHAMBER_JEV_URL`, `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`, `OPENCHAMBER_ALLOWED_EXTENSIONS` (URL репозиторіїв через кому) і `OPENCHAMBER_ALLOW_LOCAL_EXTENSIONS=1`. У Docker вам знадобиться та, що для мережевого доступу, бо сервер має слухати за межами контейнера.

### Сховати вбудовані каталоги скілів

OhPiChamber постачається з кількома публічними каталогами скілів (Anthropic, OpenAI, Cursor, Matt Pocock). Якщо у вашої організації є власний, додайте його як власний каталог і сховайте вбудовані у файлі політики. Це працює як з корпоративним режимом, так і без нього.

```json
{
  "hideBuiltinSkillCatalogs": true
}
```

Тоді налаштування пропонують лише каталоги, які люди додали самі, а OhPiChamber не завантажить вбудований навіть на прямий запит. Змінної середовища для цього немає, бо користувач може задати її сам.

### Приклади

Щоб покласти файл політики на Mac, виконайте в Terminal від імені адміністратора:

```bash
sudo mkdir -p "/Library/Application Support/OhPiChamber"
sudo tee "/Library/Application Support/OhPiChamber/policy.json" > /dev/null <<'JSON'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
JSON
```

У Linux так само, лише папка `/etc/openchamber`.

У Windows запустіть PowerShell від імені адміністратора. Останній рядок залишає право запису в папку лише адміністраторам і системі:

```powershell
New-Item -ItemType Directory -Force "C:\ProgramData\OhPiChamber" | Out-Null
@'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
'@ | Set-Content -Encoding UTF8 "C:\ProgramData\OhPiChamber\policy.json"
icacls "C:\ProgramData\OhPiChamber" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Users:(OI)(CI)RX"
```

Для сервера в Docker додайте це в `environment` у `docker-compose.yml`. Контейнер слухає за своїми межами, тож йому потрібен дозволений мережевий доступ:

```yaml
environment:
  OPENCHAMBER_UI_PASSWORD: ${OPENCHAMBER_UI_PASSWORD}
  OPENCHAMBER_ENTERPRISE_MODE: "1"
  OPENCHAMBER_ALLOW_NETWORK_ACCESS: "1"
  # Optional:
  OPENCHAMBER_RELAY_URL: wss://relay.acme.com/ws
  OPENCHAMBER_JEV_URL: https://llm.acme.com/v1/systemone
  OPENCHAMBER_JEV_MODEL: acme-classifier
  OPENCHAMBER_JEV_API_KEY: ${ACME_JEV_KEY}
  OPENCHAMBER_ALLOWED_EXTENSIONS: https://github.com/acme/
```

Щоб перевірити, що все спрацювало, відкрийте Налаштування → Провайдери: угорі з'явиться повідомлення про корпоративний режим із назвою вашої організації.

### Що змінюється

- Керування провайдерами моделей та обліковими даними належить Host. У корпоративному режимі операції додавання провайдерів — підключення провайдера, додавання чи налаштування користувацьких провайдерів або моделей, запис облікових даних, пошук моделей чи запуск OAuth — відхиляються Host; видаляти чи перемикати вже наявні облікові записи можна й далі. MCP-сервери, налаштовані для сесії або робочого простору, продовжують працювати, бо вони підключаються до цього сервера, а не до провайдера моделей. Явний preflight передачі облікових даних також відхиляється Host, поки увімкнено корпоративний режим; жодні облікові дані не зчитуються й не імпортуються.
- Заповнення відомостей про моделі ніколи не досягає OpenRouter у корпоративному режимі. Запит і так містить лише ідентифікатори моделей; увімкнений режим відхиляє його, тож автозаповнення відповідає з каталогу, що постачається з застосунком, а моделі, яких цей каталог не знає, зберігають порожні поля.
- Вхід у MCP-сервер лишається вимкненим. Host відхиляє запуск входу MCP і браузерний callback, що його завершує (`403 enterprise_mode`). Сервери, які не потребують входу, зокрема локальні, що приймають значення середовища, працюють як і раніше.
- Host блокує нативний вебпошук на межі вихідного мережевого трафіку, а також додавання чи заміну облікових даних пошуку. Налаштування пошуку можна й далі змінювати, а збережені облікові дані — видаляти; ключі доступні лише для запису й ніколи не повертаються.
- [Постачальники класифікації (Jev)](/uk/classification-providers/) лишаються вимкненими, зокрема й власний endpoint, який хтось вводить у Налаштуваннях. Запобіжник і Auto не пропонуються, а сесії потрапляють у роботу лише вручну. Щоб користуватися Jev через власну інфраструктуру, закріпіть endpoint через `jev` у файлі політики або через `OPENCHAMBER_JEV_URL` (плюс `OPENCHAMBER_JEV_MODEL` і, якщо потрібно, `OPENCHAMBER_JEV_API_KEY`). Він стає типовим, його все одно можна вимкнути, а нічого іншого вибрати не можна.
- Зачитування вголос через OpenAI вимкнене. Власний сервер синтезу чи розпізнавання мовлення має працювати на тій самій машині. Локальні голоси й локальні моделі диктування працюють і далі.
- Push-сповіщення на телефони й у браузери містять лише загальний заголовок на кшталт "Agent response is ready", без тексту повідомлення чи назви сесії. Сповіщення на десктопі лишаються на вашій машині й містять повний текст.
- Перевірка оновлень працює й далі, тож виправлення безпеки до вас доходять, але вона ніколи не звітує про використання, навіть анонімним ідентифікатором встановлення.
- [Зовнішні тунелі](/uk/tunnels/) (Cloudflare, ngrok, Tailscale) вимкнені. Cloudflare і ngrok розшифровують трафік на своєму боці й бачать кожен запит відкритим текстом; Tailscale Serve і Funnel відкривають цей комп'ютер іншим пристроям.
- Діаграми `.drawio` відкриваються як XML-текст. Редактор діаграм — це сторінка diagrams.net, і відкрита там діаграма передається цій сторінці.
- Каталог інтеграцій у бічній панелі прихований. Він встановлює сторонні сервіси зі списку, що постачається разом з OhPiChamber. Додавання MCP-серверів, плагінів і скілів у налаштуваннях працює як і раніше.
- Шрифти інтерфейсу й коду, що завантажуються з публічного CDN, замінюються системними. Ваш вибір зберігається на випадок, коли режим вимкнуть.
- [Private Relay](/uk/private-relay/) працює лише через self-hosted relay, налаштований через `relayUrl` у файлі політики або `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws`. OhPiChamber не має вбудованого спільного relay (а віддалений push для iOS потребує `OPENCHAMBER_PUSH_RELAY_URL` або прямого налаштування APNs), тож власний relay тримає метадані з'єднань і шлях до цієї машини всередині вашої мережі. Без налаштованого URL relay зв'язати пристрої через relay неможливо.
- Сторінки, якими агент ділиться з іншими людьми через посилання й PIN, ідуть лише через ваш власний relay, заданий у `relayUrl` або `OPENCHAMBER_RELAY_URL`. Relay зберігає тільки зашифровані сторінку й відповідь, але посилання веде саме до нього. Без власного relay поширення не існує: агенту його не пропонують, а сервер відмовляє. Відкриття сторінок, якими поділилися з вами інші, працює так само: OhPiChamber відкриває лише посилання вашого власного relay, а без нього вставлене посилання лишається звичайним текстом.
- OhPiChamber слухає лише на машині, де він запущений. Десктопне налаштування, яке дає іншим пристроям у локальній мережі відкривати застосунок, вимкнене, а сервер відмовляється запускатися на мережевій адресі, хоч через CLI (`--host`, `--lan`), хоч через середовище. Якщо файл політики з'являється, поки застосунок працює, з'єднання з інших машин обриваються до наступного запуску. Дозвольте мережевий доступ через `"allowNetworkAccess": true` у файлі політики або через `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1` там, де корпоративний режим вмикає середовище. Пам'ятайте, що з'єднання йде звичайним HTTP, тож у спільній мережі його може прочитати будь-хто; сервер, до якого підключаються інші, ставте за [власний HTTPS](/uk/reverse-proxy/).
- [Розширення](/uk/extensions/), які можуть надсилати дані за межі машини (звертаються до зовнішнього API, завантажують щось із зовнішніх адрес, запускають фоновий сервіс, отримують у той сервіс те, що агент каже в сесіях, читають сесії з Host або запускають сесії, відповідають на запити дозволів агента, додають інструкції, постачають скіли для агентів), встановлюються лише з Git-репозиторію, указаного в `allowedExtensions`. Дозволене розширення, яке доставляє сповіщення, отримує лише загальний заголовок, без тексту повідомлення, назви сесії чи проєкту, так само як телефон. Дозволене розширення, яке працює як трекер, отримує ваші пошукові запити та ідентифікатори елементів, які ви відкриваєте, а коментарі сесій, які воно публікує, несуть сталу позначку й посилання на сесію, ніколи не те, що в ній було сказано. Дозволене розширення, яке звітує про використання, отримує облікові дані, які Host зберігає для провайдерів, перелічених у його маніфесті й схвалених вами в його діалозі, і нічого з ваших сесій. Розширення, які нічого з цього не роблять, встановлюються як завжди. Встановлене розширення з будь-якого іншого місця лишається вимкненим, і Налаштування пояснюють чому. У списку зазначають URL репозиторіїв, бо назву розширення обирає собі саме; запис, що закінчується на `/`, як-от `https://github.com/acme/`, дозволяє всі репозиторії під ним. На машинах тих, хто розробляє розширення, `"allowLocalExtensions": true` також дозволяє встановлення з локальної папки. ZIP лишається закритим у будь-якому разі.
- Змінні середовища з **Налаштування → Загальні** не доходять до OMP, бо в одній із них може бути ключ провайдера. Git, термінал і дії проєкту й далі їх отримують.

Задачі малої моделі (назви сесій, рекапи, повідомлення комітів, розбір змін) не потребують жодного спеціального режиму. Вони завжди працюють на малій моделі, яку ви вибрали в Налаштуваннях, або на малій моделі провайдера, з яким ви працюєте, або на моделі за замовчуванням, налаштованій у Host. Вони ніколи не перемикаються на якогось іншого провайдера, який у вас просто підключений.
