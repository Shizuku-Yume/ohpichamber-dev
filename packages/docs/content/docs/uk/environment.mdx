# Змінні середовища

OhPiChamber читає ці змінні під час запуску. Для startup-сервісів `ohpichamber startup enable` типово зберігає snapshot поточного середовища, тому після змін перезапустіть цю команду.

## Змінні для сесій агентів, Git і термінала

Щоб передати сесіям агентів, Git, терміналу та [діям проєкту](/uk/project-actions/) власні змінні, наприклад API-токен чи адресу бази даних, додайте їх у **Налаштування → Загальні → Змінні середовища**, а не експортуйте перед запуском OhPiChamber. Значення лишаються на машині, де працює OhPiChamber, у файлі `environment.json` у директорії даних, і прочитати його може лише ваш користувач. Налаштування більше ніколи не показують значення: його можна замінити або видалити, але не переглянути.

- Сесії агентів отримують їх під час запуску.
- Git, термінал і дії проєкту отримують їх під час наступного запуску.

Проєкт може додати власні змінні або команду, що їх виводить, наприклад `direnv export json`, у **Налаштування → Проєкти**. Див. [Проєкти](/uk/projects/#середовище-проєкту).

Усе, що нижче, OhPiChamber читає сам під час запуску.

## Сервер OhPiChamber

### `OPENCHAMBER_HOST`

Адреса, на якій слухає web-сервер OhPiChamber. Використовуйте `0.0.0.0`, щоб відкрити доступ з інших машин.

### `OPENCHAMBER_LAN_URL`

Адреса, за якою інші пристрої у вашій мережі дістаються до OhPiChamber, наприклад `http://192.168.1.20:3000`. Посилання і QR-коди для підключення пропонують її замість адреси, яку OhPiChamber визначає сам. Задайте її, коли це визначення хибне, наприклад у Docker, де OhPiChamber бачить лише внутрішню адресу контейнера.

### `OPENCHAMBER_UI_PASSWORD`

Пароль для browser UI. Використовуйте його для доступу не лише з localhost, тунелів або reverse proxy.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

Скільки годин діє вхід у браузері, якщо «довіряти цьому пристрою» вимкнено. За замовчуванням `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

Скільки днів діє вхід на пристрої, якому ви довіряєте. За замовчуванням `7`.

### `OPENCHAMBER_API_ONLY`

Запускає OhPiChamber у headless mode, якщо встановлено `true` або `1`. API routes залишаються доступними для desktop і mobile clients, але browser UI не віддається.

### `OPENCHAMBER_FRAME_ANCESTORS`

Origins, яким дозволено показувати OhPiChamber у фреймі на своїй сторінці, через пробіл, наприклад `https://dash.example.com`. `*` дозволяє будь-який сайт. Типово вбудовувати його можуть лише сам OhPiChamber і його desktop- та mobile-застосунки, тож інші сайти не можуть перекрити його кнопки.

### `OPENCHAMBER_TRUSTED_PROXIES`

Адреси зворотних проксі, що працюють на іншій машині чи в іншому контейнері, через кому, наприклад `192.168.1.10` або `172.18.0.0/16`. OhPiChamber обмежує невдалі спроби входу для кожного клієнта і читає адресу клієнта з `X-Forwarded-For` лише тоді, коли запит приходить із цієї машини або з адреси з цього списку. Проксі, якого немає в списку, вважається одним клієнтом, тож невдалі спроби однієї людини можуть на якийсь час не пустити всіх, хто за ним.

### `OPENCHAMBER_DATA_DIR`

Перевизначає директорію даних OhPiChamber. Типово це `~/.config/ohpichamber`.

### `OPENCHAMBER_CHATS_DIR`

Переносить директорії керованих чатів, які OhPiChamber створює для чатів без проєкту. Типово це `~/.config/ohpichamber/chats`. Наявні чати не переносяться.

### `OPENCHAMBER_COMPRESS_API`

Керує стисненням API-відповідей. `true` або `1` вмикає, `false` або `0` вимикає.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Вимикає стиснення API-відповідей, якщо встановлено `true` або `1`. Має пріоритет над `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Вмикає детальні HTTP request logs, якщо встановлено `true` або `1`.

## Проксі

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Спрямовує власні вихідні запити OhPiChamber, як-от ліміти використання та каталоги скілів, через проксі. Назви в нижньому регістрі теж працюють. Хости з `NO_PROXY` під'єднуються напряму, а `localhost`, `127.0.0.1` і `::1` — завжди, тож зворотні виклики входу та локальні з'єднання працюють як раніше.

## Terminal і Git

### `OPENCHAMBER_TERMINAL_SHELL`

Shell executable для terminal sessions в OhPiChamber.

### `OPENCHAMBER_GIT_BINARY`

Git executable для Git-функцій OhPiChamber.

### `GIT_BINARY`

Альтернативний override для Git executable. Для OhPiChamber-specific налаштувань краще використовуйте `OPENCHAMBER_GIT_BINARY`.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

TTL у мілісекундах для cached Git-backed file reads. Встановіть `0`, щоб вимкнути cache під час debugging.

## Voice і tunnels

### `OPENAI_API_KEY`

API key, яким голосові функції OhPiChamber користуються, коли звертаються до самого OpenAI. На власний OpenAI-сумісний сервер він ніколи не надсилається: дай цьому серверу окремий ключ у Налаштуваннях.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Дозволяє remote OpenAI-compatible base URLs для voice-функцій, якщо встановлено `true` або `1`.

### `NGROK_AUTHTOKEN`

ngrok auth token для tunnel-команд OhPiChamber. Також можна налаштувати ngrok через `ngrok config add-authtoken <token>`.

## Runtime helpers

### `BUN_BINARY`

Bun executable, який OhPiChamber має використовувати для запуску daemon processes.

### `BUN_INSTALL`

Корінь інсталяції Bun. OhPiChamber використовує його, щоб знайти `bin/bun` для daemon startup і updates.
