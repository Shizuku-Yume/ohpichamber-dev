# Провайдери, моделі та агенти

Перш ніж OpenChamber зможе щось робити, до нього треба підключити щонайменше одного AI-провайдера. Ця сторінка охоплює підключення провайдера, вибір моделі та налаштування агентів.

## Підключення провайдера

1. Відкрийте **Settings → Providers**.
2. Відкрийте меню **Add provider** й оберіть провайдера, який ще не підключений, або виберіть **Other / Custom** для кінцевої точки, сумісної з OpenAI.
3. Увійдіть способом, який вимагає провайдер:
   - **API key** — вставте свій ключ і збережіть.
   - **Вхід через OAuth** — відкрийте посилання авторизації у браузері, щоб увійти. Якщо буде запит, вставте код авторизації в OpenChamber і завершіть підключення.

### Користувацькі та інші провайдери

Для шлюзів, локальних LLM, Ollama, LiteLLM та схожих OpenAI-сумісних API:

1. Оберіть **Other / Custom** у списку провайдерів.
2. Введіть ідентифікатор провайдера, відображувану назву, базову URL-адресу (`http://` або `https://`), необов’язковий API-ключ та щонайменше один ідентифікатор і назву моделі.
3. Вкажіть вікно контексту та максимальну кількість вихідних токенів моделі. Додаткові метадані (як-от параметри міркування, варіанти та модальності) можна налаштувати у форматі JSON у деталях моделі.
4. За потреби додайте заголовки запитів.
5. Збережіть — OpenChamber реєструє провайдера й моделі через Agent Service, зберігаючи API-ключі як облікові дані лише для запису.
6. Щоб змінити наявного користувацького провайдера, відкрийте його й виберіть **Edit**.

API-ключ необов’язковий. Локальні точки без ключа (як-от Ollama, LiteLLM чи llama.cpp) та сервіси з автентифікацією через заголовки можна підключати без API-ключа.

Коли провайдер показано як підключений, його моделі стають доступними в чаті.

Щоб відключити, відкрийте провайдера й виберіть видалення його входу.

## Вибір моделі

Модель ви обираєте там, де працюєте:

- у чаті використовуйте перемикач моделей у рядку повідомлення, щоб задати провайдера й модель для цієї сесії
- для кожного агента задайте модель за замовчуванням (нижче)

## Налаштування агентів

Агент — це іменована конфігурація: модель, системний промпт та доступні йому інструменти.

1. Відкрийте **Settings → Agents**.
2. Оберіть агента або створіть нового.
3. Відредагуйте будь-що з:
   - **description** — для чого призначений агент
   - **model** — перевизначення провайдера та моделі за замовчуванням
   - **prompt** — системний промпт та постійні інструкції, яких він завжди дотримується
   - **allowed tools** — інструменти, доступні агенту (доступність інструментів: додавання інструментів до списку дозволяє моделі їх викликати, тоді як авторизація операцій контролюється політиками та схваленнями Host)
   - **permission preset** — необов'язковий ідентифікатор пресету дозволів для профілю

## Де зберігаються ваші входи

Облікові дані та входи провайдерів зберігаються у сховищі облікових даних сервісу Agent Service на сервері, що гарантує надійність та ізоляцію ключів. Для одного провайдера можна підключити кілька акаунтів та обрати активний акаунт за замовчуванням у списку акаунтів провайдера.
