# Environment Variables

OhPiChamber reads these environment variables at startup. For startup services, `ohpichamber startup enable` snapshots the current environment by default, so rerun it after changing variables you want the service to use. Variables OhPiChamber itself set in the shell you run it from, such as the desktop app's terminal or an agent's shell, stay out of the service; your own exports carry over from there too, unless you re-export a name OhPiChamber already set in that shell, which a regular terminal avoids.

## Variables for agent sessions, Git and the terminal

To give agent sessions, Git, the terminal and [project actions](/project-actions/) variables of your own, such as an API token or a database address, add them in **Settings → General → Environment variables** instead of exporting them before OhPiChamber starts. Values stay on the machine that runs OhPiChamber, in `environment.json` in the data directory, readable only by your user. Settings never shows a value again: you can replace or remove it, not read it back.

- Agent sessions receive them when started.
- Git, the terminal and project actions get them on their next run.

A project can add its own variables, or a command such as `direnv export json` that prints them, in **Settings → Projects**. See [Projects](/projects/#project-environment).

Everything below is read by OhPiChamber itself at startup.

## OhPiChamber server

### `OPENCHAMBER_HOST`

Bind address for the OhPiChamber web server. Use `0.0.0.0` to allow access from other machines.

### `OPENCHAMBER_LAN_URL`

The address other devices on your network use to reach OhPiChamber, such as `http://192.168.1.20:3000`. Pairing links and QR codes offer it instead of the address OhPiChamber detects itself. Set it when that guess is wrong, for example in Docker, where OhPiChamber only sees the container's internal address.

### `OPENCHAMBER_UI_PASSWORD`

Password for the browser UI. Use this when binding outside localhost, using tunnels, or running behind a reverse proxy.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

How long a browser sign-in lasts, in hours, when "trust this device" is off. The default is `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

How long a sign-in lasts, in days, on a device you chose to trust. The default is `7`.

### `OPENCODE_JWT_SECRET`

Overrides the secret used to sign Host UI session tokens. This setting configures Host session signing rather than the agent runtime. Keep this secret private. When set, global sign-out is unavailable because OhPiChamber cannot rotate the signing secret.

### `OPENCHAMBER_API_ONLY`

Starts OhPiChamber in headless mode when set to `true` or `1`. API routes stay available for desktop and mobile clients, but the browser UI is not served.

### `OPENCHAMBER_FRAME_ANCESTORS`

Origins allowed to show OhPiChamber inside a frame on their own page, separated by spaces, for example `https://dash.example.com`. `*` allows any site. By default only OhPiChamber itself and its desktop and mobile apps may frame it, which keeps other sites from overlaying its buttons.

### `OPENCHAMBER_TRUSTED_PROXIES`

Addresses of reverse proxies that run on another machine or in another container, separated by commas, such as `192.168.1.10` or `172.18.0.0/16`. OhPiChamber limits failed sign-in attempts per client and reads the client's address from `X-Forwarded-For` only when the request comes from this machine or from an address listed here. A proxy that isn't listed counts as one client, so one person's failed attempts can keep everyone behind it from signing in for a while.

### `OPENCHAMBER_DATA_DIR`

Overrides the OhPiChamber data directory. The default is `~/.config/ohpichamber`.

Everything OhPiChamber stores lives under this directory: settings, auth, project configs, themes, plans, and speech models. An instance that used a custom directory before version 1.23 gets its `projects`, `themes`, and `speech-models` folders copied from `~/.config/ohpichamber` on the first start; the originals stay in place and nothing is merged.

### `OPENCHAMBER_CHATS_DIR`

Moves the managed chat directories that OhPiChamber creates for chats without a project. The default is `~/.config/ohpichamber/chats`. Existing chats are not moved.

### `OPENCHAMBER_COMPRESS_API`

Controls API response compression. Use `true` or `1` to force it on, `false` or `0` to force it off.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Disables API response compression when set to `true` or `1`. This takes precedence over `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Enables verbose HTTP request logs when set to `true` or `1`.

## Proxy

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Sends OhPiChamber's own outgoing requests, such as usage limits and skill catalogs, through a proxy. Lowercase names work too. Hosts in `NO_PROXY` connect directly, and `localhost`, `127.0.0.1` and `::1` always do, so sign-in callbacks and local connections keep working.

## Terminal and Git

### `OPENCHAMBER_TERMINAL_SHELL`

Shell executable used for OhPiChamber terminal sessions.

### `OPENCHAMBER_GIT_BINARY`

Git executable used by OhPiChamber Git features.

### `GIT_BINARY`

Alternative Git executable override. Prefer `OPENCHAMBER_GIT_BINARY` for OhPiChamber-specific configuration.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Time-to-live, in milliseconds, for cached Git-backed file reads. Set `0` to disable this cache while debugging.

## Voice and tunnels

### `OPENAI_API_KEY`

API key OhPiChamber voice features use when they call OpenAI itself. It is never sent to a custom OpenAI-compatible server: give that server its own key in Settings.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Allows remote OpenAI-compatible base URLs for voice features when set to `true` or `1`.

### `NGROK_AUTHTOKEN`

ngrok auth token used by OhPiChamber tunnel commands. You can also configure ngrok with `ngrok config add-authtoken <token>`.

## Runtime helpers

### `BUN_BINARY`

Bun executable OhPiChamber should use when spawning daemon processes.

### `BUN_INSTALL`

Bun installation root. OhPiChamber uses it to find `bin/bun` for daemon startup and updates.
