# Permissions et filet de sécurité

Chaque action de l’agent (lancer une commande, modifier un fichier, appeler un outil MCP, récupérer une page) est évaluée par l’autoriseur du Host et la stratégie de worker d’Agent Service. Les modes de permission d’OpenChamber déterminent ce qui se passe quand une action requiert une approbation.

## Allow, ask et deny

La passerelle Host valide les accès au système de fichiers par rapport au répertoire du projet. Les actions ciblant des chemins en dehors de la racine du projet sont rejetées d'office. À l'intérieur de la racine du projet, les lectures et modifications courantes de fichiers s'effectuent via les outils de fichiers du projet sans confirmation supplémentaire.

- **allow :** l’agent continue
- **deny :** l’action est bloquée
- **ask :** l’agent s’arrête et attend une réponse

Pour configurer les outils visibles et utilisables par un agent, utilisez le champ **outils autorisés** (allowed tools) dans **Paramètres → Agents**. Pour choisir le mode de permission par défaut des nouvelles sessions, utilisez **Paramètres → Sessions**.

## Les trois modes

| Mode | Qui répond au « ask » |
| --- | --- |
| **Demander à chaque fois** | Vous. Chaque demande attend votre réponse. |
| **Filet de sécurité** | Jev laisse passer les actions courantes et vous garde les risquées. |
| **Tout accepter** | OpenChamber, toujours oui. Chaque demande est autorisée tout de suite, sans vérification. |

**Tout accepter** n’a besoin de rien d’autre : ce mode considère simplement chaque « ask » comme autorisé. Utilisez-le quand vous faites confiance à la tâche et ne voulez pas être interrompu.

## Changer de mode

- **Pour une session :** cliquez sur le bouton en forme de bouclier dans le champ de saisie. Chaque clic passe au mode suivant.
- **Pour les nouvelles sessions :** choisissez le mode par défaut dans **Paramètres → Sessions → Permissions**. Les sessions existantes gardent leur mode.

Les sous-agents suivent la session qui les a lancés.

## Le filet de sécurité

Dans ce mode, OpenChamber interroge [Jev](/fr/classification-providers/) sur chaque demande : est-ce courant, ou est-ce à vous de décider ? Lire, compiler, lancer les tests, modifier les fichiers du projet et faire des commits ordinaires passent. Réécrire l’historique git, supprimer des données, modifier le système, déployer, publier quelque part ou envoyer des fichiers à l’extérieur attendent votre décision, comme tout ce qui n’est pas clair.

Une demande retenue affiche la carte de permission habituelle avec une ligne en plus, **Le filet de sécurité a retenu cette action pour que vous décidiez**, et le type d’action. Si Jev ne répond pas en quatre secondes, l’action vous attend aussi. Le filet de sécurité n’autorise jamais rien parce que la vérification a échoué.

Le filet de sécurité a besoin d’un [fournisseur de classification](/fr/classification-providers/). Sans lui, le bouton bouclier saute ce mode et il est désactivé dans les paramètres.

## Continue pendant votre absence

Le mode vit dans le serveur OpenChamber : il continue donc de répondre aux demandes après que vous avez fermé l’onglet ou verrouillé votre téléphone, et il survit aux redémarrages.
