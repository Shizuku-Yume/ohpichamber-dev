# Fournisseurs de classification (Jev)

Certaines fonctions d’OhPiChamber ont besoin d’une décision rapide avant d’agir : cette commande est-elle risquée, de quel type de tâche relève ce prompt, ce travail semble-t-il terminé ? C’est Jev, un petit modèle de décision conçu par TypeSafe, qui répond à ces questions. Cette page explique comment donner à OhPiChamber l’accès à Jev.

Jev n’écrit jamais de code et ne répond pas dans votre chat. Il renvoie seulement un verdict, et OhPiChamber agit en conséquence. OhPiChamber attend une réponse quatre secondes au plus avant l’envoi d’un message ou l’exécution d’une action, et jusqu’à quinze secondes pour les vérifications après un tour, où rien n’en dépend.

## Ce qui utilise Jev

| Fonction | La question à laquelle Jev répond |
| --- | --- |
| [Permissions et filet de sécurité](/fr/permissions/) | L’agent doit-il vous demander avant de lancer cette action ? |
| [Routage automatique des modèles](/fr/auto-model-routing/) | À laquelle de vos catégories appartient ce prompt ? |
| [Sessions en cours](/fr/sessions-in-work/) | Ce tour ressemble-t-il à la fin du travail ? |
| [Récapitulatif et suggestion du prochain message](/fr/sessions-in-work/) | Un récapitulatif ou une suggestion vaut-il la peine d’être généré après ce tour ? |

Sans fournisseur, le filet de sécurité et Auto sont masqués, et les sessions en cours ne reçoivent pas l’indication « semble terminé ». Les sessions passent quand même en cours quand vous envoyez un message. Les récapitulatifs et les suggestions fonctionnent toujours, simplement sans le filtre.

## Configuration

Jev reste désactivé tant que vous ne l’activez pas : rien de vos conversations ne part vers un fournisseur de classification si vous n’en choisissez pas un. Ouvrez **Paramètres → Fournisseurs → Fournisseurs de classification** et choisissez où partent les requêtes vers Jev. En plus de **Désactivé**, il y a cinq options.

### Clé OpenRouter

Utilise la clé API enregistrée et configurée pour OpenRouter, facturée sur votre compte OpenRouter. La classification Jev requiert un identifiant de fournisseur enregistré plutôt qu'une variable d'environnement.

1. Ouvrez **Paramètres → Fournisseurs** et ajoutez une clé API au fournisseur **OpenRouter**.
2. Revenez dans **Fournisseurs de classification** et choisissez **Clé OpenRouter**.

### Clé Vercel AI Gateway

Utilise la clé API enregistrée et configurée pour Vercel AI Gateway, facturée sur votre compte Vercel. La classification Jev requiert un identifiant de fournisseur enregistré plutôt qu'une variable d'environnement.

1. Ouvrez **Paramètres → Fournisseurs** et ajoutez une clé API au fournisseur **Vercel AI Gateway**.
2. Revenez dans **Fournisseurs de classification** et choisissez **Clé Vercel AI Gateway**.

### Google Gemini

Utilise Gemini Decision 1, le modèle de décision de Google, via la Decisions API de Google, facturé sur votre compte Google. OhPiChamber lui pose les mêmes questions qu’à Jev. Avec l’offre gratuite de Google, Google peut utiliser ce qu’il reçoit pour améliorer ses produits ([conditions de l’API Gemini](https://ai.google.dev/gemini-api/terms#data-use-unpaid)).

1. Obtenez une clé API dans [Google AI Studio](https://aistudio.google.com/apikey).
2. Collez-la dans le champ **Clé API Gemini** et cliquez sur **Enregistrer**.

Enregistrer une clé la sélectionne aussi. Elle reste sur le serveur OhPiChamber, dans son propre fichier, et n’est jamais envoyée au navigateur.

Si le fournisseur **Google** d’OMP a déjà une clé API, vous pouvez laisser le champ vide et choisir **Google Gemini**. Une clé dans `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY` ou `GEMINI_API_KEY` fonctionne aussi. Une clé enregistrée dans OhPiChamber l’emporte sur les deux. Gardez la clé dans OhPiChamber si vous voulez Gemini uniquement pour les décisions : une clé dans le fournisseur Google d’OMP y ouvre aussi tous les modèles de chat Gemini, et une clé API Gemini ne peut pas être limitée à un seul modèle.

### Clé API TypeSafe

Votre propre clé et votre propre quota TypeSafe.

1. Obtenez une clé API auprès de [TypeSafe](https://docs.typesafe.ai).
2. Collez-la dans le champ **Clé API TypeSafe** et cliquez sur **Enregistrer**.

Enregistrer une clé la sélectionne aussi. Elle reste sur le serveur OhPiChamber, dans son propre fichier, et n’est jamais envoyée au navigateur.

### Point de terminaison personnalisé

N’importe quel service qui parle l’API System One de TypeSafe : une passerelle auto-hébergée, un proxy d’entreprise ou un fournisseur absent de cette liste.

1. Sous **Point de terminaison personnalisé**, remplissez les champs **URL du point de terminaison** et **Modèle** (par exemple `jev-latest`).
2. Ajoutez une **Clé API** si le service en demande une. Elle est envoyée comme jeton `Bearer`.
3. Cliquez sur **Enregistrer**.

Collez l’adresse complète sur laquelle le service répond, comme `https://api.typesafe.ai/v1/systemone` ou `https://proxy.company.internal/v1/decision` pour un proxy d’entreprise. OhPiChamber l’appelle telle que vous la collez et n’ajoute rien au chemin. Seuls `http` et `https` fonctionnent, et la clé va dans son propre champ, jamais dans l’URL.

Enregistrer sélectionne aussi le point de terminaison. Comme la clé TypeSafe, le point de terminaison et sa clé restent sur le serveur OhPiChamber, dans leur propre fichier, et la clé n’est jamais envoyée au navigateur.

Un serveur peut aussi recevoir son point de terminaison depuis l’environnement, ce qui est pratique quand vous configurez OhPiChamber pour une équipe :

```bash
OPENCHAMBER_JEV_URL=https://jev.example.com/v1/systemone
OPENCHAMBER_JEV_MODEL=jev-latest        # facultatif, c’est la valeur par défaut
OPENCHAMBER_JEV_API_KEY=...             # facultatif
```

Sur les portables que vous gérez, placez plutôt le même point de terminaison sous `jev` dans le [fichier de politique](/fr/security/) de la machine. Il l’emporte sur l’environnement.

Dans les deux cas, ce point de terminaison remplace celui enregistré dans les Paramètres, et les Paramètres l’affichent sans que personne puisse le modifier. En [mode entreprise](/fr/security/), c’est la seule source Jev autorisée en plus de **Désactivé**, et elle est sélectionnée par défaut.

Dès qu’un fournisseur fonctionne, la carte dans **Paramètres → Fournisseurs** affiche **Prêt**.

## Quand votre choix ne fonctionne plus

Si le fournisseur choisi n’est plus utilisable (par exemple, une clé a été supprimée), OhPiChamber se rabat sur la première de vos propres clés qui fonctionne : clé TypeSafe, puis votre point de terminaison personnalisé, puis OpenRouter, puis Vercel AI Gateway. Il ne se rabat jamais sur Google Gemini, et **Désactivé** reste désactivé. La page indique lequel est utilisé en ce moment.

Si Jev est lent ou échoue sur une requête, rien ne casse. Chaque fonction a une réponse sûre pour ce cas :

- Le filet de sécurité laisse l’action en attente de votre décision.
- Auto envoie le prompt à votre modèle de repli.
- L’indication « semble terminé » n’apparaît pas sur les sessions en cours.
- Le récapitulatif et la suggestion sont générés comme si Jev n’existait pas.

## Ce que Jev voit

Jev reçoit votre dernier message et, pour le contexte, des extraits de la conversation récente : jusqu’à trois tours précédents, coupés à quelques centaines de caractères chacun, et à la fin d’un tour, la réponse de l’agent réduite à son début et à sa fin. Pour le filet de sécurité, il reçoit aussi l’action pour laquelle l’agent demande une permission, telle qu’OMP la décrit : la commande que l’agent veut lancer, ou le fichier et la modification pour une édition. Quand l’agent crée un fichier, cette modification est le fichier entier, y compris les images écrites sous forme de texte comme le SVG. Quand Jev vérifie un objectif, il reçoit l’objectif et la dernière réponse de l’agent, jusqu’à 10 000 caractères.

Les requêtes partent du serveur OhPiChamber directement vers OpenRouter, Vercel AI Gateway, Google, TypeSafe ou votre point de terminaison personnalisé, selon votre choix.

## Où ça fonctionne

Jev tourne dans le serveur OhPiChamber : il fonctionne donc dans l’application desktop, dans l’application web et sur votre téléphone connecté à l’une des deux.
