# Variáveis de ambiente

O OhPiChamber lê estas variáveis na inicialização. Para serviços de inicialização, `ohpichamber startup enable` salva por padrão um snapshot do ambiente atual, então execute de novo após mudar variáveis que o serviço deve usar.

## Variáveis para sessões de agentes, Git e o terminal

Para dar às sessões de agentes, ao Git, ao terminal e às [ações de projeto](/pt-br/project-actions/) variáveis próprias, como um token de API ou o endereço de um banco de dados, adicione-as em **Configurações → Geral → Variáveis de ambiente** em vez de exportá-las antes de iniciar o OhPiChamber. Os valores ficam na máquina em que o OhPiChamber roda, em `environment.json` no diretório de dados, e apenas o seu usuário pode ler. As Configurações nunca exibem um valor novamente: você pode substituir ou remover, não ler de volta.

- As sessões de agentes as recebem na inicialização.
- O Git, o terminal e as ações de projeto as recebem na próxima execução.

Um projeto pode adicionar variáveis próprias, ou um comando que as imprime, como `direnv export json`, em **Configurações → Projetos**. Veja [Projetos](/pt-br/projects/#ambiente-do-projeto).

Tudo abaixo é lido pelo próprio OhPiChamber na inicialização.

## Servidor OhPiChamber

### `OPENCHAMBER_HOST`

Endereço onde o servidor web do OhPiChamber escuta. Use `0.0.0.0` para permitir acesso de outras máquinas.

### `OPENCHAMBER_LAN_URL`

O endereço que outros dispositivos da sua rede usam para acessar o OhPiChamber, por exemplo `http://192.168.1.20:3000`. Links e QR codes de pareamento oferecem esse endereço em vez do que o OhPiChamber detecta sozinho. Defina quando essa detecção errar, por exemplo no Docker, onde o OhPiChamber só vê o endereço interno do contêiner.

### `OPENCHAMBER_UI_PASSWORD`

Senha da interface no navegador. Use quando expor fora do localhost, por túnel ou por proxy reverso.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

Quanto tempo dura o login no navegador, em horas, quando "confiar neste dispositivo" está desligado. O padrão é `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

Quanto tempo dura o login, em dias, num dispositivo marcado como confiável. O padrão é `7`.

### `OPENCHAMBER_API_ONLY`

Inicia o OhPiChamber em modo headless quando definido como `true` ou `1`. As rotas de API continuam disponíveis para clientes desktop e mobile, mas a UI do navegador não é servida.

### `OPENCHAMBER_FRAME_ANCESTORS`

Origens que podem mostrar o OhPiChamber dentro de um frame na própria página, separadas por espaços, por exemplo `https://dash.example.com`. `*` permite qualquer site. Por padrão só o próprio OhPiChamber e seus apps desktop e mobile podem incorporá-lo, o que impede outros sites de sobrepor os botões dele.

### `OPENCHAMBER_TRUSTED_PROXIES`

Endereços de proxies reversos que rodam em outra máquina ou em outro contêiner, separados por vírgulas, como `192.168.1.10` ou `172.18.0.0/16`. O OhPiChamber limita as tentativas de login com falha por cliente e só lê o endereço do cliente em `X-Forwarded-For` quando a requisição vem desta máquina ou de um endereço desta lista. Um proxy fora da lista conta como um único cliente, então as tentativas com falha de uma pessoa podem impedir por um tempo que todos atrás dele façam login.

### `OPENCHAMBER_DATA_DIR`

Altera o diretório de dados do OhPiChamber. O padrão é `~/.config/ohpichamber`.

### `OPENCHAMBER_CHATS_DIR`

Move os diretórios gerenciados de conversa que o OhPiChamber cria para conversas sem projeto. O padrão é `~/.config/ohpichamber/chats`. As conversas existentes não são movidas.

### `OPENCHAMBER_COMPRESS_API`

Controla a compressão das respostas da API. `true` ou `1` ativa; `false` ou `0` desativa.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Desativa a compressão das respostas da API quando definido como `true` ou `1`. Tem prioridade sobre `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Ativa logs HTTP detalhados quando definido como `true` ou `1`.

## Proxy

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Envia por um proxy as requisições de saída do próprio OhPiChamber, como limites de uso e catálogos de skills. Nomes em minúsculas também funcionam. Hosts em `NO_PROXY` se conectam diretamente, e `localhost`, `127.0.0.1` e `::1` sempre se conectam, então os retornos de login e as conexões locais continuam funcionando.

## Terminal e Git

### `OPENCHAMBER_TERMINAL_SHELL`

Executável de shell usado nas sessões de terminal do OhPiChamber.

### `OPENCHAMBER_GIT_BINARY`

Executável do Git usado pelos recursos Git do OhPiChamber.

### `GIT_BINARY`

Override alternativo para o executável do Git. Para configuração específica do OhPiChamber, prefira `OPENCHAMBER_GIT_BINARY`.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

TTL, em milissegundos, para leituras de arquivos em cache baseadas em Git. Use `0` para desativar o cache durante depuração.

## Voz e túneis

### `OPENAI_API_KEY`

API key usada pelos recursos de voz do OhPiChamber quando chamam a própria OpenAI. Ela nunca é enviada a um servidor próprio compatível com OpenAI: dê a esse servidor uma chave própria nas Configurações.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Permite base URLs remotas compatíveis com OpenAI para recursos de voz quando definido como `true` ou `1`.

### `NGROK_AUTHTOKEN`

Token de autenticação do ngrok usado pelos comandos de túnel do OhPiChamber. Você também pode configurar com `ngrok config add-authtoken <token>`.

## Auxiliares de runtime

### `BUN_BINARY`

Executável do Bun que o OhPiChamber deve usar ao iniciar processos daemon.

### `BUN_INSTALL`

Raiz da instalação do Bun. O OhPiChamber usa isso para encontrar `bin/bun` ao iniciar daemons e atualizar.
