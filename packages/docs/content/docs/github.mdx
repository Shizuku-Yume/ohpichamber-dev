# GitHub Issues & PRs

Connect your GitHub account and OpenChamber can pull in issues and pull requests, start a session straight from one, and open or update PRs for you.

The project's remote decides which host OpenChamber talks to. A project whose `origin` is on gitlab.com uses your GitLab account for the board, the pull request badge on its branches, and the Git panel. A remote on a host alias from `~/.ssh/config`, such as `github.com-work`, isn't matched to any host. Gitea and Forgejo match an alias whose SSH configuration points at the instance's web address, and a remote on the instance's SSH clone address once you enter that address in **Settings → Integrations**.

1. Open **Settings → Integrations** and expand the **GitHub** card.
2. Choose **Connect GitHub**. OpenChamber shows a link and a short code.
3. Open the link, enter the code, and approve.

When it's connected, your account shows on the card. You can connect more than one account and switch between them, or disconnect at any time. If the `gh` CLI is signed in on the same machine, OpenChamber can use it as a fallback.

## Start work from an issue or PR

When you create a [worktree session](/worktrees/) with GitHub connected, you can start it from an issue or a pull request:

- pick an **issue** and OpenChamber names the branch after it
- pick a **pull request** and it checks out the PR's branch; you can include the PR's diff so the agent has the full change

The new session opens with the issue or PR already attached to the message box. Nothing is sent for you: choose the model, say what you want done, and send.

## Open and manage pull requests

From the **PR** tab in the [git view](/git/), you can create a pull request, update it, mark a draft as ready, or merge it. OpenChamber can generate the PR title and description from your changes.

## Link an issue or pull request to a message

In the chat composer, open the **+** menu and choose the link entry for your host, such as **Link GitHub Issue or PR**, **Link GitLab Issue or MR**, or **Link Gerrit change**. Pick one or more items. Each one goes with your next message as context, a pull request can bring its diff, and the session's work status panel keeps a link to it. Attaching only adds context; your message says what to do with it.

You can also paste a link to an issue, pull request or Linear issue into the message. It turns into a chip with its number and title right where you pasted it, and goes with the message the same way. A link the app can't read stays plain text, and a notice says why.
