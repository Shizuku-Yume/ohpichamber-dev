# Providers, Models & Agents

Before OpenChamber can do anything, it needs at least one AI provider connected. This page covers connecting a provider, choosing a model, and tailoring agents.

## Connect a provider

1. Open **Settings → Providers**.
2. Open the **Add provider** menu and pick a provider that isn't connected yet, or choose **Other / Custom** for an OpenAI-compatible endpoint.
3. Sign in using the method required by the provider:
   - **API key** — paste your key and save.
   - **OAuth sign-in** — open the authorization link in your browser to sign in. If prompted, paste the authorization code back into OpenChamber, then complete the connection.

### Custom / Other providers

For gateways, campus LLMs, Ollama, LiteLLM, and similar OpenAI-compatible APIs:

1. Choose **Other / Custom** in the provider list.
2. Enter a provider ID, display name, base URL (`http://` or `https://`), an optional API key, and at least one model ID and name.
3. Enter the model's context window and maximum output tokens. Advanced metadata (such as reasoning options, variants, and modalities) can be configured as JSON under model details.
4. Optionally add request headers.
5. Save — OpenChamber registers the provider and models through the Agent Service, storing API keys as write-only credentials.
6. To change an existing custom provider, open it and choose **Edit**.

An API key is optional. Keyless local endpoints (such as Ollama, LiteLLM, or llama.cpp) and services using custom header authentication can connect without an API key.
When a provider shows as connected, its models become available in chat.

To disconnect, open the provider and choose to remove its sign-in.

## Pick a model

You pick the model where you're working:

- in chat, use the model picker in the message bar to set the provider and model for that session
- per agent, set a default model (below)

## Set up agents

An agent is a named setup — a model, a system prompt, and which tools are available to it.

1. Open **Settings → Agents**.
2. Pick an agent, or create a new one.
3. Edit any of:
   - **description** — what the agent is for
   - **model** — its default provider and model override
   - **prompt** — standing instructions it always follows
   - **allowed tools** — which tools are available to the agent (tool availability: listing tools here makes them callable by the model, while operation authorization remains enforced by Host policies and approvals)
   - **permission preset** — optional permission preset ID for the agent profile
## Where your sign-ins live

Provider credentials and sign-ins are stored in the Agent Service credential store on the server, keeping keys secure and isolated. You can connect multiple accounts for a provider and choose which active account to use as the default in the provider's accounts list.
