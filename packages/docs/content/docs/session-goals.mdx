# Session Goals

Goals are implemented by OMP's goal mode in the Agent Service worker. The agent owns continuation and declares completion; OpenChamber does not run a second supervisor or independent auditor.

A goal turns one prompt into a finish line. OMP continues the session toward that objective until the agent reports completion, the token budget is exhausted, no progress is possible, or you stop it.

## Start a goal

1. Press the target button in the composer. It lights up — goal mode is armed.
2. Type your prompt and send it. That message becomes the goal's objective.

This works in an existing session and in a new session draft alike: arm the target, write the first message, send — the new session starts with the goal already active.

### More ways to start a goal

- **From an agent's reply**: in the "Start new session from this answer" dialog, check **Run as goal** — the reply is handed over as an assignment for OMP goal mode (combine with **Create worktree** for an isolated run).
- **From a plan**: when implementing a saved plan in a new session or worktree, check **Run as goal** in the dialog. The plan content becomes the OMP goal objective.
- **On a schedule**: check **Run as goal** on a [scheduled task](/scheduled-tasks/) to start OMP goal mode for that run.

## How it works

OMP goal mode continues the session from the worker after each turn. The agent's goal tool declares completion; it is not judged by a separate model. OMP also stops when the optional token budget is reached, when a continuation makes no progress, or when you pause, drop, or abort the goal.

- Good: "Add tests for the export module and make the whole test suite pass."
- Not so good: "Fix it" or "Continue with that idea."

For small contextual follow-ups you don't need a goal — just send a normal message.

### Stopping and resuming

- The **stop button** aborts the running turn and pauses the goal — your explicit "stop" always wins over the loop.
- **Pause** on the goal strip does the same from the other direction: it pauses the goal and stops the running turn.
- While paused, chat normally — the loop stays out of the way.
- **Resume** re-arms the loop: on an idle session the continuation nudge goes out immediately; if the agent happens to be working, the loop silently re-attaches at its next pause.

## Watch and manage

- The strip above the composer shows the goal's objective, status, and token usage, with an inline pause/resume button.
- The target button stays lit while the goal runs (blue), turns green on completion, and red when paused or budget-limited. Press it to open the goal dialog: edit the objective or budget, or remove the goal.
- In the session sidebar, a small target appears next to the session date, colored by the goal's state.

## Notifications

When a goal is active, per-turn "agent is ready" notifications are suppressed. When OMP reports completion or a reached token budget, you get one goal notification. Pausing, dropping, or aborting a goal does not send a completion notification. A no-progress stop waits for your next instruction; it does not declare the goal complete. Permission requests, questions, and error notifications keep working as usual.

## Token budget

In **Settings → Chat → Goal** you can set a default token budget for new goals. When a goal reaches its budget it stops as "budget reached" instead of spending more — you can raise the budget and resume from the goal dialog.

## Keep in mind

- Goal mode runs in the OMP session worker, not in a separate OpenChamber server-side supervisor.
- OMP owns continuation, completion, budget, and no-progress decisions.
- One goal per session at a time.
