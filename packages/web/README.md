Web and PWA application and Host Gateway server runtime for OhPiChamber.

This package owns the browser UI build, the Host Gateway HTTP and WebSocket server, CLI executable (`ohpichamber`), and host service endpoints (filesystem, Git, PTY terminals, dev server discovery, dev tunnels, authentication, and push notifications).

### Migration status

OhPiChamber's retained Host Gateway infrastructure lives in the dedicated `server/lib/host/` modules; the extracted Host owner is documented in [`server/lib/host/DOCUMENTATION.md`](server/lib/host/DOCUMENTATION.md). The Host Gateway has no production proxy registration or Host-managed OpenCode lifecycle: the unmounted legacy `proxy.js` was deleted with the in-space runtime, and normal agent execution uses the OMP Agent Service through Canonical API `/api/agent/v1`. `server/lib/opencode/` now holds historical notes only. Isolated spaces run no agent runtime and stay behind the server-owned release gate until the OMP space runtime is built.

Production startup now starts the supervised Bun OMP Agent Service after the Host listener, Git credential-helper publication and shutdown handlers are ready. No OpenCode binary is required or automatically started. Canonical readiness is `/api/agent/v1/ready`; startup failure leaves canonical operations unavailable, without an alternate engine. Electron Agent Runtime staging is implemented and verified, while packaged Electron UI/runtime certification remains open; standalone npm package runtime bundling is addressed in M5 (`m5-release-surfaces`). Credential handoff is explicit and private; startup never imports credentials.

Full project overview, screenshots, and architecture documents live in the repository root and `.workflow/omp-migration/`.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/Shizuku-Yume/ohpichamber/main/scripts/install.sh | bash
```

Or install manually: `bun add -g ohpichamber` (or npm, pnpm, yarn).

> **Runtime prerequisites:** Node.js 24.14+ for the Host, Bun 1.4.4+ on PATH for the supervised Agent Service, and built Agent Service entries with their installed pinned SDK/native dependencies. An OpenCode CLI is not a startup prerequisite. Standalone distribution bundles the pinned OMP runtime and platform native assets.

### Monorepo development scripts

```bash
# From repository root
bun run build:web       # Build web assets and server dependencies
bun run dev:web         # Watch and build web UI
bun run dev:web:server  # Start server with watch mode
bun run start:web       # Run production server

# From packages/web
bun run build           # Build builtin extensions and web assets
bun run dev             # Watch and build
bun run start           # Start via bin/cli.js serve
```



Published packages run emitted JavaScript from `build/server` and `build/bin`.
To build from a checkout, run `bun install` and `bun run build:web` at the repo
root. `bun run start:web` runs the source CLI with Bun; `bun run dev`,
`dev:server`, `dev:server:watch` and tests use sources without a server build.
`bun run build:server` builds only the backend and its runtime assets.
The build includes retained JavaScript/MJS runtime modules even when a typed
declaration keeps them out of TypeScript's emit graph. After building, run
`node scripts/smoke-server-build.mjs --built-cli` from this package to exercise
the production CLI, HTTP listener and native Agent Service with isolated data.

## Usage

```bash
ohpichamber                          # Start on port 3000
ohpichamber --port 8080              # Custom port
ohpichamber --lan --port 3000        # Listen on LAN (0.0.0.0)
ohpichamber --ui-password secret     # Password-protect UI
ohpichamber startup enable           # Start at login as a native service
OPENCHAMBER_UI_PASSWORD=secret ohpichamber startup enable # Save service password env
ohpichamber startup status           # Show startup service status
ohpichamber startup disable          # Remove startup service
ohpichamber tunnel help              # Tunnel lifecycle commands
ohpichamber tunnel providers         # Show provider capabilities
ohpichamber tunnel profile add --provider cloudflare --mode managed-remote --name prod-main --hostname app.example.com --token <token>
ohpichamber tunnel start --profile prod-main
ohpichamber tunnel start --provider cloudflare --mode quick --qr
ohpichamber tunnel start --provider cloudflare --mode managed-local --config ~/.cloudflared/config.yml
ohpichamber tunnel status --all      # Show tunnel state across instances
ohpichamber tunnel stop --port 3000  # Stop tunnel only (server stays running)
ohpichamber connect-url --port 3000  # Add this server to OhPiChamber Desktop
ohpichamber connect-url --server http://host:3000 --qr
ohpichamber connect-url --port 3000 --qr
ohpichamber logs                     # Follow latest instance logs
ohpichamber stop                     # Stop server
```

`startup enable` snapshots your current environment into the native service so startup behaves like you launched `ohpichamber` from the same shell. This preserves provider tokens, PATH, SSH agent settings, and other CLI auth/config env vars. Use `--no-env-snapshot` for a minimal service env.

The canonical Bun workers invoke retained Host capabilities through the private
Host Action boundary. OpenCode tool injection, managed prompt optimizer and
explicit restart/config controls are inherited migration blockers, not current
automatic startup behavior or fallback engines.

### Tunnel behavior notes

- One active tunnel per running OhPiChamber instance (port).
- Starting a different tunnel mode/provider on the same instance replaces the active tunnel.
- Replacing or stopping a tunnel revokes existing connect links and invalidates remote tunnel sessions.
- Connect links are one-time tokens; generating a new link revokes the previous unused link.

### Connect other OhPiChamber apps

Use `connect-url` when a web/API server should be added to OhPiChamber Desktop or another OhPiChamber app. If no server is running on the selected port, OhPiChamber starts one first.

```bash
ohpichamber connect-url --port 3000
ohpichamber connect-url --port 3000 --qr
ohpichamber connect-url --port 3000 --json
ohpichamber connect-url --port 3000 --name "Workstation"
ohpichamber connect-url --port 3000 --lan --server http://workstation.local:3000 --qr
```

### Headless/API-only server for Desktop

Use this on a remote machine when you want OhPiChamber running as a web/API server, then connect to it from OhPiChamber Desktop on another machine:

```bash
ohpichamber connect-url --port 3000 --api-only --lan --server http://workstation.local:3000 --qr --ui-password your-password
```

`--api-only` starts API routes without serving browser UI assets. `--lan` binds the server so other machines can reach it. `--server` is the address saved into the Desktop connection link. `--ui-password` protects browser access if UI routes are enabled elsewhere; the generated client token is what Desktop uses for API access.

This creates a remote client token and prints an `ohpichamber://connect?...` link. The link contains the server URL, token, label, and payload version. In OhPiChamber Desktop, paste it in **Settings -> Remote Instances -> Direct Instances -> Import Link** to add that server as an Instance.

If the server was started with `--lan` or `--host 0.0.0.0`, `connect-url` automatically advertises a detected LAN IP instead of `127.0.0.1`. Use `--server <url>` when you want to advertise a specific DNS name, Tailscale address, reverse proxy URL, or HTTPS endpoint.

If you are exposing the server beyond localhost, start it with a password:

```bash
ohpichamber serve --lan --port 3000 --ui-password your-password
```

Generating a client token does not automatically password-protect the hosted browser UI. `--ui-password` protects browser access; the client token lets another OhPiChamber app connect to this server.

<details>
<summary>Host environment variables</summary>

The Host starts the supervised Bun OMP Agent Service automatically behind `/api/agent/v1`.

| Variable | Description |
|----------|-------------|
| `OPENCHAMBER_HOST` | Bind hostname for the OhPiChamber web server (default: `127.0.0.1`; use `0.0.0.0` for LAN/remote access. trusted networks only) |
| `OPENCHAMBER_VERBOSE_REQUEST_LOGS` | Set to `true` to log every HTTP request; disabled by default to keep user logs small |
| `OPENCHAMBER_GITLAB_CLIENT_ID` | OAuth application ID used for GitLab device flow. Overrides the built-in application, which covers `gitlab.com` only; a self-managed instance needs its own. Personal access token and `glab` authentication remain available without it. |
| `OPENCHAMBER_SKIP_API_COMPRESSION` | Set to `true` to disable gzip compression for `/api/*` responses |
| `OPENCHAMBER_COMPRESS_API` | Set to `true` to force `/api/*` compression, or `false` to disable it. Desktop runtime disables API compression by default to reduce local CPU overhead |
| `OPENCHAMBER_FS_UPLOAD_MAX_BYTES` | Maximum file upload size in bytes (default: 100 MiB) |
| `OPENCHAMBER_PROXY_TIMEOUT_MS` | OpenCode upstream proxy deadline in milliseconds. Accepts integers from `0` to `2147483647`; defaults to `240000` (4 minutes). Invalid values warn and keep the default. `0` disables this proxy deadline, allowing unbounded waits until the client disconnects. Other client and upstream timeouts still apply. VS Code's separate extension bridge is unchanged. |
| `OPENCHAMBER_TERMINAL_SHELL` | Preferred terminal shell executable used by the `Auto` setting before platform defaults |

</details>

<details>
<summary>Docker & Docker Compose setup (OMP 18.18.0)</summary>

Run OhPiChamber with the supervised OMP Agent Service inside Docker:

```bash
# 1. Prepare persistent host directories
mkdir -p data/ohpichamber data/omp data/ssh workspaces
chown -R 1000:1000 data/ workspaces

# 2. Launch OhPiChamber via Docker Compose
OPENCHAMBER_UI_PASSWORD="your-strong-password" docker compose up -d
```

### Mounted Volumes
- `./data/ohpichamber:/home/ohpichamber/.config/ohpichamber`: Host configuration and instance settings.
- `./data/omp:/home/ohpichamber/.omp`: Pinned OMP Agent Service state, logs, and authentication credentials.
- `./data/ssh:/home/ohpichamber/.ssh`: SSH keys and configuration.
- `./workspaces:/home/ohpichamber/workspaces`: Project files and repositories.

### Optional environment variables
```yaml
environment:
  OPENCHAMBER_UI_PASSWORD: your_secure_password
  OPENCHAMBER_HOST: 0.0.0.0
  OPENCHAMBER_TUNNEL_MODE: quick # quick | managed-remote | managed-local
  OPENCHAMBER_TUNNEL_PROVIDER: cloudflare
```

For `managed-remote` mode, also set:
```yaml
environment:
  OPENCHAMBER_TUNNEL_MODE: managed-remote
  OPENCHAMBER_TUNNEL_HOSTNAME: app.example.com
  OPENCHAMBER_TUNNEL_TOKEN: <token>
```

For `managed-local` mode, you can set:
```yaml
environment:
  OPENCHAMBER_TUNNEL_MODE: managed-local
  OPENCHAMBER_TUNNEL_CONFIG: /home/ohpichamber/.cloudflared/config.yml
```

Managed-local path note: `OPENCHAMBER_TUNNEL_CONFIG` must use a container path under `/home/ohpichamber/...`. If the config file references `credentials-file`, ensure that JSON path is also mounted and reachable inside the container.

> **Note on Container Verification:** Docker is unavailable in the current development environment. Dockerfile, compose, and entrypoint manifests are statically verified; live container runtime execution and verification are explicitly deferred to milestone M7 (`m7-release-verification`).

<details>
<summary>systemd service (VPN / LAN access)</summary>

Use `--foreground` to keep the Node Host in-process so systemd (or another process
manager) can track and restart it. The Host supervises the Bun Agent Service;
there is no separate OpenCode service dependency. Ensure Bun and the built service
dependencies are installed and reachable in the service environment.

> **Why set `PATH` and `SSH_AUTH_SOCK`?**
> systemd user services start with a minimal environment. no shell profile is sourced.
> Without an explicit `PATH`, Bun and tools installed via Homebrew, npm, or `~/.local/bin` may be unavailable to the service and its shells.
> Without `SSH_AUTH_SOCK`, git operations over SSH (push, pull, clone) will fail.
> `%t` expands to `$XDG_RUNTIME_DIR` (e.g. `/run/user/1000`), where most SSH agents write their socket.

**`~/.config/systemd/user/ohpichamber.service`**
```ini
[Unit]
Description=OhPiChamber Web Server

[Service]
Type=simple
ExecStart=ohpichamber serve --port 3000 --host 0.0.0.0 --ui-password your-password --foreground
Environment="PATH=/home/YOU/.bun/bin:/home/YOU/.local/bin:/usr/local/bin:/usr/bin:/bin"
Environment=SSH_AUTH_SOCK=%t/ssh-agent.socket
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now ohpichamber
```

`--host 0.0.0.0` is required to listen on all interfaces (the default is `127.0.0.1`). Use `--host <ip>` or `OPENCHAMBER_HOST=<ip>` to bind to a specific interface instead.

</details>

## What makes the web version special

- **Remote access** - Cloudflare tunnel with quick, managed-remote, and managed-local modes plus QR onboarding (direct UI password entry required)
- **Mobile-first PWA** - optimized chat controls, keyboard-safe layouts, drag-to-reorder projects, and attachment-friendly UI
- **Background notifications** - know when your agent finishes, even from another tab
- **Cross-tab tracking** - session activity stays in sync reliably across browser tabs
- **Self-update** - update and restart flow from the UI that keeps server settings intact
## Client Distributions and Platform Targets

OhPiChamber is available across Web, Desktop, and Mobile surfaces:

- **Web & PWA**: Served directly by `ohpichamber` or installable as a standalone PWA.
- **Desktop Electron** (`packages/electron`): Native binaries for six desktop targets:
  - **macOS** (`darwin-arm64`, `darwin-x64`): `.dmg` and `.zip`.
  - **Windows** (`win32-x64`, `win32-arm64`): NSIS `.exe` installers (unsigned builds succeed cleanly when Authenticode secrets are absent).
  - **Linux** (`linux-x64`, `linux-arm64`): AppImage, `.deb`, and `.rpm`.
- **Mobile Capacitor** (`packages/mobile`):
  - **Android**: Debug and release `.apk` (install via `adb install` or device package installer) and Play Store `.aab`.
  - **iOS**: Release `.ipa` and simulator builds.

### Unsigned Self-Installation Instructions

Official CI workflows produce unsigned/ad-hoc artifacts when commercial code-signing or Apple Developer credentials are not configured.

- **macOS Gatekeeper Bypass (Electron)**:
  Downloaded unsigned `.app` bundles are quarantined by macOS Gatekeeper. To run:
  1. Clear the quarantine extended attribute in Terminal:
     ```bash
     xattr -cr /Applications/OhPiChamber.app
     ```
  2. Alternatively, Control-click (or right-click) `OhPiChamber.app` in Finder, choose **Open**, and confirm **Open** in the Gatekeeper dialog.
- **iOS Sideloading (Capacitor IPA)**:
  Unsigned or ad-hoc `.ipa` artifacts can be installed onto physical iOS devices:
  1. Sideload the `.ipa` using tools such as **Sideloadly**, **AltStore / SideStore**, or **Xcode Devices & Simulators** (`Window > Devices and Simulators`) with a personal Apple ID.
  2. On the iOS device, navigate to **Settings -> General -> VPN & Device Management**, tap your developer certificate under Enterprise/Developer App, and select **Trust**.
  3. On iOS 16 and later, enable **Settings -> Privacy & Security -> Developer Mode** and reboot when prompted.
