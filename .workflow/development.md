### Native provider management design (2026-10-18)

Task 49 defines native provider management, OAuth lifecycle, and custom provider discovery:
- **Worker ownership:** Dedicated Bun Agent Service worker owns `AuthStorage`, OAuth secrets, and the native models file. All native resources reside in the Bun SDK worker, accessed through Canonical Client and Host Gateway. Node Host and UI never import or run the native SDK.
- **Enterprise policy & Host gate:** Host enforces authentication and preserves existing native provider-entry Host authorization/enterprise gates at every route without inventing legacy `provider.use` / `integration.use` policy checks on native endpoints.
- **Opaque non-secret public contract:** Public records expose opaque `credentialRef` tokens (not internal storage row IDs). Tokens and secret headers are write-only; errors are sanitized.
- **Transactional native OAuth flows:** Native OAuth flows return tokens in memory via SDK `getProviderDefinition` / `getOAuthProvider.login` callbacks, committing credentials only through serialized coordinator mutations after `expectedRevision` CAS check to prevent async `AuthStorage.oauth.login` persisting out of order.
- **Flow binding & lifecycle:** Each flow binds `workspaceId`, `agentDirectory`, `providerId`, worker generation, and a unique `flowId`, supporting abort/cleanup and manual remote callback prompts.
- **Account labeling & multi-account:** Application labels in private configuration keyed by `credentialRef` provide intentional application metadata; default account selection binds to existing native model resolution.
- **Identity separation:** Separate native login method ID from stored provider ID (`storeCredentialsAs`).
- **Retained scope:** Replaces legacy OpenCode integration form fields without deleting OAuth, multi-account, or custom provider capabilities.
