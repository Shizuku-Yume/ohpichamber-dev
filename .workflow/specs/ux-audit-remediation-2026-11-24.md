# Maintainer UX Audit & OMP 19.1 Alignment Remediation (2026-11-24)

**Status:** done
**Priority:** high
**Integration branch:** ux-audit-remediation/integration

## What this is for

After the maintainer tested the locally installed Linux AppImage (`71744c1df7`), ten screenshots exposed severe UX regressions, unfinished OMP 19.1 adaptations, and upstream OpenChamber v2.8.0 merge losses across Settings, the workbench right rail / Work Status panel, subagent/vibe worker viewing, and OMP tool rendering. A full codebase audit against upstream OpenChamber v2.8.0 (`30c70496a5`), OMP 19.1 SDK (`@oh-my-pi/pi-coding-agent`), `PATTERNS.md`, and `STYLING.md` traced every reported complaint plus related cross-cutting defects ("举一反三"):

1. **Usage page (`用量`) dumps 6 flat `重置额度规则` steppers** (`UsagePage.tsx:109-128`) while the actual auto-redeem consent switches (`codexResets.autoRedeem*`, `claudeResets.autoRedeem*`) are `boundary`-hidden (`settings-ui.ts:33-37`). Fix: expose the `autoRedeem*` tri-state settings on `usage:resets` and fold both Codex and Claude auto-reset rules inside **default-collapsed** `SettingsDisclosure` rows under an Auto-use reset credits section.
2. **Provider & model editing (`提供商`) dumps raw OMP wire parameters flat in the user's face** (`CustomProviderForm.tsx`, `CustomProviderModelRow.tsx`): ~10 top-level identity fields before models, raw API slugs (`openai-codex-responses`, `bedrock-converse-stream`) in dropdowns and filter pills, noisy 3-line model rows, ~10 always-visible fields per expanded model, and 4 provider disclosures (`discovery`/`compat`/`bedrock`/`remoteCompaction`) that **auto-expand** whenever populated. Fix: progressive disclosure by frequency — human-readable labels for all 16 provider / 24 model APIs, essential fields only at top level, clean 2-line model rows, 5 essential model fields when expanded, and ALL advanced/cosmetic/override/compat/header/bedrock/discovery/remote-compaction blocks **collapsed by default** (auto-opening only on validation error or fresh Bedrock switch).
3. **Model Roles (`模型角色`) clashes with project design & lacks OMP 19.1 custom roles**:
   - `ModelRoleLinkRow` displays raw `provider/model:thinking` strings next to ugly underlined `SettingsInlineLink` text (`在模型角色中设置`, `在网页搜索中设置`, `打开语音设置`) across `Sessions`, `Git`, `Memory`, `Agents`, `Tools`, `ModelRoles`, and `RetryFallbackChains`.
   - `ModelRolesPage` hardcodes 15 built-in roles; OMP 19.1 supports custom roles via `modelRoles` keys + `modelTags` (`{ name, color?, hidden? }`), but `modelTags` is `hidden` in `settings-ui.ts` and the UI has zero add/edit/delete flow.
   - Fix: replace contextual `ModelRoleLinkRow` jump links on `Sessions` (`smol`, `slow`, `plan`), `Git` (`commit`), `Memory` (`memory`), `Agents` (`task`, `advisor`), and `Tools` (`image`) with direct inline `ModelRoleEditor` / `ImageModelSelector` controls backed by the same canonical `omp.modelRoles.<role>` record; redesign the remaining linked-subsystem rows (`web`, `speech` on `ModelRolesPage` and `web` chain in `RetryFallbackChains`) to show friendly resolved model/provider names (never raw `provider/model:thinking`) + standard `Button variant="outline" size="xs"` with `arrow-right` icon (never bare underlined text); expose `modelTags` in `settings-ui.ts` and build a full **Custom roles** section with `+ Add role` dialog, inline editing, rename, and delete with confirmation.
4. **Behavior page (`行为`) dead-ends with red `此文件在目录中已不存在` on `RULES.md` / `SYSTEM.md`**: `BehaviorSidebar.tsx:80-82` lists fixed `RULES.md` and `SYSTEM.md` unconditionally while `catalog-resources.ts:236-247` omits files not yet on disk, causing `NativeBehaviorFiles.tsx:355-368` to render a red missing-file error and `返回行为文件` button. Fix: mirror `AGENTS.md` — selecting an uncreated `RULES.md` or `SYSTEM.md` opens a clean ready-to-edit empty editor with autosave creation on first write (and hides Delete until the file exists); keep missing-file alerts only for dynamically deleted `rule`/`instruction` entries; revalidate native catalog on window focus.
5. **OMP Plugins (`OMP 插件`) dumps SSH hosts / built-in rules & ships a broken Marketplace + dead Apply button**:
   - `PluginsPage.tsx` embeds `ExtensionControlCenter` showing ALL 11 OMP capability kinds including `OpenSSH Config` (`~/.ssh/config` hosts) and 26 `内置默认` built-in rules — unrelated to plugins and duplicating `Behavior`, `Skills`, `MCP`, `Commands`, and `Remote Instances`. Fix: strictly scope Plugins page capability controls to actual plugin/extension-contributed capabilities (`extension-module`, `hook`, `tool`) and NEVER show `ssh`, `OpenSSH Config`, `builtin-defaults`, `rule`, `context-file`, `skill`, `slash-command`, `prompt`, or `mcp` in `OMP 插件`.
   - `plugins.apply` (`catalog-plugins.ts:313-321`) permanently returns `RELOAD_REQUIRED` failure — remove the dead Apply button and show an honest next-session reload note.
   - `catalog-plugins.ts:366` swallows ALL marketplace errors into one hardcoded English sentence (`Native marketplace operation failed. Check the source, name and network access.`), and `updateAllMarketplaces` fails the entire refresh if a single local source path is stale (such as a leftover `/tmp/native-plugins-*` path). Fix: preserve structured error codes & sanitized details, isolate per-source refresh failures, ensure `removeMarketplace` always succeeds even when `sourceUri`/`catalogPath` is missing on disk, localize all marketplace errors across all 15 locales, fix `AddPluginDialog` scope matching & empty-state copy, and enforce isolated HOME in `catalog-plugins.test.ts` so tests can never touch real `~/.omp`.
6. **Subagent & Vibe worker viewing, Right Activity Rail, and side-by-side Work Status**:
   - Upstream OpenChamber v2.8.0 (`30c70496a5`) lost `roomyBesidePanel` (`besidePanel`) in `useWorkStatusVisibility.ts` and `ChatContainer.tsx` during merge resolution, so opening ANY right context panel (including `SubagentsPanel`) hides `WorkStatusPanel` even on 2048px displays; `MainLayout.tsx` also disconnected merged `useSidebarPeek` and `usePaletteShortcuts`.
   - `ContextPanelRail` hides the `subagents` (`ai-agent`) icon whenever no `subagents` tab is already open — even when the active session has running or completed subagents. Fix: pass `subagentsShown` (active session has subagents OR a `subagents` tab exists) to `getVisibleContextRailSurfaces` so the `subagents` rail icon is always reachable when subagents exist, and ensure every subagent/vibe open action populates the right-panel `chat` tab (lighting up the `chat` rail icon right below `subagents`, matching upstream v2.8.0).
   - `childSessionRecord` (`useGlobalSessionsStore.ts:114`) stamps `title: child.role` (`sonic`) instead of the subagent's real name (`home-disk-usage-2`) or task gist, producing duplicate `sonic` sidebar rows.
   - OMP 19.1 `vibe_spawn` ignores `_toolCallId`, leaving `Subagent.toolCallId` unset so `vibe_spawn` cards never associate with their spawned child sessions or `SubagentsPanel` task prompts. Fix: correlate `vibe_spawn` results (`details.spawned.id`) to `toolCallId` and prompt in `SubagentProjector` + `subagentTask.ts` + `useSubagentRows.ts`.
7. **OMP 19.1 All-Tools Presentation & Structured Cards (Vibe + all other built-in/injected tools)**:
   - `presentations.ts` uses wrong param keys for `vibe_send`/`vibe_wait`/`vibe_kill`/`yield`/`think`/`new_context`/`resolve`/`reject`/`propose`/`report_issue`, omits `openchamber_usage`, and leaves `mcp__*` raw.
   - `ToolPart.tsx` + `toolHelpers.ts:683` dump raw JSON inputs and drop rich `details` (`VibeToolDetails.screens`, `CoordinationDetails.jobs/agents`, `DebugToolDetails.snapshot`, `GhToolDetails.watch`, `GoalToolDetails.goal`, `SecurityScanToolDetails`, `WebSearch.response.answer/failures`, `Read/Grep/AstGrep.displayContent`).
   - Fix: build dedicated `VibeToolCard` (TV-wall worker screens + composer prompt display + live `OpenSubtaskButton`, ZERO raw JSON), `WaitToolCard`, and lean `StructuredToolCards` for `debug`, `github`, `goal`, `security_scan`, `checkpoint`, `rewind`, `yield`, `think`, `report_issue`, `resolve`/`reject`/`propose`, plus `web_search` answer/failures, `displayContent` preference for `read`/`grep`/`ast_grep`, `openchamber_usage` presentation, and `mcp__*` friendly labels.
8. **Cross-cutting Settings polish & guardrails ("举一反三")**:
   - `MemoryPage`: hide or fold the 20 Mnemopi/Hindsight rows when their backend is not selected (`memory.backend === 'off'` or the other backend).
   - `RetryFallbackChains`: close the local modal dialog before calling `requestSettingsJump('web-search', ...)` and display friendly provider names instead of raw selectors.
   - `OmpRowControl`: ensure unit inference covers `Minutes`/`Hours` and lock a regression test proving every exposed OMP setting ID has a real translated label across all 15 locales (no raw `setting.id` fallback).
   - Add automated layout/UX regression guards in `settingsLayoutGuard.test.ts`, `settingsItemOwnership.test.ts`, `settingsSearchAnchors.test.ts`, and sync `.workflow/upstream-deltas.tsv`.
