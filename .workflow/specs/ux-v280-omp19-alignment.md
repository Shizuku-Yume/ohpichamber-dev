# Settings UX overhaul, v2.8.0 subagent panel adoption, OMP 19.1 tool parity, and OpenCode purge

**Status:** done
**Priority:** high
**Integration branch:** ux-v280-omp19-alignment/integration

## What this is for

Remote OMP 19/19.1 alignment commits (#138–#155) and the OpenChamber v2.8.0 merge (`cb5c92b26`) landed without visual walkthroughs and created four product-level regressions:

1. **Settings IA and control chaos.** `Sessions` grew to ~15 sections while `modelRoles` split across 7 pages behind cross-links; `useOmpPageSettings` silently drops write failures to `console.warn` across 7+ pages; `NativeBehaviorFiles` shipped a single-dropdown manual-save form displaying raw camelCase frontmatter keys (`astCondition`, `alwaysApply`, `globs`), `'true'`/`'false'` string selects, and `JSON.stringify` text inputs; `ModelCompactionSettings` and `RetryFallbackChains` added manual `<form>` Save buttons and raw newline `<Textarea>`s; `Commands` and `Skills` injected global discovery sections above per-entity editors; `SnippetsPage` kept manual Save and success toasts; and `VoiceSettings`, `PluginsPage`, `WebSearchPage`, `GitHubSettings`, and `GitLabSettings` accumulated raw HTML `<input>`/`<button>` controls, duplicate `Apply` actions, and boxed row chrome.
2. **Broken subagent UX across merge and OMP 19.1 async execution.** Conflict resolution in `cb5c92b26` replaced upstream v2.8.0's 159-line `SubagentsPanel` and shared `SubagentStatusRow` (`ade48bfb8d`) with a 25-line stub while leaving `SubagentHudTray` (with an unreachable `AgentHubModal`) and 20+ orphaned `toolRow/*` and `timeline/*` files. Meanwhile OMP 19.1 changed `task` to detached async execution (`tasks[]` returns in ~10 ms with empty `details.results` and delivers completions via `CustomMessage` `customType: "async-result"`), causing `WorkerProjection` to drop background subagent reports, `TaskToolSessions` to race into `"Unavailable"`, and live rows to mismatch `childSessionId` and hide subagent names.
3. **Unaligned OMP 19.1 tool cards.** Default `hashline` `edit` calls (`[path#tag]`) show bare `"Edit"` with no file target while running; `input.i` tool intent is missing on collapsed tool rows yet leaked into raw JSON dumps; `bash` async jobs and named services hide their job/service status; `find` indented hit lines fail the path-link regex; completed HTML `<form>` `ask` calls dump raw JSON; and `tts` has no tool presentation.
4. **Residual OpenCode services and branding.** `OpenCode Go`, `OpenCode Console budgets`, `OpenCode Zen` (`zen-promo`, `zen-key`, `opencode-zen`, `opencode.ai` endpoints), GUI `commands.enableOpencode*` toggles, `opencode.ai` / `openchamber.dev` links, and `x-opencode-directory` client headers remain live.

## What it does

- **Settings IA and save feedback.**
  - `ModelRolesPage` directly edits every GUI-supported OMP model role (`default`, `smol`, `slow`, `plan`, `vision`, `commit`, `tiny`, `memory`, `task`, `advisor`, `widget`, `judge`, `image`) using shared searchable role pickers. Concept pages (`Git`, `Memory`, `Agents`, `Tools`, `WebSearch`) display read-only summaries with jump links to `ModelRolesPage`, while `Sessions` keeps only the top-level default model and thinking quick-pickers without claiming `omp.modelRoles`.
  - `Sessions` retains only session-workflow settings (defaults, permissions, plan/goal modes, compaction, retry/fallback, worktrees, retention); `sessions:sampling` and low-level execution/isolation knobs move to `OmpSettingsPage` tabs with matching search targets.
  - `useOmpPageSettings` reports saves and failures through `reportSettingsSaveState` so `SettingsPageLayout showSaveStatus` renders `Saving…` and `Save failed`, rolling back rejected optimistic state.
- **Compliant Settings editors and primitives.**
  - `BehaviorPage` presents a unified entity browser matching `AgentsPage` and `SkillsPage`: a left list grouped by Global and Project scopes (`AGENTS.md`, `RULES.md`, `SYSTEM.md`, `.omp/rules/*`, `.omp/instructions/*`) with a `+ Create` dialog, and a right structured editor driven by `SettingsAutosave` (silent blur/toggle saves, localized labels in all 15 locales, `SettingsCheckboxRow` booleans, localized enum selects, structured multi-value inputs, visible `AGENTS.md` injection guidance, and a clean Prompt & Personality `showSaveStatus` section).
  - `ModelCompactionSettings` and `RetryFallbackChains` create entries via `+ Add` dialogs with `ModelSelector` / wildcard pickers, structured threshold modes + `NumberInput`, `@dnd-kit` `SettingsSortableList` chain reordering, and immediate CAS saves without manual Save buttons or newline `<Textarea>`s.
  - Global `Discovery sources` controls leave the inline `Commands` and `Skills` entity editor panes; `SnippetsPage` uses `SettingsAutosave` silently with an inline `/` input prefix; `VoiceSettings` uses shared `Input`/`Button` primitives; `PluginsPage` exposes one clear `Apply` lifecycle action; boxed row chrome and duplicate status pills across `WebSearch`, `MCP`, `GitHub`, and `GitLab` are replaced with shared flat primitives; and `lib/settings/search.ts` covers every stable anchor.
- **OpenChamber v2.8.0 SubagentsPanel over OMP 19.1 async state.**
  - `WorkerProjection` projects OMP 19.1 `CustomMessage` (`customType: "async-result"`) deliveries as canonical subagent completion records rather than dropping them, and `WorkerSession` + `SessionRegistry` unify live and persisted `childSessionId`, subagent `name`, `role`, `solutionSpace`, and pre-lifecycle tool events.
  - Context Panel `SubagentsPanel` and `WorkStatusSubagentsSection` share `SubagentStatusRow` (ported from upstream `30c70496a5` / `ade48bfb8d`): line 1 shows subagent name, status icon, context %, tokens, duration/cost; line 2 shows live `currentTool` + argument/`i` intent, thinking/writing, retry countdown, 90 s silence warning, and role + model. Expanding a row in `SubagentsPanel` (auto-expanded when blocked on permissions or questions) renders pending `PermissionCard`/`FormCard` items, the Markdown report (from foreground result or `async-result`), collapsible task prompt, steer/cancel controls while running, and `Open session`.
  - Timeline `task` cards handle single and batch `tasks[]` calls, display live store-backed subagent rows and counts without racing into `"Unavailable"` or printing model-facing `proc://` advisories, and `SubagentHudTray` + `AgentHubModal` are retired.
- **OMP 19.1 tool cards and merge cleanup.**
  - Running and completed `edit` (`hashline`, `apply_patch`, `sloppy`) rows extract target file paths from patch headers and enable file quick-open; `input.i` renders on tool rows and is omitted from raw JSON argument dumps; `bash` rows badge `async` jobs and named `service` state; `find` hit lines link `path:line` with scores; HTML `<form>` `ask` results render clean field/answer pairs; `tts` is registered in tool presentations and permission groups; `PermissionCard` details disclose only the redacted public summary (`reason`, `command`, `path`) because raw tool `input` stays off the browser boundary (`approval-summary.ts`, `architecture.md:312`, `contracts.md:225`); and unreferenced `toolRow/*` and `timeline/*` files are deleted with `parts/DOCUMENTATION.md` updated.
- **OpenCode / Zen / Go purge and mechanical guardrails.**
  - `OpenCode Go`, `OpenCode Console budgets`, and `OpenCode Zen` (`zen-promo`, `zen-key`, `opencode-zen`, `opencode.ai` quota/classifier endpoints, provider listings, docs, and 15-locale strings) are removed, with stored `zen-promo`/`zen-key` preferences falling back cleanly to `off` or the first configured classifier.
  - `commands.enableOpencode*` moves to `config-only`, remaining `opencode.ai` and `openchamber.dev` UI/probe URLs are removed, client directory headers cut over from `x-opencode-directory` to `x-openchamber-directory`, `messages.test.ts` shrinks `auditedOpenCodeKeys`, and `settingsLayoutGuard.test.ts` mechanically blocks raw HTML form tags, manual Save buttons/success toasts on autosave pages, untranslated field identifiers, boxed row chrome, and missing search anchors.

## How it is built

- **Settings ownership and persistence.** `settings-ui.ts` and `ompSettingsLayout.ts` remain the single bijective registry for OMP settings (`settings-ui.test.ts`, `ompSettingsLayout.test.ts`, `settingsItemOwnership.test.ts`). `useOmpPageSettings` wraps mutations with `reportSettingsSaveState` and single-flight CAS retry/rollback. Entity file editors (`BehaviorPage`, `SnippetsPage`, `CommandsPage`, `SkillsPage`) use `useAutosave` from `shared/SettingsAutosave.tsx`; draft creation stays memory-only until Dialog/Create confirmation.
- **Canonical subagent pipeline.** In `packages/agent-service`, `WorkerSession` pre-allocates or reconciles canonical child session IDs with native subagent IDs across `TASK_SUBAGENT_LIFECYCLE_CHANNEL`, `TASK_SUBAGENT_PROGRESS_CHANNEL`, `TASK_SUBAGENT_EVENT_CHANNEL`, and `SessionRegistry.persistSubagent`, keeping `name` (display identifier) separate from `role` (agent profile). `WorkerProjection` parses `customType: "async-result"` entries (`AsyncResultDetails` + `<task-result>` blocks) into structured canonical notice/report parts so both timeline turns and `useSubagentReports` read authoritative subagent reports without leaking raw harness tags.
- **UI subagent and tool presentation.** `packages/ui/src/components/chat/subagents/` and `work-status/` implement `useSubagentRows`, `useSubagentReports`, `subagentTask`, `SubagentStatusRow`, and `SubagentsPanel` over Canonical stores (`useSubagentsStore`, `useGlobalSessionsStore`, directory `permission`/`form`/`message` slices), matching upstream `ade48bfb8d` layout and interaction contracts on Web, Electron, and mobile (where `WorkStatusSubagentsSection` renders the same two-line row). `lib/toolPresentation/` and `ToolPart.tsx` parse hashline `[path#tag]` headers, strip `i` from JSON dumps, and render structured `task`, `bash`, `find`, `ask`, and `tts` states.
- **OpenCode retirement and headers.** `packages/web/server/lib/routing/` normalizes legacy `zen-promo`/`zen-key` values on read without throwing. Host routes accept `x-openchamber-directory` as primary (retaining server-side fallback read only where internal tests/boundaries require during transition, while zero client callers emit `x-opencode-directory`). `catalog-models.ts` excludes `opencode-zen` and `opencode-go` from public provider catalogs.

## What it must not do

- Expose raw OMP SDK objects outside `packages/agent-service` or execute unsanitized model HTML.
- Touch `~/.config/ohpichamber`, `~/.config/OhPiChamber`, or `~/.omp/agent` during tests or real-path verification.
- Add npm dependencies, edit `changelog/` or `CHANGELOG.md`, or run GitHub commands.
- Break strict Zod schemas consumed by mobile/Capacitor without coordinated `@openchamber/agent-contract` builds.

## What was considered and rejected

- **Delete `ModelRolesPage` and scatter all 16 roles across concept pages.** Keeps controls near feature toggles, but forces users to visit 6+ pages to audit or switch a multi-role setup and has no home for `vision`, `tiny`, `widget`, or `judge`.
- **Restrict `BehaviorPage` to Markdown-only `AGENTS.md` / `RULES.md` / `SYSTEM.md` and drop `.omp/rules/*` GUI editing.** Simpler UI, but forfeits first-class GUI authoring for OMP 19.1 scoped/judged rules that the backend confined catalog already supports safely.
- **Keep `SubagentHudTray` and `AgentHubModal` alongside `SubagentsPanel`.** Duplicates live state in three places and covers the active chat with a modal dialog; upstream v2.8.0 specifically replaced modal inspection with the side-by-side Context Panel surface.
- **Retain `OpenCode Zen` and `OpenCode Go` as third-party providers.** Leaves retired OpenCode SaaS promotions, broken console scrapers, and OpenCode branding inside an OMP-only product.
