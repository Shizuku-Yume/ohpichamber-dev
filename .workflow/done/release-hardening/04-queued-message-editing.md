- **Bugfix root causes (real-path findings):** (1) **F1** — send-now 400 "Root prompt agentId must be null": `session-ui-store.sendMessage` treated an omitted agent as "re-resolve the currently selected agent", so a capture made for the root session arrived as `undefined` and inherited the session agent, which root admission refuses; the capture and the send-now call now pass `null` verbatim — `null` means exactly "no agent", and only `undefined` falls through the re-resolution chain. Wire proof: round 2–3 steers carry `"agentId":null` and return 200. (2) **F2** — fresh client blind to pre-existing queued rows: projections key under `runtime/directory/session` and a first snapshot can apply before session discovery keys the session; the rows were dropped as unattributable instead of parked. Rows for an unresolved session now park under the empty-directory key, and a re-key pass subscribed to both the global sessions store and the workspace-directory registry (they update independently) plus the composer-side `sessionDirectoryMap` binding moves them into place with their revision guard. (3) **F5** — edit→resend of attachment items aborted with "Couldn't save … for the agent to open", two links in one chain: restored attachments carried the re-read bytes in a `File` but no `dataUrl` that `attachedFilesForModel` requires (the restore now rebuilds the data URL, making the restored attachment indistinguishable from a freshly picked one for the submit pipeline), and `sanitizeAttachmentsForSend` rewrote every server-sourced `serverPath` through `toServerFileUrl` including `attachment://` Host-store references (it now passes those through so admission reuses the Host's upload instead of re-uploading). (4) **Canonical parser prefix** — one line in `packages/web/server/lib/host/canonical-routes.js` outside the task's named files: Express 5 matches middleware paths by segment boundary and the regex `/^\/sessions\/[^/]+\/queue(?:\/|$)` never matched `/queue/order`, `/queue/:item` or `/queue/:item/take`, so the 1 MB JSON parser never fired and every canonical queue mutation with a body ran with `req.body === undefined` (400). The parameterized prefix `/sessions/:sessionId/queue` matches the collection and every sub-path; recorded in HOST-DEVIATIONS.md §1.
- **Implementation facts:** Host `sqlite-store.js` persists the optional `draft` verbatim beside the captured request in the same serialized write transaction; `take` runs revision CAS, refuses leased rows, deletes and bumps atomically — a failed take leaves the item queued. Old rows (incl. every converted legacy item) have no `draft`; projection marks `originalAvailable:false`, take returns `draft:null` with surviving `content`/`text` for a partial restore — no payload migration. Both route families share one `takeResult` mapping; body/route item-id mismatch is 400. Contract gains `QueueOriginalDraftSchema`/`QueueTakeRequestSchema`/`QueueTakeResultSchema`/`originalAvailable`. UI store `takeQueuedItem`: 409 → refresh + `refused`, 404 → refresh + `missing`, success applies the server queue and reconstructs the composer message; `popToInput` is the same take; the deleted client-side `takeForSend` batch helper has its upstream-gaps allowlist row citing this task. The restored text lands in durable draft storage before the first async attachment read, so a refresh in between cannot lose the message; restored attachments file under the draft identity being edited rather than whichever input slot is active when reads resolve.
