## Progress

- **Bugfix root causes** (full trace in `task01/CAUSE.md`):
  - **Exact slash command needed two Enters** — reproduction: type `/compact` in full with the autocomplete popup open and press Enter once; nothing dispatches, the input becomes `/compact ` and only the second Enter submits. Cause: `matchCommandPalette` (`composer/language/triggers.ts:29-38`) keeps the command trigger open for any no-space `/` input without checking whether the query already *is* the highlighted command, and `createComposerKeyHandler` (`createComposerKeyHandler.ts:106-117`) forwards every Enter to `CommandAutocomplete` before submit handling, so the first Enter only rewrites the exact text with a trailing space (`useComposerCompletions.handleCommandSelect` line 215). Fix: `CommandAutocomplete`'s imperative handle answers `isExactMatchHighlighted()` and the key handler yields to `shouldSubmitEnter` when Enter hits an exact highlighted match; partial matches and Tab still complete.
  - **Rejected control command lost its text** — reproduction: `/compact` in a session too small to compact (422 `SESSION_TOO_SMALL`); the composer cleared up front and the toast/error appeared over an empty input. Cause: `useComposerSubmission.ts` cleared the composer (`setMessage('')`, mentions, persisted draft) *before* dispatching the control and reconstituted text only in the throw path through `restoreDraft`'s concatenating merge, so in-flight typing raced the restore and value-rejections never restored. Fix: dispatch first with the composer intact and clear only on acceptance; refusals (`SESSION_TOO_SMALL`, throws, `/fork` send-failed) keep the typed text with their error/info toast, and `useComposerDraft.persistNow` no longer clobbers other identities' mention state when persisting a non-current draft (null identity is handled).
  - **Stale model label during a new session's first streaming run** — reproduction: open a new chat, switch model, send; while the run streams the composer label shows the previous/default model and reverts at completion. Cause: promotion (`createSessionWithDraftLifecycle` → `setCurrentSession` → `activateDirectory`/`loadProviders` without `preserveManualModel`) resets `useConfigStore` selection before `saveSessionModelSelection` lands, and the label (`ModelControls.tsx`, `MobileModelButton.tsx`) read only `useConfigStore`, repaired asynchronously by effects that waited for a completed assistant message (`extractSessionRecordModelChoice` always null, `findLatestUserModelChoice` skipping streaming parts). Fix: `useActiveRunModelSelection` derives the label from the authoritative session/run selection (strictly runId-matched active turn) while a run is active; `userModelChoice` reads `SessionSnapshot.selection.model`; activation/providers preserve the manual selection through promotion.
  - **Post-run fallback to `agents[0]`'s pinned model after Turn 1** — reproduction: submit Turn 1 within ~500 ms of opening a new chat; after Turn 1 completes the composer switches to `scout`'s `claude-haiku-5-5` so Turn 2 runs the wrong model. Cause: Effect 2 ran on optimistic `draft_<id>` ids and fell through to `applyFallbackAgent`, `stickySessionAgentRef` leaked across the `draft_<id>` → real session promotion, Effect 1's `setAgent` without `keepModel` synchronously overwrote the model, and `applyFallbackAgent` ignored `snapshot[sessionId].selection.model`. Fix: skip draft ids, clear the sticky ref on session transitions, strictly runId-match the active turn, and guard the fallback with session-selection knowledge.
