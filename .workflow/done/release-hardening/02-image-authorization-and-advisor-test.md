**Root causes and fixes.** (1) `catalog.image.generate` asked only for the coarse `provider-entry` grant and never passed the `provider.use` policy, so image traffic was checked by a weaker rule than every agent-driven provider request. Fixed end to end: `native-policy-protocol.ts` adds `'image'` to the descriptor purpose enum, `catalog-models.ts` `generate` awaits an injected `authorizeImageUse` before any credential resolution, `stateless.ts`/`session.ts`/`catalogs.ts` plumb it to `authorizeTool('provider.use', …)` with the image tuple (the session.ts/catalogs.ts touches are small cross-file plumbing outside the original file list, needed because both the stateless worker and live sessions build image generation through the shared catalogs context). The Host authorizer generalizes the embedding rule: any non-chat purpose (`'embedding'`, `'image'`) is admitted on provider id + normalized endpoint with any model — the workspace policy provider list only ever contains enabled rows, so presence is exactly "enabled provider at that endpoint" — and refusal details name the purpose with the same endpoint redaction; chat exact-match is unchanged. (2) The advisor overflow-compaction candidate loop in the patched SDK skipped Host-refused candidates but had no behavioral test; the WATCHDOG.yml fixture test drives a real overflow with both chain candidates denied and asserts zero provider requests plus the visible refusal, with a byte-identical revert-proof of the installed SDK copy (receipts in the evidence directory). (3) `security.mdx` still told enterprise-mode readers that update checks keep running although the fork removed that check in the rebrand; the bullet is removed from the English page and all 11 localized copies (every localized `security.mdx` that exists).

**Reviewer finding and fix.** The read-only reviewer found a medium defect in the first implementation: image uses were matched against the chat provider rows (`policy.providers`), so an image model whose provider had no enabled chat model was refused even when the image model itself was enabled, and image enablement — which lives in the separate `catalog.imageModels` catalog — never entered the policy at all. The fix adds a dedicated `imageProviders` row set end to end: `HostNativePolicySnapshotSchema` (`native-policy-protocol.ts`) and `HostWorkspacePolicySchema` (`supervisor/host-authorization-protocol.ts`) carry it, `native-policy-snapshot.ts` captures it from `catalog.imageModels` with the same provider-endpoint resolution as chat rows, and the Host authorizer matches `purpose: 'image'` against those rows while embedding and chat rules are unchanged. Cross-file changes beyond the original file list: `catalogs.ts` and `session.ts` (authorizeImageUse plumbing for live sessions), `supervisor/host-authorization-protocol.ts` (policy schema), `native-policy-snapshot.ts` (row capture, with its test), `workers.policy.test.ts` and `tool-tier-coverage.test.ts` (schema shape updates), `.workflow/upstream-deltas.tsv` (the ledger repair below). Web authorizer tests now cover: image rows admit with any model, a chat-only provider refuses image use, an image-only provider with no chat row is admitted. The agent-service dist is regenerated, not committed (gitignored).
