## Background & UI Restoration Scope

The current user explicitly prioritizes restoring the original OpenChamber UI appearance and interaction behavior, with no redesign. Investigation identified commit `bfa8edacb9b0096aabf40b12886794ce62df8ddb` as the assembled pre-M1 baseline visually inherited upstream. The current integration worktree (`e848504602333955b1d134bba3345d8bbc2ed065`) retains the authoritative native Canonical contracts.

This task restores attachment presentation, media galleries, and safe credential handling:
- **Attachment Chips & Cards:** Restores the compact visual chip and card presentation for uploaded and referenced files (`FileAttachment`), displaying file type icons, human-readable file sizes, and quick actions to open or download the file.
- **Image Lightbox & Gallery:** Restores inline thumbnail grids and the expanded modal gallery (`MarkdownImageGallery`) for high-resolution viewing of images generated by tools or uploaded by users.
- **Authenticated Media Transport:** Resolves media content through canonical endpoints using standard authenticated client requests (`CanonicalClient`). URLs must never leak bearer authentication tokens in URL query strings or browser history.
- **Lifecycle & Memory Management:** Revokes object URLs (`URL.revokeObjectURL`) when attachments unmount or when navigating away from a session, preventing memory leaks and avoiding stale media references when switching runtimes.

## Progress

Resumed at integration HEAD `4d99b9827` in worktree `59-original-attachment-ui` (original Base commit kept above as history). Two real Task59 defects were found and fixed:

1. **Markdown gallery never loaded.** The server `POST /api/openchamber/sessions/:id/markdown-image-grants` returns `{ sourceIndex, status, assetPath, expiresAt }`, but `markdownImageAssets.ts` parsed legacy `source`/`path` fields and built an `/api/fs/raw` URL. Every prepared image became `error`, so `MarkdownImageGallery` rendered caption-only thumbnails in real Web. Host and space grant raw paths were added to the URL-token allowlist as narrow GET-only regexes (`/api/openchamber/sessions/<id>/markdown-image-grants/<grant>/raw` and the `/api/spaces/<12-hex>/...` form); POST and lookalike paths remain rejected.
2. **Compact sent-turn chip hid the size.** The compact `NativeAttachmentChip` now renders the human-readable size beside the truncated name; a regression asserts icon, truncated name and `3 B`.

The unused local `ImageGallery` component was removed.
