## Progress

**Planned at integration HEAD `3765257ca` (2026-10-21).** No source was changed in this planning turn. Base commit is left for `flow-implement`.

**Root cause.** `readGuestWorkspace` builds projects from `useProjectsStore`, whose ids are settings ids (`path_*`), while canonical `Session` records carry Host project ids (`pro_*`). The session filter at `packages/ui/src/lib/guests/workspace.ts:86` compares those unrelated identities. The same code, and Guest Shell project scope in `shells.ts`, also use `session.displayPath` as a Host directory, but the canonical field is project-relative (`'.'` at a project root). The Guest therefore filters every configured project to an empty session list. The panel's `ready` state and the project row are correct; only the session membership and directory projection are wrong.

**Mapping decision: UI projection.** Keep Guest project ids as the settings registry ids, because `startSession`, worktree selection, Guest file access and shell project scope already resolve those ids through `useProjectsStore`. The canonical `Workspace`/`Project` DTO intentionally omits the Host project identity and path, and `agent-scope-store.js` keeps `hostProjectId` private. The smallest authoritative mapping is the directory binding that shared UI already owns: `POST /api/agent/v1/workspaces/resolve` binds each admitted workspace id to the caller's directory via `registerWorkspaceDirectory`, and `resolveGlobalSessionDirectory` is the established session-to-directory projection used by the sidebar, tabs, mobile and mini-chat. Host admission permits one canonical project per directory, so membership is exact without parsing ids or duplicating project state.

**Chosen shape.** Extract one `guestProjectDirectories(projectId)` helper returning the normalized settings project root plus normalized `guestProjectWorktrees` paths. In `workspace.ts`, scan the existing `getAllSyncSessionMap()` and include a session only when `resolveGlobalSessionDirectory(session)` is in that set. Pass the resolved directory into `projectSession`, so child status, worktree lookup and the reported `directory` all use it, and echo `query.projectId` as the record's `projectId`. In `shells.ts`, use the same directory set against each tracked shell's own `directory`; do not rescan sessions or read `displayPath`. Leave coverage, subscription ownership and runtime-switch disposal unchanged. The canonical workspace binding is registered before a directory's child store loads and is populated before the global snapshot applies, so a child-store session always has a resolved directory; no second identity map, cache or subscription is required, and child-store session updates already drive the workspace observer.

**Rejected alternatives.** Adding `hostProjectId` to Canonical `Project`/`Workspace` would make the Host expose an identity that its public DTO deliberately withholds and would require contract, sync and consumer migration plus a second project identity in UI state. Changing Guest projects to canonical `pro_*` ids would break `startSession`, worktree and shell scope resolution, change the public Guest contract, and still leave Guests without directories. Inferring the canonical id from the `path_*` value or the project name is an arbitrary prefix/name assumption and is refused.
