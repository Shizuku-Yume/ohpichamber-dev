# 70: Cancel a live run promptly and keep it cancelled

**Effort:** omp-through-m3
**Task type:** bugfix
**Base commit:** <commit-sha>

**Delivers:** A live turn is never projected as `completed` merely because it has no terminal entry yet: `WorkerProjection.readHistory` reports the live status for the active turn, and only recorded terminals settle a turn. An abort latches cancellation for its `runId` before the worker awaits the native abort, so a `turn_end`/`agent_end` pair without the aborted assistant `message_end`, or a prompt that resolves not dispatched, settles the run and its turn `cancelled` exactly once. The control route returns that settled run with the same `runId`, no later `completed` overwrites it, and Stop clears only against the cancelled run. Unknown or already-settled `runId` still returns `RUN_NOT_FOUND`, non-abort control stays `400`, and Host scope/auth checks are unchanged. Task 69 measured a warm direct abort at 559 ms, so this task adds no route retry or timeout and makes no Host-latency claim. Task 65 keeps its existing live run-control Check and re-runs its live abort proof after this task.
